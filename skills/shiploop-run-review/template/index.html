The contract we must not break

One sentence in, then investigation, planning and an iteration loop. The skill never decides the flow. The script does, and the skill obeys what it returns.

Skill

Calls the script. Does exactly the step the packet names. Calls back with its result.

Script

Reads and writes state. Decides the next stage, writes every contract, refuses anything inconsistent.

State

The only source of truth. It tells the script what the very next prompt is.

request → investigate → plan → [ skill calls script → script updates state → state names next prompt → skill obeys ] → repeat → release

Backchain: what it planned, added and cost

Each loop split into time that clearly added value, time that clearly did not, the confirming passes a loop needs to close, and what we cannot yet judge. Times come from file and accept timestamps, so they are approximate. Change a verdict when you disagree.

Iterations and expectations

How one iteration runs, and where we are in the plan. Each iteration states what we expect before it runs. Record what we saw; if we were wrong, revise the expectation with its reason, and the old wording stays in the history.

    When something unexpected happens

    A catch-all for what no check anticipated. The same reaction every time, and an optional note in the prompt.

    1. Keep the evidence first: put the run facts in the repo journal before touching anything.
    2. Decide one thing now: is it fatal? Stop a run only if it is, or if the change cannot affect planning.
    3. Name the expectation it touches. If none, it is noise or a new expectation to write down.
    4. If the system behaved sensibly and our expectation was wrong, revise the expectation and record why, instead of changing the engine.
    5. List what you do not know and how you would find out, before proposing a fix.
    6. React with the smallest reversible change, tested on its own footprint.
    7. Verify in a run, then record expected versus achieved here.
