# Vercel and Next.js development

Return to the [guidance selector](../coding-guidance.md#select-guidance) when the runtime or boundary changes. Next.js ships no built-in auth; identity comes from a library (Auth.js/NextAuth v5, Clerk, Better Auth) or a hosted IdP ([Next.js Auth guide](https://nextjs.org/docs/app/guides/authentication)). Auth.js's JWT strategy verifies a signed/encrypted cookie server-side with no DB call, while its database strategy looks up a session ID on every request ([session strategies](https://authjs.dev/concepts/session-strategies)); Clerk verifies via `auth()` in Server Components/Actions/Route Handlers ([`auth()` reference](https://clerk.com/docs/reference/nextjs/app-router/auth)). Next.js's own guidance treats Middleware as optimistic-only redirection and requires real authorization in a Data Access Layer next to the data fetch, because CVE-2025-29927 let a spoofed `x-middleware-subrequest` header skip Middleware entirely ([Data Security guide](https://nextjs.org/docs/app/guides/data-security), [GHSA-f82v-jwr5-mffw](https://github.com/advisories/GHSA-f82v-jwr5-mffw)). Server Actions are POST-only with Origin/Host checks and encrypted action IDs, but still need an authorization check written inside every action body ([Security in Server Components/Actions](https://nextjs.org/blog/security-nextjs-server-components-actions)).

For state, Vercel-native options are Blob (`@vercel/blob`, immutable content-addressed files) and Edge Config (`@vercel/edge-config`, a read-optimized key/value store, not a transactional database); anything else — Postgres, Redis, Mongo — comes through Marketplace integrations such as Neon and Upstash, since Vercel Postgres/KV were retired in December 2024 ([Storage overview](https://vercel.com/docs/storage), [Marketplace Storage](https://vercel.com/docs/marketplace-storage)). Consistency and transaction guarantees are set entirely by the chosen provider. Functions auto-scale to tens of thousands of concurrent instances with no shared locking primitive, so row versioning or `SELECT … FOR UPDATE`-style locking must live in the database itself ([Functions limits](https://vercel.com/docs/functions/limitations)); Vercel Queues delivers at-least-once, so concurrent duplicate processing is expected and dedup is the consumer's job ([Queues concepts](https://vercel.com/docs/queues/concepts)).

For connectivity, plain request/response uses Route Handlers or Server Actions on Node or Edge ([Runtimes](https://vercel.com/docs/functions/runtimes)). Streaming/SSE is supported, with Edge required to start within 25s and stream to 300s while Node/Bun/Python stream up to `maxDuration` ([Functions limits](https://vercel.com/docs/functions/limitations)) — the lightest channel that meets a freshness need should be picked from these before reaching for something heavier. WebSockets are natively supported (Public Beta, June 2026) on Fluid compute, but a connection pins to one instance for its life and closes at `maxDuration`, so cross-instance state needs an external store; Next.js has no native upgrade API, so use `experimental_upgradeWebSocket()` from `@vercel/functions` ([WebSockets docs](https://vercel.com/docs/functions/websockets)). After any push, reading authoritative state back means going to the Marketplace store or the Data Cache, not assuming the CDN or edge layer already reflects it.

Caching has layers. Next.js 16's `"use cache"` with `cacheLife()`/`cacheTag()` sets explicit stale/revalidate/expire windows ([`use cache` directive](https://nextjs.org/docs/app/api-reference/directives/use-cache)). The Data Cache is regional and persists across deployments until busted via `revalidateTag`/`revalidatePath`/`updateTag` ([Data Cache](https://vercel.com/docs/caching/runtime-cache/data-cache)). The CDN cache respects `s-maxage`/`stale-while-revalidate` as a best-effort ceiling of one year, does not support `proxy-revalidate`/`stale-if-error`, and never caches responses carrying `Set-Cookie`, `Authorization`, or a high-cardinality `Vary` like `Cookie` ([CDN Cache](https://vercel.com/docs/caching/cdn-cache)).

Secrets marked "sensitive" are encrypted at rest and never shown again after creation; "regular" env vars are stored and displayed as plaintext to anyone with project access, and Marketplace credentials are injected under this same model ([sensitive env vars](https://vercel.com/docs/environment-variables/sensitive-environment-variables), [Marketplace Storage](https://vercel.com/docs/marketplace-storage)).

For scheduled work, Cron Jobs allow up to 100 per project on every plan, but Hobby is capped to once a day with hour-only UTC accuracy and failed invocations are not auto-retried ([Cron Jobs](https://vercel.com/docs/cron-jobs)). `after()`/`waitUntil()` run trailing work bounded by the invocation's own `maxDuration` ([`after()`](https://nextjs.org/docs/app/api-reference/functions/after)). Vercel Queues auto-retries failed handlers and requires producer idempotency keys with consumer-side dedupe ([Queues concepts](https://vercel.com/docs/queues/concepts)). Vercel Workflows provide durable execution with no fixed duration cap, event-log replay on restart, and encrypted step I/O for work exceeding `maxDuration` ([Workflows](https://vercel.com/docs/workflows)).

Locally, `next dev` doesn't reproduce multi-region routing, real CDN caching, Fluid compute's cross-invocation concurrency, Firewall/WAF, or actual cron firing. `vercel dev` replicates more but is not a full production emulator, and Vercel recommends skipping it when the framework's own dev command suffices ([`vercel dev`](https://vercel.com/docs/cli/dev)). Preview Deployments are real, fully built, network-reachable per-branch deployments with their own env vars, making them the closest genuine pre-prod verification surface ([Environments](https://vercel.com/docs/deployments/environments)).

Limits to check before committing to a design: [Functions limits](https://vercel.com/docs/functions/limitations), [Platform limits](https://vercel.com/docs/limits), [Cron usage/pricing](https://vercel.com/docs/cron-jobs/usage-and-pricing), [Workflows pricing/limits](https://vercel.com/docs/workflows/pricing), [CDN cache limits](https://vercel.com/docs/caching/cdn-cache#limits).

A single-user, client-only product needs none of the server-side storage, locking, caching, or scheduling machinery above.

## Claims to check

- "Vercel Functions can't do WebSockets" — outdated; native support shipped in Public Beta June 2026 on Fluid compute. [WebSockets](https://vercel.com/docs/functions/websockets)
- "Vercel Postgres/KV are Vercel-managed databases" — both discontinued; migrated to Neon/Upstash, new provisioning is third-party Marketplace. [Marketplace Storage](https://vercel.com/docs/marketplace-storage)
- "A Middleware auth check is sufficient" — Next.js calls this optimistic-only, and CVE-2025-29927 proved Middleware is bypassable via a spoofed header. [Data Security guide](https://nextjs.org/docs/app/guides/data-security)
- "ISR route-segment config is still the primary caching API" — Next.js 16 moved to `"use cache"`/`cacheLife`/`cacheTag` under Cache Components. [Migrating to Cache Components](https://nextjs.org/docs/app/guides/migrating-to-cache-components)
- "Edge Config is a general transactional database" — it's a read-optimized config store, not transactional. [Storage overview](https://vercel.com/docs/storage)
