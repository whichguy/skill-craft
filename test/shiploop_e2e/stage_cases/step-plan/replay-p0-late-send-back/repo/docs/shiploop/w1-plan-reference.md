# W1 planning reference

The accepted requirement is R-1 in `docs/shiploop/spec.md`, sourced from the run's `request.md`. Each nonblank line is a record; field keys match a lowercase letter followed by lowercase letters, digits or underscores, values are trimmed, and malformed fields or duplicate keys report their 1-based source line via SyntaxError. Non-string parser input and non-array selector input throw TypeError. Selection preserves input order and matches the requested field and value. The exact Ada/Bob example and its first-record selection are acceptance oracles.

AD-1 in `docs/shiploop/architecture.md` chooses a local CommonJS module, Node built-ins, and the existing `node:test` suite. `src/text.js`, `test/text.test.js`, and `package.json` are the house-style and harness references. There is no persistence, migration, external service, or shared test state. The test stage owns `test/records.test.js` and its four named cases; it must use independent assertions and avoid treating a matching test title as evidence of behavior. The focused runner must execute all four IDs, with at least four tests; `npm test` supplies regression coverage. The step proofs are independent of that later test file. Split a field at its first `=` so remaining equals are value text; validate keys as written. This is a planning assumption, not an additional user requirement.

S1 supplies parser and parser contract; S2 depends on S1's module and supplies selection and selector contract. Both steps operate on `src/records.js`. The test stage owns the later test path and suite; a missing test file at planning time is expected, not a passing test. The record is stateless and cleanup is unnecessary. Revalidate the harness and its focused case counts after the test file is authored.
