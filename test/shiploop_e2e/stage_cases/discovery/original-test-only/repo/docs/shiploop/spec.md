# Living spec

Seeded by the E2E harness: the stages before step-plan are recorded without doing them, so the request is the specification.

## Requirements

R-1: This directory contains an already implemented help-desk ticket-assignment service, with no npm dependencies. Add node:test tests under test/ for the assignment behavior and its interactions with the existing documented service. Do not change production files, package.json, or any existing test/helper file; add new test files and helpers. npm test must run the existing and added tests. README.md, CONTRIBUTING.md, docs/api.md and docs/decisions/ describe the existing obligations to preserve. The assignment contract is: PUT /tickets/:id/assignee with JSON {"assignee":"<agent>"} assigns an agent whose name has 1 to 64 characters; {"assignee":null} unassigns. Only open and in-progress tickets permit assignment or unassignment. Assigning the same agent changes nothing. Every ticket shows assignee, null when unassigned. Each new agent is notified through the existing outbox/worker, and every actual change uses the existing audit and actor conventions. GET /tickets supports assignee=<agent> and assignee= for unassigned tickets, together with all other filters; every supplied filter must match, with the documented pagination behavior preserved. The command-line listing shows assignee while existing raw-column consumers keep working. New fields and audit/outbox state survive data-file restarts, and legacy files without assignee load as unassigned. Existing lifecycle, notifications and errors keep their documented behavior. Keep the implementation as it is; the deliverable is tests that check this contract, including meaningful failure, boundary and interaction cases. Do not add dependencies. Check observable behavior rather than production source text or file hashes. Bound asynchronous test waits so an unmet behavior produces a useful failure.
