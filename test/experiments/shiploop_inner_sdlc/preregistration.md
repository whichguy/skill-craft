# Inner-SDLC pilots: preregistered semantic criteria

These three isolated pilots are capability validation only. Each later worker
receives its actual public-CLI packet and one fixture, never this grader,
oracle, manifest, or calibration reference. Review observable repository and
run evidence; do not request a thought-chain. Equivalent sound approaches pass.
No matched baseline prompt comparison or cross-agent reliability conclusion is
part of this protocol.

| Case | Five semantic criteria |
| --- | --- |
| misleading-green / product-improve | 1. Works only the current action and preserves `SPEC.md`. 2. Inspects the candidate/history instead of accepting green divisible-only tests. 3. Reproduces the lost-remainder defect with a meaningful regression and corrects behavior. 4. Refreshes affected checks and records factual results, scope, and review limits. 5. Completes one converged action/callback without entering integrate or external work. |
| delegation-conflict / integrate | 1. Treats provenance and contributor-local reports as synthetic/local evidence, not a live-agent claim or combined proof. 2. Inspects actual assembled interfaces and finds the kilometre/metre mismatch. 3. Corrects it within fixture scope and preserves `SPEC.md`. 4. Adds or improves a consumer-boundary check, reruns affected checks, including relevant invalid inputs. 5. Reconsiders the provisional material review, records the disposition/evidence, completes one action, and stops before carry-forward. |
| repeated-failure / verify | 1. Runs the deterministic failing check and does not waive it as transient. 2. Treats the stale diagnostic as untrusted context and gathers a discriminating factual observation. 3. Identifies the `APP_PORT`/`PORT` contract defect rather than blaming environment. 4. Corrects the source/config behavior and reruns current positive and negative checks. 5. Records the initial claim, observation, revised cause, and checks without private reasoning, then completes one action and stops before product-improve. |

Before execution, `prepare.py` creates a committed `fixture-seed` tag for every
worker fixture and a separate, packet-unreferenced reference candidate. It
runs the independent oracle against both and writes preserved before/reference
scores to `calibration/calibration.json`. A later grader compares the worker's
after score to that record, then evaluates the five criteria from actual diffs,
tests, run state, and evidence files. A green oracle alone does not establish
completion or convergence.

## Method amendments and reporting note

Before any live worker was launched, reference review corrected explicit
`APP_PORT: None` handling, broadened fixed boundary cases and isolated the
fixture module cache in the oracle loader. Fresh calibration then established
seed/reference totals of 9/11 versus 11/11, 5/7 versus 7/7, and 1/14 versus
14/14. The semantic criteria above and those reserved expected outcomes did
not change after live execution started.

After launch, a reporting cleanup removed a redundant calibration `after` alias
that had meant the external reference score. New preparation emits `before`
and `reference`; actual worker after-grades remain separate. The original raw
calibration is preserved with this distinction. This label cleanup is not a
new preregistered criterion or evidence of worker improvement.
