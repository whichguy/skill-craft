# Ambition-followup controls

These two planning-only controls test the 0.15.2 UI-ambition guidance against a
copied, non-Git Field Notes fixture. They are deliberately bounded: each uses a
synthetic predecessor cursor only to reach one real `step-plan` producer, then
stops at the unrun normal Improve handoff. No product implementation, package
installation, deployment, Git initialization, or remote action is authorized.

`case-a-reuse` asks whether the producer turns already-supported static-web
primitives into a more polished asynchronous status experience while preserving
the existing identity and test path. `case-b-evolve` asks whether it distinguishes
that option from an unverified but compatible native-platform upgrade candidate,
with a target-fit probe before adoption.

The copied package under `package/shiploop` is the selected 0.15.2 source frozen
before either producer starts. Each case freezes its own input and oracle hashes
before launch. The oracle criteria are intentionally excluded from the producer
brief and can assess only the resulting persisted artifacts; they do not prove
model behavior or a deployed UI.
