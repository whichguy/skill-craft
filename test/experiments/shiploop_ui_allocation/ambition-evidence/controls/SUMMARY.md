# UI ambition follow-up outcomes

## Apparatus and provenance

Both controls used the copied selected ShipLoop 0.15.2 package in `package/shiploop`. The original and final 134-file content manifests have the same SHA-256: `c765de846defc1d9b14261062d3471f8cc275179f7c232223fda57ded8486d55`.

Each case froze its request, controlled contract/tooling facts, copied product, selected package, frozen Improve identity, optional frontend-design card, and hidden rubric before its producer began. The final verification still matched.

To reach one bounded producer, each case seeded `intake` through `select-work` as explicitly synthetic fixture predecessors. Those records do not claim that earlier planning stages or an Improve campaign ran. The package CLI rendered the real `step-plan` packet, each fresh producer wrote one plan and submitted the exact current callback once, and the parent then remained at the normal, unbound Improve child. No control bound that child, modified product code, made a package available, installed anything, created a browser/design harness, deployed, initialized Git, or made a remote call.

The initial attempt to seed each synthetic cursor failed because its empty `run` directory had not been created. The complete raw errors are retained as `case-*/evidence/seed-state-first-attempt.raw.txt`; creating the empty directory and rerunning changed only experiment run state, then produced the captured synthetic seed record. It did not change frozen producer input.

`evidence.py` is a structural reader. It reports persisted state, imported Improve records, and synthetic-predecessor labels, but intentionally does not prove producer semantics. Here it correctly reports no imported Improve child; the real producer evidence is the current action callback result and post-producer packet.

## What the controls support

The tested guide wording elicited two concrete, appropriately ambitious UI plans that both reused the existing component/design/test path instead of silently adding a stack. One selected polish through existing primitives; the other described a meaningful higher-interaction native option while keeping it conditional on target evidence. Both carried components, interaction/state, skin, async recovery, accessibility/reduced-motion, estimate/benefit, and reuse/evolve/upgrade decisions into actual ShipLoop step-plan results.

The controls are small and not statistically reliable. They used the same copied fixture, two requested prompts, synthetic predecessor records, and a controller assessment rather than a blind independent judge. They do not establish that a future model will always choose well, that a native API works on any target, or that planned UI behaves correctly. Normal ShipLoop Improve and later implementation/test/browser stages remain the mechanisms for resolving the preserved policy boundary and proving behavior.
