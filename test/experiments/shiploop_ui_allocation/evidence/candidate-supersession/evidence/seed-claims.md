# Synthetic predecessor claims and fixture scope

This control uses a synthetic cursor through the eight ShipLoop stages from
intake through `select-work` solely so a fresh producer can receive one actual
candidate-3 `step-plan` packet. Each accepted predecessor is explicitly labeled
synthetic and is not evidence that a producer, model, semantic review, or
Improve runtime completed that stage.

W1 has a real available basis: `product/docs/requirements.md` and
`product/docs/design.md` define retained requirements, the static-environment
boundary, and the local-bootstrap premise. The synthetic completed-W1 label is
only the cursor position, so a missing W1 is not the readiness question under
test.

`run/notes/global-plan.md` is the retained **historical original** with the
obsolete order W1 -> W2 integration contract -> W3 bootstrap.
`run/notes/global-plan-reviewed-replacement.md` is a reviewed accepted
replacement and takes operational precedence: W1 -> W2 local bootstrap -> W3
integration contract. The product is deliberately non-Git and source-read-only
for this experiment. The normal durable correction of the stale planning record
is therefore a pending, explicitly named owner/destination task; it is not a
reason to claim that a future authorized W2 local setup is unavailable.

The fresh producer plans only W2. It may retain the later external W3 contract
with its owner and correction route. No synthetic record supplies the W3
contract, feature implementation, remote target, deployment, or consumer
validation.
