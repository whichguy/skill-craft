# Candidate discovery acceptance samples

Two fresh native readers use current rendered discovery packets and a frozen
ShipLoop package. One local whitespace helper and one synthetic CRM/document
workflow; no extra investigation-plan treatment text. All remote data are fixture
observations. Baseline and preserved source are required. No callbacks, Improve,
implementation, network, installation or remote writes. Eight minutes, 24 host
actions and 900 note words per discovery sample. Bounds are instructions, not
a runtime watchdog; process receipts measure fixture probes only.

Local acceptance: current behavior/baseline, proposed narrow delta, no full
investigation plan/field table and no remote prerequisites.
Multi acceptance: visible bounded investigation plan; current identity before
dependent reads; relevant inventory page2; native state candidates; separate
operator/runtime/end-user roles; explicit runtime write denial from a named
principal observation; lock/atomicity/completion/recovery limits; facts versus
proposals; only actual consumers gated.
Both: exact index-to-note and note-to-receipt locators, declared limitations,
protected input bytes unchanged. Use the existing project index and existing
evidence fields; do not add a runtime stage.

One fresh cold planner receives the completed multi-system project directory
and a current plan packet, starts from SHIPLOOP.md alone and follows its links.
No explicit discovery-note or receipt filename is supplied in the cold launch.
Success requires finding both via the index and carrying unresolved state, access
and recovery prerequisites into a conditional plan. Missing links remain failures;
no coordinator rescue. Five minutes and 600 words, PLAN.md only, no tests/probes.

This is acceptance sampling, not an A/B efficacy claim. One sample/case; no
platform execution, full ShipLoop callback acceptance, or model-general result.
Review against these criteria; keep failures and do not silently replace them.
