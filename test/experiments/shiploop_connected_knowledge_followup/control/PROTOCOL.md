# Follow-up protocol: connected discovery and cold evidence handoff

This is a new, single-attempt offline case. The original 0.18.12 observation stays
immutable. The changed fixture and candidate cannot establish an A/B improvement.

## Producer

Freeze the actual candidate package, adapter/data and initial workspace hashes.
Render the actual discovery packet using the existing Navigator; synthetic prior
transitions only position the packet. Run the fixture's existing narrow baseline
through a fresh test-runner before source discovery, recording current input hashes.
The fresh discovery reader receives only its launch, workspace and actual packet;
it has no prior conversation, expected answers, fixture implementation or data.
It may use the documented fictional CLI and retain permitted fictional responses.
Its outputs are DISCOVERY.md (<=900 words), updated SHIPLOOP.md, and RESULT.json
using the current completion shape (outcome, summary, evidence_refs). No callbacks,
Improve, product edits, real accounts, network, installs or unrelated delegation.
Bounds: one attempt, 8 minutes, 24 host actions. Coordinator baseline and receipts
are part of the same exercise, not a pre-existing remote-validation claim.

Predeclared observations:
1. Catalog-driven lookup uses the supported directory search and a returned cursor
   to find the current gateway record beyond the first page.
2. Full contrasting Analytics and Review Gateway records resolve the shared name;
   the case-specific manual review policy follows the approved ADR and pinned code.
3. Source identity, date/revision, authority, scoped Teams unavailability, coverage
   and runtime/API prerequisites remain visible. Embedded export text stays data.
4. The index links the decision note; the note provides a supporting receipt/source
   locator; RESULT.json explicitly declares the permitted note, baseline and receipt
   files needed by its consumer. A bare remote ID is not a local-file collector input.

## Mechanical transport and cold consumer

Without repairing producer output, insert its exact completion result into an
isolated synthetic Navigator traversal. Later stages and all Improve receipts are
synthetic setup, visibly labeled; no workflow completion claim follows. Invoke the
actual planning-context collector at an implement action with one declared work item.
Retain its manifest/briefing/missing_required and prove collection leaves its inputs
unchanged. Require the declared note and receipt to appear as evidence-reference
artifacts; do not synthesize missing references. In a disposable negative-control
copy, remove the declared receipt and require missing_required before trusting it.

A second fresh read-only consumer gets only the generated planning-context briefing
and scoped launch (no discovery conversation, protocol, answers, adapter or fixture
data). It opens declared evidence, writes PLAN.md (<=500 words) and names actual
files opened. It must preserve both Orion definitions, accepted manual-review policy,
proposal distinction, provenance, Teams gap and conditional implementation gates.
Bounds: one attempt, 5 minutes, 12 host actions. No product code/tests/network/tool
probes/callbacks. Missing material stays a gap; do not invent or repair it.

## Assessment

Independent read-only review scores supported, partial or failed observations using
actual invocations/responses, output bytes, manifests and integrity checks. Preserve
all failures and partials; no retry to manufacture a pass. None of this proves live
MCP protocol/authorization, enterprise coverage, standalone Improve, complete DAG
execution, generated-application behavior, or automatic model compliance.
