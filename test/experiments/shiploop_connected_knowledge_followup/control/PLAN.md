## Evidence and alternatives

Local packet source currently places discovery's handoff at the end of its
runtime-state paragraph and refers to it without a direct STAGE_REFERENCES entry.
The prior sample omitted a receipt locator despite existing long-form instructions.
This supports a routing/salience change, not a claim that one sample proves causality.
A second full handoff checklist is rejected as duplicated authority and token cost.
Automatic validation of all remote source locators is deferred: authorization,
meaning and retrieval route are host-dependent; mere string presence is not proof.
A separate orchestration stage is rejected because current actions and collection
already provide the needed producer/consumer boundary.

MCP's resource specification supports paginated listing and host-selected context
interfaces. It does not require a universal user-facing lookup operation; the new
fixture samples a capability-limited directory without claiming MCP wire compliance:
https://modelcontextprotocol.io/specification/2025-11-25/server/resources

## Verification boundaries

Structural suites demonstrate routing and transport, not model compliance. The new
single-attempt synthetic sample is a follow-up with changed fixture and candidate,
not an A/B comparison, measured improvement estimate, real enterprise access test,
or complete ShipLoop/Improve/application execution. Source/fixture hashes and actual
reader receipts must accompany claims. No secret or real organization data is used.
