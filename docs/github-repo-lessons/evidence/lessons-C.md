## 1. obra/superpowers
1. **Description = trigger only, never workflow.** Where: `skills/writing-skills/SKILL.md` (CSO section); every `skills/*/SKILL.md` description starts "Use when ...". Why: the repo records that a description summarising "code review between tasks" made an agent do one review instead of the skill's two. Apply: our packet/skill descriptions should name only the trigger condition; keep sequence in the body or script.
2. **Bootstrap skill injected by hook, with 1%-chance framing.** `hooks/hooks.json` (SessionStart matcher `startup|clear|compact`) runs `hooks/session-start`, which inlines `skills/using-superpowers/SKILL.md` in an EXTREMELY_IMPORTANT block. It re-fires after clear/compact. Why: routing does not depend on the model remembering to look. Apply: our ShipLoop already prints packets; the same idea is re-injecting the rule head after compaction.
3. **Rationalisation tables + "Iron Law" + delete-means-delete.** `skills/using-superpowers/SKILL.md` (Red Flags table: thought vs reality), `skills/test-driven-development/SKILL.md` (Iron Law, "Common Rationalizations"). Why: pre-empts the specific excuses the model generates. Apply: the harness packet for a stage should list the 3-5 excuses seen in our own failed runs and their rebuttals; mine them from run journals.
4. **Skills are pressure-tested as TDD for prose.** `skills/writing-skills/testing-skills-with-subagents.md` (RED: run scenario without skill, GREEN: write skill, REFACTOR: close loopholes) and `persuasion-principles.md` (authority/commitment framing; cites a 33% to 72% compliance rise). Apply: our rubric-eval/E2E should have a no-skill baseline arm per rule so each rule is shown to prevent a seen failure.
5. **Fresh subagent per task, context constructed not inherited, two-gate review.** `skills/subagent-driven-development/SKILL.md` ("never inherit your session's context"), `implementer-prompt.md`, `task-reviewer-prompt.md` (spec + quality verdicts from one diff file; "Do Not Trust the Report"; reviewer may not spawn reviewers), `re-review-prompt.md` (scoped re-review of the fix diff only). Fix loop capped at 5 rounds: rounds 1-3 resume implementer, 4-5 fresh implementer on stronger model, then adjudicate. Apply: the reviewer reads a script-generated diff file, not the implementer's narrative.
6. **Ledger on disk survives compaction.** Same SKILL.md "Setup": `scripts/sdd-workspace PLAN_FILE` prints a git-ignored per-plan dir under `.superpowers/sdd/`; `progress.md` first line names the plan, `Task N: complete` lines gate re-dispatch ("re-dispatched entire completed task sequences — the single most expensive failure observed"). Apply: same lesson as our script-owned state; note they use a script only for the path and leave the ledger to the model.
7. **Plans are anti-placeholder and self-scanned.** `skills/writing-plans/SKILL.md`: bite-sized tasks; "TBD", "handle edge cases", "write tests for the above" listed as plan failures; step scan for "a line that decides nothing is a gap" and for over-specified transcripts; Review Focus lists five uncovered failure modes each with a test added. Pre-flight conflict scan in SDD writes a per-task-pair table to the ledger (a table, not a verdict, so it cannot be claimed without rows).
8. **"Rulings, not stalls."** SDD SKILL.md: unattended execution records `Ruling: <what> - <why> - <cost if wrong>` and continues; only four named stop reasons. Matches our unattended default.

Surprise: the most-copied rule (description must not summarise workflow) comes from an observed single-review failure, and the 2026 edition is mostly cost control: model selection per role, "narrate at most one short line", reviewers forbidden from running suites.

## 2. affaan-m/everything-claude-code (ECC)
1. **Hooks that deny with a question instead of asking "are you sure".** `scripts/hooks/gateguard-fact-force.js` (PreToolUse Edit/Write/Bash): first touch of a file is denied with "present these facts" (importers, public API, schema, instruction quote), retry passes. Header: asking yes/no gets "yes"; demanding facts forces investigation. Per-session denial cap and exempt globs exist. Apply: a script gate that refuses a step submit until the evidence fields are non-empty is the same trick, stronger because the script checks them.
2. **Exit-2 blockers for agent shortcuts.** `scripts/hooks/block-no-verify.js` (blocks `--no-verify`, `core.hooksPath` redirects with shell-aware scan via `scripts/hooks/lib/shell-scan`), `config-protection.js` (blocks edits to linter/formatter configs so the agent fixes code not rules). Apply: protect our test/lint config and release-boundary files the same way.
3. **Profile/flag gating around every hook.** `scripts/hooks/run-with-flags.js` takes id + script + profiles (`minimal,standard,strict`); env switches (`ECC_DISABLED_HOOKS`, `ECC_GATEGUARD=off`). Why: lets enforcement be tiered and disabled per hook without editing hooks.json. Apply: our hook costs memory says env gates kill soft exit; copy their id-per-hook scheme to make any single gate switchable.
4. **Context kept small by counters, not by instruction.** `scripts/hooks/suggest-compact.js` (tool-call count threshold 50 then every 25, or window-scaled token threshold), `pre-compact.js`, `session-start.js`/`session-end.js` persist session state; skill `skills/context-budget`. Apply: trigger compaction advice from measured numbers.
5. **Instinct learning with confidence.** `skills/continuous-learning-v2/SKILL.md`: hooks observe, atomic "instincts" with confidence 0.3-0.9, project-scoped vs global, promotion to skills. Why: memory is small units with provenance, not one growing file. Apply: our memory/journal could carry a confidence + scope field.
6. **TDD as an agent plus a hook gate.** `agents/tdd-guide.md` (RED run must FAIL, GREEN, 80% coverage required); `scripts/hooks/quality-gate.js`, `stop-format-typecheck.js`, `post-edit-typecheck.js` run checks outside the model. Weaker than superpowers: coverage target is stated, not forced by a script.
7. **GAN-style generator/evaluator split with a live app.** `agents/gan-planner.md`, `gan-generator.md`, `gan-evaluator.md` (evaluator drives Playwright and scores a rubric). Apply: evaluator scores the running product, not the diff; fits our E2E judge.
8. **Untrusted-content baseline pasted into every agent/CLAUDE.md** ("Prompt Defense Baseline"). Cheap but bloats each prompt; ~70 language-specific reviewers/resolvers (`agents/*-reviewer.md`) is breadth, not mechanism.

Surprise: the repo is mostly volume (311 skills, ~70 agents), but its single strongest idea is GateGuard, a hook that converts "confirm" into "show evidence"; and it names its own failure mode (LLMs always answer yes).

## 3. gsd-build/get-shit-done (GSD)
1. **Orchestrator stays lean; every plan runs in a fresh executor.** `get-shit-done/workflows/execute-phase.md` ("Orchestrator coordinates, not executes"; wave-grouped parallel spawn, executors receive prior-wave SUMMARY.md plus CONTEXT/RESEARCH), `agents/gsd-executor.md`. Apply: this is our "one step per context" principle; the wave number is computed at plan time and stored in frontmatter.
2. **Plans sized to ~50% of a context window.** `agents/gsd-planner.md` ("Plans should complete within ~50% context", 2-3 tasks per plan; TDD gets its own plan because RED-GREEN-REFACTOR eats 40-50%). Why: quality degrades with fill, so size units by context cost not by human time. Apply: add a context-cost estimate to our step sizing.
3. **Plan is machine-readable and goal-backward.** `get-shit-done/templates/phase-prompt.md` frontmatter: `wave`, `depends_on`, `files_modified`, `requirements` (must be non-empty), `must_haves: {truths, artifacts, key_links}`. Planner derives must-haves backward from the goal. Apply: key_links ("what must be CONNECTED, this is where stubs hide") is a cheap wiring check we can script.
4. **Verifier starts from "goal not achieved".** `agents/gsd-verifier.md` ("SUMMARY.md claims are not evidence", FORCE stance, existence is not behavior, stub detection). Plan checker has a revision gate: max 3 loops then escalate (`agents/gsd-plan-checker.md`). Same adversarial-default as superpowers' "Do Not Trust the Report".
5. **Hook reports context numbers to the agent.** `hooks/gsd-statusline.js` writes metrics to a /tmp bridge file; `hooks/gsd-context-monitor.js` (PostToolUse) injects additionalContext at <=35% remaining (wrap up) and <=25% (stop, save state), debounced 5 tool calls, stale after 60 s. Apply: the model cannot see its own usage; a hook that tells it is the working pattern.
6. **Durable state in small named files.** `.planning/STATE.md` ("project's living memory"), PROJECT, ROADMAP, per-plan SUMMARY, `continue-here.md` for pause/resume (`get-shit-done/templates/`), plus `sdk/` (gsd-sdk query layer) so scripts, not prose, read plan inventories as JSON (execute-phase.md "Load plan inventory ... Parse JSON").
7. **Soft vs hard hooks, opt-in.** `hooks/gsd-workflow-guard.js` is advisory only and off by default ("SOFT guard"); `hooks/gsd-validate-commit.sh` blocks non-Conventional commits with exit 2 but is a no-op unless `.planning/config.json` has `hooks.community: true`. Also `gsd-read-injection-scanner.js`, `gsd-prompt-guard.js` for injection screening.
8. **Specialised single-purpose agents (33)** incl. `gsd-nyquist-auditor` (validation coverage), `gsd-integration-checker`, `gsd-assumptions-analyzer`, `gsd-code-fixer` (review then fix split).

Surprise: its central claim is not "spec-driven" but that plan size is bounded by context fill (50%), and the executor is told to never trust the previous step's own summary.
