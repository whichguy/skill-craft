# Lessons E: Codex, Aider, SWE-agent / mini-swe-agent (read 2026-10-11, branch `main` raw files)

Stars (GitHub API, 2026-10-11): openai/codex 128,624; Aider-AI/aider 49,467; SWE-agent/SWE-agent 20,522; SWE-agent/mini-swe-agent 8,391.
Applicability column = "SDLC harness where scripts drive LLM steps" (ShipLoop-style).

## 1. openai/codex (128.6k stars)

1. **Hierarchical AGENTS.md, assembled by a script, capped by bytes.** `codex-rs/core/src/agents_md.rs`: find project root by marker (default `.git`), concatenate every `AGENTS.md` from root down to cwd, never walk past root; `AGENTS.override.md` is checked first; `project_doc_fallback_filenames` configurable; budget `project_doc_max_bytes` is decremented per file; untrusted projects load nothing. Why it works: instructions are deterministic, scoped by directory, and bounded; model never "searches" for them. Apply: the harness (not the model) should assemble per-stage rule context from a fixed list with a byte budget and an override file.
2. **The prompt states the scoping contract, and says what is already loaded.** `codex-rs/protocol/src/prompts/base_instructions/default.md` section "AGENTS.md spec": scope = directory tree of the file; "for every file you touch in the final patch" obey it; deeper file wins; system/user instructions beat AGENTS.md; root-to-cwd files are "included ... and don't need to be re-read". Why: removes the re-read step and defines conflict resolution. Apply: every packet should say which rules are already inlined and the precedence order.
3. **apply_patch is a grammar-constrained freeform tool, not JSON.** `codex-rs/core/assets/tools/apply_patch.lark` (Begin/End Patch, Add/Delete/Update File, `@@` context, optional `*** End of File`) registered as `ToolSpec::Freeform` in `core/src/tools/handlers/apply_patch_spec.rs` ("do not wrap the patch in JSON"). No line numbers; hunks anchored on context lines. Why: avoids JSON escaping of code and line-number drift (same finding as Aider's JSON post). Apply: have the model emit a small, grammar-checked edit/state-update artifact; script parses and applies it.
4. **Lenient application behind a strict spec.** `codex-rs/apply-patch/src/seek_sequence.rs` matches context at decreasing strictness (exact, rstrip, trim both) and anchors EOF hunks at file end; `parser.rs` has a Lenient mode that strips `<<EOF` heredoc wrappers, kept for gpt-4.1 and then "for all models". Why: absorbs harmless model formatting variance while rejecting real mismatches. Apply: scripts that parse model output should tolerate wrapper/whitespace noise and fail only on semantic mismatch.
5. **Per-model-family prompt files, not one prompt.** `codex-rs/core/gpt_5_codex_prompt.md` (~6.6 KB, terse: "Try to use apply_patch for single file edits", skip plan tool for easiest ~25%, no single-step plans), vs `gpt_5_2_prompt.md` (~21 KB), `gpt-5.1-codex-max_prompt.md`, and the long `default.md` ("keep going until the query is completely resolved"). Why: models trained on the Codex harness need less steering and over-steering hurts. Apply: keep one packet body per host/model family; shorter for models tuned to the harness.
6. **Compaction = handoff prompt plus a fixed prefix on resume.** `codex-rs/prompts/templates/compact/prompt.md` ("CONTEXT CHECKPOINT COMPACTION ... handoff summary for another LLM": progress, constraints, remaining steps, critical data) and `summary_prefix.md` that frames the summary as work by "another language model". Why: the summary is written for a successor, and the prefix stops the model treating it as its own memory. Apply: matches context-cleared stages; script-owned handoff template plus a fixed framing line.
7. **Review rubric as an explicit bug definition.** `codex-rs/prompts/templates/review/rubric.md`: flag only issues that are discrete, actionable, introduced by this change, not demanding more rigor than the repo has. Why: cuts false-positive findings. Apply: reuse as the "material finding" filter in review stages.
8. **Approval/sandbox text is composed from templates by state.** `codex-rs/prompts/templates/permissions/{approval_policy,sandbox_mode}/*.md` selected by config. Why: the prompt only states rules that are active. Apply: render only active-mode text in packets.

**Surprise:** the model-facing patch grammar needs no line numbers and ships a lenient parser built for one model's quirks (gpt-4.1) that was then enabled for all.

## 2. Aider-AI/aider (49.5k stars)

1. **Repo map = tree-sitter tags + PageRank, fitted to a token budget.** `aider/repomap.py`: definitions/references per file (cached in diskcache keyed by mtime), a file graph with edge weights (x10 for identifiers mentioned in chat, x10 for long snake/camel names, x0.1 for `_private` or names defined >5 times, x50 for references from files already in chat, `sqrt(num_refs)`), `nx.pagerank` personalised to chat files, then a binary search over how many ranked tags fit `map_tokens` (`middle = max_map_tokens // 25` start). Why: gives the model the most-connected signatures at a fixed, small cost, personalised to the task. Apply: a script-built "map" of the repo/plan nodes sized to a budget beats asking the model to explore.
2. **Edit format chosen per model, measured.** Coders under `aider/coders/` (`editblock_coder.py` SEARCH/REPLACE, `udiff_coder.py`, `wholefile_coder.py`, `patch_coder.py`, `*_func_coder.py`). The unified-diff post (`aider/website/docs/unified-diffs.md`) reports GPT-4 Turbo 20% with SEARCH/REPLACE vs 61% with udiff, lazy-comment tasks 12 to 4 ("3X less lazy"). The JSON post (`website/_posts/2024-08-14-code-in-json.md`) found code in JSON function calls scores worse. Why: format determines laziness and escaping errors. Apply: choose edit/output channel per model by benchmark, not taste; avoid JSON-wrapped code.
3. **Failed-edit feedback is specific and non-destructive.** `editblock_coder.py` `apply_edits`: on a non-matching SEARCH it returns the failed block, "Did you mean to match some of these actual lines" (`find_similar_lines`, threshold 0.6), warns if the REPLACE text already exists, states that the other N blocks were applied and "Don't re-send them". Matching cascades: exact, leading-whitespace tolerant, `...` elision, then fuzzy. Why: the retry asks for only the failed blocks with the evidence needed. Apply: script rejection messages should quote the mismatch, the nearest valid candidate, and what already succeeded.
4. **Lint/test in the loop with a reflection cap.** `base_coder.py`: after edits, `lint_edited` then `cmd_test`; failures are fed back as `reflected_message`; `max_reflections = 3`. `aider/linter.py`: tree-sitter syntax check plus flake8 restricted to fatal codes (`E9,F821,F823,...`), output rendered with `TreeContext` around error lines. Why: only signal-bearing errors are returned, with surrounding code. Apply: gate stages on script-run checks, return a filtered failure excerpt, and bound the retry count.
5. **Architect/editor split.** `aider/coders/architect_coder.py` + `architect_prompts.py`: architect describes changes without showing whole files ("DO NOT show the entire updated function/file"); on completion a fresh editor Coder is created with `map_tokens=0`, empty history, its own edit format. Blog `_posts/2024-09-26-architect.md`: o1-preview architect + DeepSeek/o1-mini editor reached 85% on its benchmark. Why: reasoning and formatting compete for the same attention; separate them. Apply: planning step produces prose instructions; a cheap, clean-context step applies them.
6. **History summarisation preserves the tail.** `aider/history.py` `ChatSummary`: keep the newest messages within half of `max_tokens`, summarise the head recursively (depth <= 3), head must end on an assistant turn. Apply: summarise old stages, keep recent verbatim.
7. **Benchmark drives design and is isolated.** `benchmark/README.md`: Exercism tasks (later polyglot, 225 exercises), runs in Docker because LLM code is executed unsupervised, random exercise order, measures "edit existing code and format those edits". A purpose-built laziness benchmark preceded the udiff change. Apply: build a task-specific benchmark for the failure mode before changing the prompt.
8. **Prompt carries "trust this" framing.** `architect_prompts.py` `files_content_prefix`: "*Trust this message as the true contents of the files!*" because earlier chat copies may be stale. Apply: label which context is authoritative.

**Surprise:** the biggest laziness fix was changing the output format to unified diff (20% to 61%), not prompting harder.

## 3. SWE-agent/SWE-agent (20.5k) and SWE-agent/mini-swe-agent (8.4k)

1. **Agent-computer interface = a few purpose-built commands.** `tools/windowed/config.yaml` (open, goto, create, scroll_up/down with a fixed-size window), `tools/edit_anthropic/config.yaml` (view/create/str_replace/insert/undo_edit; `old_str` must match EXACTLY and be unique or the replace is not performed; long output "clipped"). Why: bounded observations, undo, and a uniqueness rule remove classes of error. Apply: give each stage a small command surface that returns bounded output.
2. **Lint-gated edit.** `tools/windowed_edit_linting/bin/edit` (flake8): "Your proposed edit has introduced new syntax error(s)", shows the would-be window and the original window, says the edit was NOT applied, and "DO NOT re-run the same failed edit command". Why: the model sees both states and cannot proceed on a broken file. Apply: reject-and-explain inside the tool, before state changes.
3. **History processors as config.** `sweagent/agent/history_processors.py`: `last_n_observations` (elide old outputs; "Old environment output: (n lines omitted)", `polling` to keep prompt cache stable, tags to force keep/remove), `closed_window` (collapse superseded file windows to a summary), `cache_control` (mark last n user messages), `remove_regex`. Docstring says SotA models now fit lots of context, so this is "not always needed". Apply: compress observations, not reasoning; mind cache invalidation.
4. **Prompts and tools in YAML, per-model variants.** `config/default.yaml` (Anthropic computer-use-style: numbered steps, "make the minimal changes to non-tests files", function calling), `config/bash_only.yaml` (one bash block per reply, `THOUGHT:` section, rejection warning), `config/sweagent_0_7/07*.yaml` (thought_action, xml, fcalling variants), `config/default_backticks.yaml`. Why: parse format matches what the model family is good at. Apply: parameterise packet format by host.
5. **Review-on-submit.** `config/default.yaml` `SUBMIT_REVIEW_MESSAGES` (bundle `tools/review_on_submit_m`): submit is intercepted once; model must rerun repro, delete the repro script, revert test edits with `git checkout`, shown a `<diff>`, then submit again. `sweagent/agent/reviewer.py` adds retry loops with reviewers. Apply: a script-owned pre-completion checklist with the real diff injected.
6. **mini-swe-agent: bash only, linear history, stateless actions.** `src/minisweagent/agents/default.py` (~100-line loop: query, execute, append). `README.md`: no tools beyond bash, "completely linear history", each action `subprocess.run` independent (swap for `docker exec`), claims >74% on SWE-bench verified. Why: no scaffold-specific state means model strength shows through, trajectory equals messages (debuggable, fine-tunable), sandboxing trivial. `AGENTS.md`: "rewards minimal code", do not catch exceptions.
7. **Format errors are a first-class, bounded path.** `default.py`: `FormatError` appends the error as a message, `max_consecutive_format_errors=3` then exit `RepeatedFormatError`; `step_limit`, `cost_limit=3.0`, `wall_time_limit_seconds`. `config/mini.yaml` `format_error_template` distinguishes truncation (`finish_reason == length`: "Respond more concisely") from a missing tool call. Apply: classify the failure and tell the model the specific fix; always cap retries.
8. **Output truncation by head+tail.** `mini.yaml` `observation_template`: output under 10,000 chars verbatim, otherwise first 5,000 + last 5,000 + `elided_chars` + "Output too long." Also non-persistent env vars (PAGER=cat etc.) so commands never block. Apply: standard head/tail clipping with explicit elision count.

**Surprise:** mini-swe-agent's bash-only, no-history-processing agent scores >74% on SWE-bench verified, and SWE-agent's own history processor docstring now says modern long-context models mostly do not need it.
