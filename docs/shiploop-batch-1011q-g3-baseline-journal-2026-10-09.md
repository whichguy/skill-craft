## What each part measures, and the evidence

Everything below was recomputed from `/Users/dadleet/e2e-runs` (29 run folders: 22 with a `result.json`, 3 with launch
records only, and the 4 Sonnet resumes of `20261003/batch-sonnet`) and the 23 committed rows. Where the design text
disagreed, the recomputation wins.

**Plugin tree digest (`plugin_sha256`).** sha256 over each file's relative path and the sha256 of its bytes, in sorted path
order, leaving out `__pycache__`, `*.pyc`, symlinks and non-files; 12 hex. A file or folder that cannot be read gives no
digest at all with the reason (`plugin_sha256_unmeasured`), never a digest of fewer files. v1220-battleship-sonnet
19868f9ee770 against v1230-battleship-sonnet 452b7e2eb831 (both plugin 1.22.0 / ShipLoop 0.54.0); r1-battleship-sonnet,
r1-checkers-sonnet and r1-battleship-grok-none all 3a7515d2efd3 (three runs, two heads: 587cd90d for r1 Battleship and r1
Grok, 5e209285 for r1 Checkers). The design's values (142047ca62ed for the r1 trio) came from a different algorithm and
are not reproduced; the equivalence classes are the same. Pinned by a golden value on a two-file tree (`96788439bf74`).

**Prompt digest (`prompt_sha256`).** sha256 of the prompt with every spelling of the run's output folder (resolved,
requested, without `/private`, `~/...`) replaced by `<output>` where it is not part of a longer name, stripped, 12 hex.
The five Grok `none` prompts: five raw 8-hex hashes (f32a5a16, 0a4c7bbe, 4a7bc018, f45d5e6e, cd6dbebe), one masked
(5ea67bf3...). Named cases: battleship d0c0cbe71344, checkers e4da54c7f03d. It takes the final prompt text, so group G5's
appended planning-review sentence can be excluded at merge in one line.

**Host build (`host_build`).** One meaning: the build of the run's first launch. Claude: `metrics.claude_code_version` (init
event); for an older run whose metrics lack it, the report reads the init event in `events.jsonl` (v1220: 2.1.291). Grok
and Codex: first stdout line of `<cli> --version` (`grok 1.0.50 (c58f321264ba)`, `codex-cli 0.162.0`), probed once per
launch in `_main` in the launch's own isolated environment and written on that launch's record; the result keeps the first
launch's (a resume reads it from `invocation.json`); a regrade restates it; the report reads the first launch record only.
Null for every run whose first launch predates the field (a resumed pre-change run does not get today's build), with the
reason in `identity_unmeasured`.

**Span, planning window, head, reasons.** `started`/`ended` are the first and last stamp of `timeline.jsonl`
(`metrics.span`); `planning_seconds` is `metrics.planning_seconds(planning)`, the closed window on the engine's clock and
null while open or unreadable; `local_head` is `versions.local_head` (checkout) or `versions.released.local_head`
(marketplace). `identity_unmeasured` ({} when all known) is on the row, in `result.json` and on each launch record, with a
reason for each null identity field. **Which source wins** (audit correction 13): when a row and a folder both describe a
run, the row wins wherever it has a value, the folder fills the rest, and every field it supplied is listed in `recomputed`.
v1230-battleship-sonnet's file row has no planning figure; its regraded `metrics.json` holds a closed 388 s window, so the
Battleship planning cell is n = 4 of 5 (4.85 / 5.56 / 6.47 minutes), not the design's 3 of 5.

**One matching predicate.** `run.row_matches(row, case, source, host, model, effort, planning_review, prompt_sha256)` returns
None or the reason; `matching_rows`, `scan_baseline`, `previous_row` and the report all use it. A row is a basis when the
case and the source name (not the note a resume adds), the host/model/effort, the `planning_review` mode (the plugin-version
rule for a row without one) and the prompt key agree and `row_reached_done` holds (`verdicts.shiploop` not false and the
recorded engine status done or absent). Prompt key: always for case `custom` (a hash on both sides and equal), only when
both carry one for a named case. The report differs in two named ways: it takes host/model/effort/mode/prompt from the
run's folder for a row that predates them (listed in `recomputed`; the live rule never does), and a named case's row with no
hash sits in the driver's only cell, or in a cell of its own when the driver has several prompts.
Of the 23 committed rows, 15 name no host, model or effort and were never a basis; 6 (v1200-hello-sonnet,
v1220-battleship-sonnet, v1230-battleship-sonnet, r1-checkers-sonnet, r3-battleship-sonnet, r3-checkers-sonnet) keep
comparing; the two Grok `none` rows (v1220-battleship-grok-medium-none and the blocked v1230-battleship-grok-none) are the
transitional break.

**Subject run.** A run whose own engine did not reach done still writes its row and prints
`baseline  nothing compared: this run did not reach done (engine blocked)`. This is the r1 Grok defect
(`turns 503 -> 301, cost $14.1673 -> $8.7455` in `r1-grok.log`, against the blocked 2026-10-07 row). Grok figures on the
`baseline vs` and follow-on lines and in `progress.py` carry `(lower bound)`.

**The report.** Over the real data: 39 attempts in 17 cells (13 in the file and a folder, 16 in a folder only, 10 in the
file only): 15 counted, 9 rows that name no host/model/effort, 7 resumed, 4 not done, 3 with no result, 1 mixed host. The
first version walked two levels and missed the four Sonnet resumes of `20261003/batch-sonnet`, and used a cell rule of its
own (see below); both are fixed. Sonnet Battleship: n = 5 on 5 plugin trees and host builds 2.1.291/2.1.292/2.1.294, cost
5.6749 / 5.8146 / 9.6543, turns 197 / 207 / 294, minutes 12.6 / 13.8 / 20.0 (4 of 5 overlapped another recorded span; v1220
ran alone). Sonnet Checkers: n = 3, cost 5.1613 / 6.6509 / 8.5146, turns 185 / 232 / 293, planning 5.67 / 6.12 / 7.02 (3
of 3 overlapped). Grok `none`: 5 attempts, 1 counted (v1220: 467 turns, $12.5014, lower bound), 2 not done (v1230, r1), 1
mixed host (r2), 1 resumed (r3). The loop's rows in the committed file: r1 Checkers, r3 Battleship, r3 Checkers (3 of 7);
r1 Battleship, r1 Grok, r2 Battleship and r2 Checkers exist only as folders.

**The one same-build pair.** The two v1190 hello runs share a plugin tree (643ee0214c57) and a Claude Code build (2.1.289):
194 against 254 turns, $5.3678 against $7.3252, 12.8 against 15.4 minutes; the second started 59 s after the first and
overlapped v1180-hello-sonnet for 722 s. They are the only such pair in the data and sit in a hello/marketplace cell of 5
runs on 4 trees, so even there a range pools builds. The Battleship and Checkers cells have no such pair, so build effects
and run-to-run spread cannot be separated there; the report says a range across builds is not a noise estimate and makes
no within/above/below claim.

**Grok session count.** See the commit `073fd4dd`/`9215bc61` messages and the LEARNINGS entry. `available_commands` is
repeated inside one session (r1: 314 for 2 `end`, 301 model calls); `end` is the only per-session marker. The count is null
for a stream with Grok in it (a launch record names Grok, or `usage` events: never a field of one event) and the marking
stays; where `usage` events follow the last `end` or there is none (r2 69, r3 230, v1210 328), at least one session never
reported (`unreported_sessions_at_least`). **The rule G2's sessions.jsonl will enable:** a launch's first line is known to
`run.launch` (`line` at its start), so a launch whose line range holds no `end` event never reported; counting those gives
an exact `unreported_sessions` and replaces the null.

Disagreements: none. Deviations from the design text, and why:
- The `sample:` facts are a line under `baseline vs` and not appended to it (that line is already ~200 characters). No live
  spread line is printed: the report prints min/median/max, and the brief made the live line optional.
- `matching_rows` returns a third value (why each other row was skipped) so the 'nothing compared' line can name the reason.
- `--baseline-report` lives in `run.py` beside `scan_baseline`, not in a new module: one code path (S-12), and a new
  module importing `run` would import it twice when run as a program.
- A cell's `source` is the first launch's (`invocation.json`), normalised to the part before ' (': r3-battleship-grok-none
  was started as a checkout run and resumed on a marketplace install; it belongs with its first launch.
- A `plugin_dir` outside the run's own folder is never digested after the fact (the same reasoning as the host build).
- FAKE_GROK/FAKE_CODEX in `test/shiploop-e2e.test.py` get no `--version` branch: the new tests wrap the shared fakes. Seven
  assertions there are edited: three list `unreported_sessions` among a Grok stream's unmeasured counters (a stream of Grok
  usage events used to claim an exact 0), four read `(lower bound)` after a Grok figure.
- The overlap key is `overlapped_by_span`, not `overlapped_at_least`, because the count is neither a floor nor a ceiling.
