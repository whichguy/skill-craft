Recommended changes, in order

1 · ADOPT · HIGH

Require a valid review before counting it as clean

A failed reviewer with no JSON and an exited reviewer returning only {"learnings":[]} both produce an empty actionable list. The iteration branch advances its clean streak whenever the product result passes. The control-flow probe reaches two with those unusable reviews; a failed product result correctly resets the streak.

Validate process success and the required review structure before consuming findings or advancing convergence. Retain distinct invalid, failed and timed-out outcomes. Confirm that each malformed/failed control stays non-clean and that a valid empty review still counts. This is a parser and branch reproduction, not execution of a full live iteration loop.

2 · ADOPT · MEDIUM · CONDITIONAL

Grade the run created by this invocation

grade_shiploop() searches descendant state files and prefers a completed run with a report. A synthetic output folder containing an active work/.shiploop state and an unrelated completed state is graded from the completed one. No retained live misgrade was established.

Record and use the run path/ID emitted by the invocation. A resume should use that same identity. Treat multiple plausible candidates as ambiguous. Validate current-active + stale-done, multiple candidates, and a legitimate external run directory; preserve support for workspaces beside work/.

grade_shiploop — selection · 972; resume selection · 2601; State probe
3 · ADOPT · MEDIUM

Calibrate the product checks against a broken product

All four development Battleship checks returned zero for a synthetic server with no fleet, no playable game and gameOver=true from the start, plus one passing placeholder test. The probe changed only the three port numbers in the check commands. The current checks establish protocol smoke behavior, not the full requested game.

Add a small independent behavioral verifier tied to the public request: genuine game progression, hits/sinks and a valid terminal condition. First prove it rejects the broken control and accepts valid implementations. Keep the separate mutation/quality records as records; do not silently turn them into a new pass gate. The prior acceptance set was removed because it did not distinguish deliveries, so restoring it unchanged is not a remedy.

4 · ADOPT · MEDIUM · CONDITIONAL

Bind HTTP checks to their candidate process

The catalog starts servers on fixed ports and grades the HTTP response without checking who served it. With a temporary sibling serving a “Battleship” page, the exact page-check command exited zero even though the candidate handler could only return “candidate”. The sibling-response explanation and bind collision are inferred from those handlers and the occupied port; the original response body and bind stderr were not retained.

Use per-run ports and confirm that the launched candidate owns the listener before accepting responses. Retain startup errors and clean up only that process. A regression should reject the sibling-server control and pass the same candidate on its own. The current “rerun concurrent failures alone” rule cannot detect a false green.

The specification calls breadth the generality gate, with one case per style. Its three cases cover web service, CLI files and stateful service. All four parallel-graph cases are selectable directly but absent from every named suite. Breadth also omits smoke; hello covers it in a focused suite and the batch gate, not in breadth.

Add one representative graph case to a focused path and, once qualified, to breadth—or narrow the documented claim. Keep the other cases opt-in. A catalog-selection check can prevent drift without launching a model. This does not establish that the graph cases already have a passing baseline.
