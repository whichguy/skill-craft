# Adversarial review: Backchain fix round: binding checks after the first adversarial review

Reviewer: codex:gpt-6.1-sol@medium

- **F1 (high, untested-case)** finish can attach a stale or absent final source assessment to the current output and still report convergence. It validates the final review's action identity, but does not require its candidate identity, source assessment, coverage, or findings to describe the final candidate. caller_review then supplies the current output digest, making an unbound assessment appear candidate-specific.
  - Experiment (scenario): Complete a caller-packet run, then finish with a review containing only the four matching identity fields. Repeat with an assessment of the inherited candidate after materially revising it. Refuted if: Both reviews are rejected or force an incomplete result because final-candidate source evidence is missing or stale.
- **F2 (high, untested-case)** The receipt action-count check still accepts callbacks submitted without record when extra records pad the count. It does not establish that each submitted report came from a recorded cycle.
  - Experiment (scenario): Under the default gate, submit a handwritten non-trivial report in callback 1. In callback 2, record twice and submit only the second recorded trivial report. Run finish on the genuine terminal receipt. Refuted if: finish rejects the run specifically because callback 1's report has no corresponding recorded submission, despite two actions and two records.
- **F3 (high, untested-case)** The assessment check still permits an empty inspection in substance to qualify as a trivial review. A current digest and a nonempty list do not establish any required lens, source, bounds, or chunk checks.
  - Experiment (scenario): Record an unchanged valid candidate using its printed identity, change_class trivial, checks [null], and empty findings, planning_gaps and execution_blockers; then submit the report and finish. Refuted if: record refuses the assessment for lacking substantive required inspection evidence, preventing convergence.
- **F4 (medium, overreach)** The new edge grouping can broaden edit permission: allow_new_edges false still permits adding input objects under an existing provisional consumer/supplier key. Callers expecting per-input protection can authorize more work than intended.
  - Experiment (scenario): Give provisional S2 and S2<-S1, set allow_new_edges false, and add another structurally valid input object from S1 to S2 without removing the original. Run freeze and record. Refuted if: The added dependency is rejected unless the caller explicitly authorizes the broader grouped-input permission.
- **F5 (medium, wording)** The generated callback instructions contradict the newly authorized source-aware removals, which can cause a model to leave an allowed necessary repair undone or declare it blocked.
  - Experiment (scenario): Run one live source-aware callback where removing an inherited provisional edge is the only necessary repair, with explicit bounds permitting that removal. Refuted if: The model performs the authorized removal and completes without treating the generated contract's prohibition as binding or requesting new authority.
