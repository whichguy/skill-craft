I would make ShipLoop’s existing `test` gate require a **discriminating check for consequential behavior**. For a selected acceptance criterion, the script should verify that the right case passes on the current candidate and fails on a relevant counterexample. ## 3. Ranked experiments

These are ranked by expected delivered-quality gain per cost. The experiment thresholds are proposed decision rules. Where the journals have no comparable spread, a fresh repeated control supplies it.

### 1. Script checks — Make a consequential case prove that it can fail

**Change.** In `test-spec` and `test`, bind selected, risk-bearing cases to the criterion and command that own them. Use the existing base, candidate and mutation runners to record a case-level pass on the candidate and a failure for the expected reason on a viable counterexample. For preservation, the original product should also pass. A load failure, unrelated failure, timeout, or missing observation gets its own disposition.

**Why and risk.** Mutation is already the strongest measured check on test quality, and the current case linkage has a mechanically demonstrable gap. A stricter check can still select the wrong counterexample, or burden legitimate harnesses that cannot report a per-case outcome. Start with local, runnable checks for a stated boundary or touched invariant. Use a reachable adjacent input or a relevant product variant. Preserve the existing route for unavailable external observations. [Case gate](/private/tmp/review-8svgxH/skills/shiploop/scripts/shiploop_expectations.py:596) · [Mutation result](/private/tmp/review-8svgxH/docs/ratchet-pilot-journal.md:1026)

**Smallest test.** First replay known-good receipts and deliberately mislinked, no-op, load-only and wrong-outcome receipts. Then use three paired test-stage slices on each of two saved builds, with several validated, independent faults in the affected behaviors. Use the **same** good and faulted builds for scoring both arms, with the fault set outside the model session. The archive’s 24–26/27 spread makes a one-fault aggregate gain unpersuasive. Require a repeated catch of a named target fault in at least two of three pairs on **each** case, with no failures on legitimate implementations or lost required regressions. Minutes and single dollars for replay and a first slice screen. Hours and tens for promotion on more than two cases. Drop if most extra catches are infrastructure failures, equivalent mutations, or defects the current suite already catches.

### 2. Forms — Put consequential choices in the handoff that consumes them

**Change.** Reuse `assumptions`, R-IDs and AD-IDs. For a choice that changes a consumer-visible result, compatibility, or who must act, record the affected clause, source, plausible alternative, and disposition. A supported requirement goes in the acceptance line. A delegated default goes in the plan with its scope and reason. A material choice the evidence cannot settle goes to its owner before dependent work.

**Why and risk.** A section gets filled, open points can survive into planning, and the wrong due-times interpretation propagated unchanged. The failure mode is a well-filled form that classifies an inference as a fact, or turns defaults into unrequested restrictions. Keep the canonical acceptance line and have the form link to it. The preservation trial showed why an extra prose section is a poor authority. [Ratchet F39–F45](/private/tmp/review-8svgxH/docs/ratchet-pilot-journal.md:2524) · [Form displacement](/private/tmp/review-8svgxH/docs/ratchet-pilot-journal.md:2717) · [Limits archive](/private/tmp/review-8svgxH/docs/spec-elaboration-journal.md:1835)

**Smallest test.** Two fresh brownfield requests with one materially ambiguous point each. Use a known answer grounded in the repo for one and an answer only the requester can supply for the other. Include a legitimate delegated implementation choice in each. Three pairs per request through accepted `plan`. Score correct resolution, correctly owned open decision, wrong commitment, and omission against a private answer sheet. The due-times control swung from 1/8 operator-first in stopped runs to 7/12 in whole runs, so use contemporaneous controls. Require at least two fewer wrong commitments or omissions per case across the three pairs and no new unwarranted constraint. Minutes and single dollars for screening, then paired builds against held-out checks for a surviving form. Drop if only record presence improves or baseline already resolves the decision reliably.

### 3. Instructions and their delivery — Put the few indispensable inputs in reach

**Change.** Reuse `_producer_blocks` and the durable packet file. Emit a short action entry with the current callback, required input locators, the checks that can refuse this action, and named reads for the full duties, exact result form and relevant evidence. Put the root mappings and any locator required to perform the immediate assignment beside that assignment. Leave the whole packet available and key the reads to the current action so a resumed model can recover them.

**Why and risk.** The loss is measured on the actual receiving host, and the code already has stable blocks to render. More reads can cost tokens, and a model can skip them too. The read-all wording already moved reference exposure without reliably improving coverage. Optimize for delivery of a specific operative input and its use, with full-packet word count as a diagnostic. [Packet renderer](/private/tmp/review-8svgxH/skills/shiploop/scripts/shiploop_navigator.py:2329) · [Sol exposure](/private/tmp/review-8svgxH/docs/spec-elaboration-journal.md:3232) · [Read-all trial](/private/tmp/review-8svgxH/docs/spec-elaboration-journal.md:3715)

**Smallest test.** Replay a short prefix, a head-plus-tail excerpt, and recovery on the same saved action. **Run one change per afternoon, on two cases with measured headroom.** Use a preserved behavior under a new feature in one case and a distinct consequential boundary in the other. **Pilot a case-level counterexample check in the existing `test` gate.** Start with one explicit changed boundary and one touched behavior that must remain available.
