### R-4 Tickets already in the data file get due times, by an explicit operator command
Owner note N1 (2026-11-23) revised this requirement: the service never fills in due times when it starts. An operator stops the service and runs a separate command, `node bin/backfill-due.js [--data FILE]` (the file is `DATA_FILE` or `--data FILE`; hours from `DUE_HOURS_*`), which gives every ticket that has no due time one, from that ticket's own `created` and `priority`, and saves the file (the usual temporary file and rename), then prints how many tickets it changed. Tickets that already have `due` keep it, so running it again changes nothing. It is not a ticket change: no audit entry, `updated` untouched, no notification. If the service starts with `DUE_TIMES=on` while any ticket has no due time, it refuses to start (exit 2, a log line) and the message names `bin/backfill-due.js`. With `DUE_TIMES` not `on` the service starts on such a file and leaves it as it is. The read-only command line `bin/tickets.js` never writes.
- Positive: a v1 file with T-0001 {priority high, created 2026-01-01T08:00:00.000Z, no due}: after `node bin/backfill-due.js --data FILE` the file holds due 2026-01-02T08:00:00.000Z, version 1, the command prints `1`, a second run prints `0` and leaves the file byte-equal. Confirmed by a command test (TC-8) with main() and a temp file.
- Positive: a ticket that already has a due keeps it even when `DUE_HOURS_*` differ; `updated` and the audit log are equal before and after. Confirmed by TC-8.
- Failure: `createService({dueTimes: true, dataFile: FILE})` over a file with a ticket lacking due throws a ConfigError whose message contains `bin/backfill-due.js`; as a real process `node src/server.js` with DUE_TIMES=on exits 2 and stderr names the command. Confirmed by TC-16 and TC-13.
- Positive: after the command the same process start succeeds with DUE_TIMES=on and lists the ticket with its due; with DUE_TIMES unset a start over the legacy file succeeds and the file is byte-equal after the start. Confirmed by TC-16 and TC-13.
- Boundary: a missing file is an error (exit 2) and writes nothing. Confirmed by TC-8.

- Met by bin/backfill-due.js (`main(argv, {env, out, err})`, exit 0 done and 2 for usage, setting or data file problems); cases TC-8 in test/due-backfill.test.js and TC-13 in test/due-process.test.js (real processes). A re-run changes nothing and does not write. Observed: the service saves the file when it stops, as it always did, so after a start with `DUE_TIMES` off the file is not byte-equal but its tickets are unchanged and hold no due time; that is what TC-13 (c) and TC-16 (b) assert (W1/S3).
