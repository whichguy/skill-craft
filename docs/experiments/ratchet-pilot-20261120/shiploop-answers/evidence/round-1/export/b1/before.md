### R-6 Existing tickets get due times, once, from their own creation time and priority
Basis: request "tickets already in the production data file get due times too ... and keep them". Default of this date: the new release backfills at start whether or not DUE_TIMES is on, using the hours in force then, and saves the data file at once, so the file holds due times before the flag is switched on.
- Positive: a data file of 1.4.0 tickets (no `due`) started with DUE_TIMES unset: the file on disk now has `due` = created + hours for every ticket; a second start changes no `due`.
- Boundary: the file is saved at start only when at least one ticket lacked `due` (an up-to-date file, or no data file, is not rewritten); a file without `due` on its tickets is valid input (that is what 1.4.0 wrote). The backfill belongs to the service's start, so bin/tickets.js and scripts/weekly-report.js, which only read, never write the file. A ticket that already has `due` is never recomputed; a file with no tickets or no data file is unaffected. Backfill writes no audit entry and no outbox event and leaves `updated`.
- Failure: a ticket `due` that is not a time makes the file refused with a message naming the record, like every other record check.
