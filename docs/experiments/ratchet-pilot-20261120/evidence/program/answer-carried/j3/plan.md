## Approach

- Add `assignee` to the store's ticket shape, initialized to JSON null. The store already copies tickets for reads and mutation responses, so the field will flow through creation, detail, list, edit and transition. Keep create and patch input allowlists and the creation audit fields as they are.
- Register `PUT /tickets/:id/assignee` using the existing router, body reader, actor reader and error envelope. Add a dedicated validator in `src/tickets/validate.js` and a synchronous assignment method in `TicketStore`. The store owns eligibility, comparison, the ticket change, audit, outbox enqueue and save.
- Use the store's audited-change path for timestamp and audit construction, and its outbox for notices. Add an assignment event template in `src/templates.js` for the existing worker and notifier. Keep requester events, scheduling, retry and delivery recording on their current paths.
- Extend the version 1 ticket record reader and writer in `src/persistence.js`. Default a legacy missing field to null and retain the recorded history and outbox. Both HTTP and the read-only CLI load through this path.
- Parse the optional assignee in `src/tickets/query.js` and intersect it with the other supplied filters in the shared matcher. The store already filters before sorting and paging. Expose the current assignee in the three CLI ticket formats in `src/format.js`. The CLI already uses the shared query parser for its current flags, and the weekly report can keep reading the existing raw columns by position.

## Decisions

The choices about open points below are proposed build defaults. The build report should record the choices actually made. Acceptance tests should enforce the clauses and allow other reasonable answers to their open points.

| Clauses | Choice and reason | Alternative considered |
| --- | --- | --- |
| C-5, C-15 | Return 200 with the full ticket for a change or eligible no-op. This follows patch and transition and lets the caller see the result immediately. | A bodyless 2xx would fit the clause and require a separate read to get the ticket. |
| C-6, C-46 | Normalize surrounding whitespace on input, preserve interior spaces and case, and require a nonblank single-line Unicode name. Reject the existing text validator's control range and Unicode line separators in the original value so tabs and line breaks cannot enter a row or recipient. Reject ill-formed Unicode so names can round-trip through URL queries. Count up to 40 Unicode code points in the trimmed name. Use the same name constraints on saved named values, and keep the existing text validators' behavior for other fields. | Literal whitespace and control characters complicate identity and CLI output. Case-folding can merge distinct names. The existing JavaScript string-length check counts a supplementary character twice. |
| C-10–C-14, C-24–C-25 | After JSON, field and actor validation, look up the ticket and use `isActive` before comparing normalized values. Use 409 for inactive same-value requests, including null. Use the store's empty-change path for eligible repeats. | Checking equality first could return success for inactive repeats. The clause allows that choice, and the state-first rule fits the existing mutation flow. |
| C-23, C-26–C-28 | Use an action and event type such as `ticket.assigned`, with the audit delta distinguishing clearing from assigning. Queue only named changes. Give an event a pending deduplication key derived from type, ticket ID and exact stored name. Coalesce an intervening return to the same recipient while their notice is pending. Set `to` to the stored name at the existing notifier boundary, with the ticket ID and assignment wording in the template. | A type-and-ticket key would suppress notices to different agents. A per-change key could queue every return to the same recipient. A separate address lookup needs a mapping the request does not supply. |
| C-32–C-33 | Keep version 1 and the single atomic file replacement. Put the field in the explicit record schema on both save and load. Default only a missing legacy field, accept explicit null, and report other invalid saved values through the data-file error path. | A new format version and separate migration would complicate startup for a field with a safe default. Reconstructing current ownership from audit or notification history would miss clears or confuse delivery status with ownership. |
| C-34–C-37 | Use the first query value, as for status and priority. A literal empty decoded value maps to null. Compare a nonempty decoded value to the exact stored spelling, leaving nonmatching text as a query with no matches. Keep omitted assignee absent from the filter object and continue ignoring undefined internal filter values. | Rejecting repeats or combining them adds a separate parser rule. Treating whitespace-only filter text as empty would select unassigned tickets unexpectedly. |
| C-38–C-42 | Show an `ASSIGNEE` column and an assignee detail field with a readable unassigned marker. Append the stored name or an empty fifth field in raw output. Keep the current CLI arguments and report reader. | Inserting the new column among the original four breaks positional readers. Adding an assignment command or an assignee CLI filter expands scope. |

## Nuances

- **U-1–U-3, C-3–C-14, C-22–C-25, C-46.** Request reading can yield while a transition proceeds. Check the current ticket inside the synchronous store method, with no yield between lookup, eligibility, comparison, audit, enqueue and save. Only `closed` is final, so the patch guard would mistakenly allow changes on resolved tickets. Validate JSON shape, the field allowlist and actor first. Explicit null is a clear and an omitted field is invalid. Reuse the byte-limited body reader, including its drain on oversized uploads. Valid requests for missing IDs use the store's normal 404 path.
- **U-1–U-3, C-13–C-25.** Creating the initial null must leave the creation audit shape intact. On a real change, capture the old value first and use one store clock reading for `updated`, the audit entry and any queued event. An eligible same-value request must exit before any timestamp, audit sequence, event ID or save changes. Patch and transition must preserve the assignee, including on resolution, closure and reopening. The resolved requester notice still goes to the requester. A failed validation, lookup or state check occurs before mutation.
- **U-4, C-26–C-31, C-43.** A Dana-to-Sam handoff while the worker is off must leave the Dana event independent and enqueue one addressed to Sam. Capture the recipient at enqueue time so later reassignment or clearing cannot redirect an earlier event. A clear adds no notice and leaves earlier notices on their existing delivery path. A missing template would silently look fine at enqueue and then fail every delivery attempt. Test the real notifier template and worker. Keep a delivery destination failure out of the request path. A recorded send stays sent, and a process interruption between sending and recording retains the service's existing possible repeat.
- **U-8, C-12–C-14, C-23, C-26, C-31–C-33.** Adding a field to an in-memory spread is insufficient because persistence explicitly picks fields. Apply legacy defaults at load and on direct store hydration from older snapshots so comparisons and audit deltas see null. Preserve sequence counters and event state, including attempts, next retry and sent/dead records. Save ticket, audit and outbox together before acknowledging success. The existing apply path mutates before save, so a thrown save must not leave a failed assignment live in memory for a later request, worker tick or shutdown save to publish. Scope rollback to assignment by retaining its pre-change ticket values and restorable audit/outbox state when persistence is configured, restoring them on a pre-commit error and rethrowing for the normal 500 envelope. Keep the existing rename as the commit point. An old executable can read version 1 but will strip unknown ticket fields on save and lacks the assignment template. A pre-upgrade file copy supports rollback to the earlier service with its earlier state, and retaining the upgraded file preserves assignments for a return to this version.
- **U-5, C-34–C-37.** The current matcher uses `some`, so adding an assignee check to that expression would broaden results and leave the pre-existing status-plus-priority bug. Require every provided condition, including null, before numeric ID sort and pagination. Leave cursor decoding, exclusive resume position and limit handling in their existing modules. An unfiltered or filtered page can have no matches. A cursor for an ID is a position even when that ID no longer matches. Full pages without skips or repeats are checked on a stable result set using the same filters.
- **U-6–U-7, C-38–C-42.** The raw output's first four fields are positional, and tabs or newlines in a name could split the field or add a report row. Verify actual raw lines, preserving the trailing tab for a blank fifth field. Use the current assignee field for details even if history shows a prior agent. Render the unassigned marker separately from names, for example by quoting a name that would otherwise display as the marker. CLI status and priority together now intersect through the shared matcher. Keep read-only loading and multi-page enumeration through the store.
- **U-9, C-1–C-2, C-43–C-45.** Existing tests assert the creation audit fields, default query shape, requester event keys and version number. Keep those fixtures and assertions intact. Use the existing CommonJS startup and built-in test runner. Keep the new tests in separate files and exercise normal CLI and API entry points.

## Build order

1. Establish the ticket field and legacy default in the store and persistence record schema. Check fresh creation, a handwritten version 1 fixture missing assignee and the existing create, audit and persistence tests.
2. Wire the dedicated body validator, `PUT` handler and synchronous store method. Reuse the audited change path, adding assignment-scoped failure recovery where needed. Wire the event key and template before exercising real delivery. Check both eligible states, no-ops, refusal effects, audit order, failed-save retry and pending notices.
3. Add query parsing and change the shared matcher to intersection. Check omitted, named and empty assignee, combined legacy filters and cursor boundaries. Add CLI outputs using the same stored ticket and verify the report against raw output.
4. Finish the new `node:test` coverage for the API, persistence, worker and CLI. Run targeted files as the pieces land, then `npm test` on Node 22 or later with no installation. Smoke-test `PORT=0 npm start` by using the port it reports. Track the Node server PID as well as the npm wrapper so the server can receive its shutdown signal and both can be reaped.
