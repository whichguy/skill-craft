Verdict: reject
## Findings
- The starting API lets operators edit a resolved ticket’s title or priority | The delivery applies the new assignment state restriction to the existing PATCH endpoint | Probe: On each version, create `T-0001`, transition it to `in_progress` and then `resolved`, and send `PATCH /tickets/T-0001` with `{"title":"Edited"}`. The starting API returned 200 and title `Edited`. The delivery returned 409 `conflict` with `ticket T-0001 is resolved and can no longer change`.
- The starting CLI lists tickets matching either of its two supplied filters. The request specifies the all-filters rule for `GET /tickets` | The delivery also applies the all-filters rule to the existing CLI flags | Probe: With `T-0001` and `T-0003` resolved and urgent and `T-0002` open and low, run `node bin/tickets.js --data FILE list --status open --priority urgent` on each version. The starting CLI listed all three IDs. The delivered CLI printed `no tickets` and exited 0.
- The CLI table must show who has each ticket, including which tickets are unassigned | The table displays the same `-` for the valid agent name `-` and for an unassigned ticket | Probe: Send `PUT /tickets/T-0002/assignee` with `{"assignee":"-"}`. It returned 200 and assignee `-`. Run `node bin/tickets.js --data FILE list` with `T-0001` still unassigned. Both rows showed `-` in the `ASSIGNEE` column.
- Agent names have a 64-character limit and the service validates saved records at startup | The loader accepts and exposes an assignee that the API considers invalid | Probe: In a temporary version-1 `DATA_FILE`, set `T-0001.assignee` to `'a'.repeat(65)` and start with `PORT=0`. `GET /tickets/T-0001` returned 200 with all 65 characters. A `PUT /tickets/T-0001/assignee` using that same name returned 400 `invalid` with `assignee must be at most 64 characters`.
## Decisions made for the requester
- Assignment trims surrounding whitespace, rejects names that are empty after trimming or contain remaining control characters, and counts UTF-16 code units | Store names verbatim or count Unicode code points.
- The assignee filter compares the supplied value verbatim and treats an unknown value as an empty result. A repeated parameter uses the first value | Apply assignment-name validation and normalization to filter values or reject duplicate parameters.
- Body validation runs before ticket lookup. The state check rejects a no-op assignment or unassignment on resolved and closed tickets with 409 | Look up the ticket before validating the body or let an inactive ticket’s no-op return 200.
- Notifications use the agent name as the recipient and preserve earlier pending events when the assignee changes. A return to the same agent while their earlier notification is pending reuses that event | Resolve names to addresses, cancel superseded events, or queue a separate event for each assignment change.
- Both assignment and unassignment use the audit action `ticket.assigned`. A ticket keeps its assignee through status transitions | Give unassignment a distinct audit action or clear the assignee on resolution or closure.
- The CLI table places `ASSIGNEE` before `REQUESTER`, and `list --raw` appends assignee as a fifth field with an empty value for an unassigned ticket. The weekly report returned identical counts on the same data | Place the table column elsewhere or retain the four-field raw output and show assignment only in the table.
