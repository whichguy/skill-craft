Verdict: reject
## Findings
- The starting API lets an operator edit the title or priority of a resolved ticket | The delivery blocks ordinary edits to resolved tickets as well as assignment changes | Probe: In each version, `POST /tickets` with `{"title":"VPN","requester":"pat@example.test","priority":"urgent"}`, then `POST /tickets/T-0001/transition` with `{"to":"in_progress"}` and then `{"to":"resolved"}`. `PATCH /tickets/T-0001` with `{"title":"VPN follow-up"}` returned 200 with the new title in the starting product and 409 `conflict` in the delivery.
- The starting CLI lists tickets matching either supplied flag when both `--status` and `--priority` are given | The delivery applies the new HTTP filter rule to the CLI too, dropping tickets that previously appeared | Probe: With T-0001 resolved/urgent, T-0002 open/normal, and T-0003 open/urgent, `node bin/tickets.js --data FILE list --status open --priority urgent` listed all three in the starting product and only T-0003 in the delivery. `GET /tickets?status=open&priority=urgent` correctly returned only T-0003 in the delivery.
- The CLI table should let the operator identify each ticket's assignee | The table displays the valid agent name `-` exactly like an unassigned ticket | Probe: With T-0003 unassigned, `PUT /tickets/T-0002/assignee` with `{"assignee":"-"}` returned 200 with `"assignee":"-"`. `node bin/tickets.js --data FILE list` displayed `-` in the ASSIGNEE column for both T-0002 and T-0003.
## Decisions made for the requester
- Assignment names are trimmed, checked for control characters, and limited to 64 UTF-16 code units | Preserve whitespace and count Unicode characters.
- The assignee filter compares names verbatim, accepts overlength values as queries, and uses the first value for a repeated parameter | Normalize or validate filter values and reject repeated parameters.
- The assignment endpoint checks the ticket state before recognizing a no-op, so even an already-unassigned resolved ticket returns 409 when sent null | Return 200 for an unchanged assignment regardless of state.
- The notifier uses the agent name as the recipient | Resolve the agent name to a separate delivery address.
- Pending assignment notifications stay queued after reassignment or unassignment, and another assignment to the same ticket and agent reuses any notification still pending for that pair | Withdraw superseded notices or queue a separate notice for each assignment.
- Assignment changes use the `ticket.assigned` audit action for assigning, reassigning, and unassigning | Use separate audit actions for assigning and unassigning.
- The table inserts ASSIGNEE before REQUESTER, and `list --raw` appends assignee as a fifth tab-separated field, empty when unassigned | Keep assignee in the table only and leave the raw output at four fields.
