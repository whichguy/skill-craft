The request adds an overdue query and preserves existing behavior. | Turning on due times also changes ordinary queries to require both filters, changing page membership and cursors. C-48 explicitly checks for this change. | Probe: Start both releases on copies of the same version-1 snapshot with T-0001 open low, T-0002 in_progress urgent, T-0003 open urgent, and T-0004 closed low. Prepare the new copy and start with DUE_TIMES=on. GET /tickets?status=open&priority=urgent returned 200 and T-0001, T-0002, T-0003 in 1.4.0 and 200 with only T-0003 in the delivery. Adding limit=1 gave a continuation in 1.4.0 and next=null in the delivery.
- The production data file must hold usable due times before activation, and a deadline calculated from creation plus response hours cannot predate that creation instant. | Preparation and enabled startup accept an earlier due for legacy timestamps with an explicit offset outside the ISO spelling they check. | Probe: In version-1 files set T-0001 created to either Mon, 01 Sep 2025 08:15:00 +0200 or 2025-09-01 08:15:00+02:00, both representing 06:15Z, and due to 2025-09-01T06:14:59.999Z. ## Decisions made for the requester
- Use four RESPONSE_HOURS_* environment variables read at startup, with whole hours and zero supported. | Use a single schedule file or allow fractional hours.
- Treat tickets created while the feature is off as legacy tickets and assign their first due during offline preparation using the saved priority and the preparation schedule. | Assign and persist a hidden due at creation while keeping the flag-off HTTP response unchanged.
- Use a separate offline npm preparation command and refuse enabled startup when a populated file is missing deadlines. | Backfill automatically during enabled startup before accepting requests.
- Store due in the existing version-1 ticket record and use a separate read-only recovery copy to restore assigned values after 1.4.0 strips them on save. | Keep deadline assignments in a separate persistent store that the old release never rewrites.
- Accept overdue=false as an ordinary listing, validate other enabled values as 400 invalid, and use the first value when the parameter repeats. | Recognize only overdue=true and ignore any other value.
- Show due in enabled CLI show output, keep the list table and four raw columns, and escape tabs and line breaks in historically stored titles. | Display deadlines in the table or extend the raw format, and preserve literal title delimiters in raw output.
- Use the selected TZ and Node's date parsing for offset-free historical records. With zero hours in America/Los_Angeles preparation used 08:30Z for the repeated 2025-11-02 01:30 and 10:30Z for the skipped 2025-03-09 02:30. | Require an explicit offset for repeated or skipped local times before assigning a deadline.
