Verdict: reject
## Findings
- The starting API lets operators edit a resolved ticket's title or priority with `PATCH /tickets/:id`. The new state restriction applies to assignment. | The delivered API blocks title and priority edits on resolved tickets. | Probe: On each service, create `T-0001` with title `VPN`, transition it to `in_progress` and then `resolved`, and send `PATCH /tickets/T-0001` with `{"title":"VPN follow-up"}`. The starting service returned `200` and a subsequent GET showed `VPN follow-up`. The delivery returned `409 conflict` and GET still showed `VPN`.
- The starting CLI lists tickets that match either flag when `--status` and `--priority` are supplied together. The request changes filter matching for `GET /tickets`. | The CLI now requires both flags to match and omits tickets it previously listed. | Probe: Run `node bin/tickets.js --data "$DATA_FILE" list --status open --priority urgent --raw` in each product on the same starting-product file containing resolved/urgent `T-0001`, open/normal `T-0002` and open/urgent `T-0003`. The starting CLI listed all three IDs. The delivered CLI listed only `T-0003`.
- The starting CLI documents and emits four tab-separated fields for `list --raw`, with the title last. | The delivery adds a fifth field even for unassigned legacy tickets, breaking readers that require four fields. The bundled weekly report still returns the same counts. | Probe: Capture `node bin/tickets.js --data "$DATA_FILE" list --raw` as `"$RAW"` in each product using the same starting-product file and run `awk -F '\t' 'NF != 4 { exit 1 }' "$RAW"`. The starting output ended its first row at `Edited after resolution` and the reader exited `0`. The delivered row added a trailing tab and the reader exited `1`.
- The CLI listing must identify each ticket's assignee. | The table uses `-` for both an unassigned ticket and a ticket assigned to the valid agent name `-`. | Probe: On the delivery, send `PUT /tickets/T-0002/assignee` with `{"assignee":"-"}`. It returned `200` with `assignee` equal to `-`. Leave `T-0003` unassigned and confirm GET returns `assignee: null`. Run `node bin/tickets.js --data "$DATA_FILE" list`; both rows show `-` under `ASSIGNEE`.
## Decisions made for the requester
- Assignment trims surrounding whitespace, rejects blank names and embedded ASCII controls, and counts up to 64 UTF-16 code units. | Preserve surrounding whitespace and count Unicode code points.
- The assignee filter compares the supplied value literally and returns an empty result for unmatched names, including values longer than the assignment limit. | Normalize and validate query values by the assignment rules.
- A valid assignment request on a resolved or closed ticket returns `409` even when it would leave the assignee unchanged. | Return `200` for a no-op before enforcing the state restriction.
- The notification uses the agent name as the outbox recipient. | Resolve the name to a separate delivery address.
- Earlier pending assignment notifications remain queued. Reassigning a ticket back to the same agent while that agent's notice is pending reuses the pending notice. | Withdraw superseded notices or queue a separate notice for every reassignment.
- Unassignment leaves the previous agent without a new notification. | Send the former assignee an unassignment notice.
- Assignment and unassignment both use the audit action `ticket.assigned`. | Give unassignment its own action.
- Resolve, close and reopen transitions preserve the assignee. | Clear the assignee on resolution or closure.
- The table places `ASSIGNEE` before `REQUESTER`, and `show ID` keeps its existing detail fields. | Place the column after `REQUESTER` and also add an assignee field to `show ID`.
