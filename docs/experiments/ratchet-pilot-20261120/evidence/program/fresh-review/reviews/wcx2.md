Verdict: reject
## Findings
- In 1.4.0, an ordinary ticket list with both status and priority returns tickets matching either filter. The request adds an overdue filter and preserves existing requests. | With due times enabled, ordinary lists require both filters, even when overdue is omitted or explicitly false. | Probe: Seed T-0001 open/normal, T-0002 in_progress/urgent and T-0003 open/urgent. GET /tickets?status=open&priority=urgent returned 200 and all three IDs on 1.4.0 and on the dark delivery. With DUE_TIMES=on, it returned 200 and only T-0003, both with the original query and with &overdue=false.
- With due times off, the service must answer exactly as 1.4.0 does. | The delivery refuses creates at the maximum safe ticket or outbox counter even with the feature off. The refusal keeps the saved file readable, but changes the dark HTTP behavior. | Probe: On separate valid empty version-1 snapshots, set either nextNumber or outbox.nextId to 9007199254740991 and leave the other at 1. With DUE_TIMES=off and WORKER_INTERVAL_MS=0, POST /tickets with a valid title, priority and requester returned 201 on 1.4.0 (T-9007199254740991 or T-0001 respectively) and advanced the affected counter to 9007199254740992. The delivery returned 500 internal on both snapshots and kept the counter unchanged.
- A ticket's due time comes from its creation instant plus its response hours. A deadline earlier than a valid, explicitly zoned creation instant cannot be an assigned promise. | Preparation, recovery and enabled startup accept an early deadline when the saved creation timestamp uses a legacy spelling, and the overdue list uses that deadline. | Probe: Put due 2025-09-01T06:14:59.999Z on an open ticket created at Mon, 01 Sep 2025 08:15:00 +0200 or 2025-09-01 08:15:00+02:00. Both parse to 06:15:00.000Z. DATA_FILE=fixture npm run prepare:due-times exited 0, and DUE_TIMES=on node src/server.js served GET /tickets?overdue=true with the ticket at 06:15:00.000Z. Using the RFC-style record as DUE_TIMES_RECOVERY_FILE also exited 0 and copied the early deadline. The ISO spelling 2025-09-01T08:15:00+02:00 was rejected with exit 2.
- The production snapshot must gain deadlines before activation, and 1.4.0 must see every ticket when rolled back onto the resulting file. | Running the documented preparation against an existing DATA_FILE symlink replaces the link with a separate prepared file and leaves the backing snapshot stale. The runbook gives no instruction to use the backing path consistently. | Probe: Create backing.json with one legacy ticket and run ln -s backing.json configured.json in the same directory. DATA_FILE=configured.json npm run prepare:due-times exited 0 and configured.json became a regular file. Enabled startup on backing.json exited 2 with T-0001 due missing. Enabled startup on configured.json accepted a second ticket with 201. Starting 1.4.0 on backing.json then listed only T-0001.
## Decisions made for the requester
- Read four independent RESPONSE_HOURS_* variables at enabled startup and at preparation, accepting whole elapsed hours including zero. | Use one configuration file or accept fractional hours.
- Store due as an optional field in the existing version-1 ticket record. | Save deadlines separately from the ticket snapshot.
- Assign old tickets through an explicit offline command and refuse enabled startup on an existing incomplete snapshot. | Backfill automatically at startup.
- Treat the exact overdue=true as a strict deadline comparison sampled once per page, treat false as no overdue filter, and use the first value if the parameter repeats. | Include tickets due at the evaluation instant, or reject repeated values.
- Recover promises from a separate pre-rollback snapshot matched by ticket ID and exact creation text. | Maintain a separate deadline store that survives 1.4.0 writes without an operator archive.
- Use Node's local-time parsing with the operator's TZ for offset-free legacy creation values. With zero hours in America/Los_Angeles, 2025-11-02T01:30:00 becomes 08:30Z and 2025-03-09T02:30:00 becomes 10:30Z. | Require an explicit offset for ambiguous or nonexistent local times before assigning a deadline.
- Display valid deadlines in enabled CLI show and escape tabs and line breaks in raw titles. | Add a deadline column to the raw listing or preserve literal delimiters in legacy titles.
