## Approach

Use a nullable `assignee` on the ticket record in `src/store.js` and `src/persistence.js`. New tickets and loaded version-1 tickets missing the field start with explicit null. The existing ticket reads and write responses return copies of this record, so the field flows through create, get, list, patch, transition, and assignment without a second response representation. Only the new assignment endpoint accepts an assignee in a request body.

Register `PUT /tickets/:id/assignee` using the existing router in `src/app.js`. Reuse the app body reader, field and actor validation, and JSON error handling. Pass the validated value to one synchronous store operation. Reuse the store's `apply` path for the change, its audit entry, its outbox effect, and its save. Add an assignment template for the existing worker and notifier. Add the query field in `src/tickets/query.js`, use the common matcher before cursor pagination, and add an assignee column to the CLI table in `src/format.js`. Keep the Node entry points, existing data-file format version, and dependency-free runtime.

## Decisions

| Clauses | Build choice and rationale | Alternative considered |
| --- | --- | --- |
| C-3, C-4 | Return 200 with the current ticket for success, including no-ops, following PATCH and transition. Contract checks accept any 2xx and check the field if a ticket is returned. | 204 would satisfy the acknowledgement requirement but would require a separate GET to see the result. |
| C-7–C-10, C-28, C-29 | For C-10's open point, follow the existing single-line name convention. Trim a name, require 1–64 JavaScript UTF-16 code units after trimming, apply the existing control-character check to the trimmed value, and require well-formed UTF-16 so a stored name can round-trip through URL query encoding. Preserve case and Unicode spelling. Expose one assignee-name validator in `src/tickets/validate.js`, built on the existing text rules, for PUT, query parsing and persistence. Validate persisted names as already canonical so loading preserves identity. Translate name validation failures on disk into the reader's record-specific data error. | Preserving surrounding whitespace or counting graphemes would depart from current field conventions. Loading by silently canonicalizing a saved name could change its identity relative to its audit and notices. |
| C-12, C-16, C-19 | For the closed same-value open point, check equality immediately after lookup and acknowledge the no-op before applying the final-state guard. Validate the body and actor even on this path. | Checking finality first follows PATCH's order and is also allowed, but here equality-first gives repeat PUTs the same acknowledgement even if the ticket closed in the meantime. |
| C-17, C-20–C-23 | Use `ticket.assigned` as the audit action for named ownership and `ticket.unassigned` for clearing it. Use `ticket.assigned` for notifications, with a key containing that type, ticket ID and the audit sequence of the change. For C-20's open point, queue a separate notice if the ticket returns to an earlier agent while their notice is pending. Each actual assignment has its own audit sequence, and delivery retries keep the same event ID and key. | A ticket-and-agent key could reuse a still-pending notice when ownership returns to that agent. The default ticket-and-type key also collides across different recipients and cannot satisfy C-20. |
| C-26–C-28 | Keep version 1 and use the existing synchronous whole-document save and rename. Treat a missing field as null on load and persist explicit null after clearing. For a thrown persistence failure, isolate the assignment's in-memory changes until the operation succeeds, using the existing record copies and constructors to stage state when persistence is enabled. | A version bump would require migration without a structural need. Direct mutation followed by an unguarded save can leave the failed operation visible and let a repeat acknowledge data that never reached disk. |
| C-29–C-33 | For C-29's open points, use the first `assignee` occurrence, following status and priority. Interpret the empty decoded value as null. Apply the name rules to non-empty values (invalid values get 400) and match the resulting name exactly. | Rejecting duplicate query keys would differ from existing parsing. Case folding or Unicode normalization would introduce aliasing among independently supplied names. Treating invalid non-empty values as no matches would conceal malformed input. |
| C-34–C-36 | For C-34's open point, show assignees only in the table. Use an `ASSIGNEE` column, with quoted string names and the bare label `unassigned`. This keeps the label distinguishable even if an agent is named “unassigned”. | A fifth raw column after title would preserve the specified positions, but retaining the four-field raw format gives existing readers the greatest compatibility. |

These are build choices. Record the five open-point answers in the build report. Contract tests for those points should cover the observations in the clauses and accept either reasonable behavior where the requester left a choice.

## Nuances

- **C-4–C-6, C-17, C-39, C-40.** Populate the field at creation and at the loaded-state boundary. A response-only default would leave `undefined` in matching and audit diffs. Keep POST and PATCH field allowlists and transition rules. Keep `CREATED_FIELDS` as it is because the initial null represents absence of an assignment and the existing creation audit shape is tested. Subsequent title, priority or status updates should reuse the record and preserve its assignee, including on close and reopen.
- **C-7–C-14, C-18.** Use the shared `readJson` for the exact byte limit and drain behavior. Use `onlyFields` and require the own `assignee` property. Branch on strict null before name validation. Call `actorOf` before entering the store even if the ticket would be unchanged. Look up the ticket through `find` with the decoded ID, so a well-formed request for a missing record gets the normal 404. Then compare the validated value and use `isFinal` for actual changes, as resolved tickets are eligible. Keep the app's normal error envelope, including its handling of malformed path encoding. Body and actor validation precede lookup as in the existing write routes.
- **C-5, C-15–C-19, C-21, C-22.** Compare equality and update inside the same synchronous store call. Independent requests can overlap while their bodies are read, but the read of the current assignee, decision, audit and save run without a yield. For a real change, send only the assignee delta to `apply` and use its single change timestamp for `updated`, audit and enqueue time. Let `AuditLog.append` allocate the next global sequence and pass the returned entry alongside `at` to the existing effects callback, whose existing caller only needs `at`. A no-op exits before clock use, append, enqueue or save. Clearing still audits and saves the null, with no enqueue. A stale retry after an intervening transfer is a valid change back to the requested agent.
- **C-20–C-24, C-39.** Capture the incoming name and ticket identity in each event via `TicketStore.notify`; the existing helper also captures the title as of the change. A later transfer or clear should leave existing notices in their normal delivery flow, including retries. Rendering from current assignee would misaddress an earlier notice. Add a template that identifies the ticket and tells the recipient it was assigned to them. Keep requester create/resolve events on their current types, keys, templates and recipients. Worker off means notices stay pending. On delivery failure the worker keeps its current backoff and dead-letter behavior. A crash between relay append and recording delivery has the existing at-least-once semantics with stable event identity.
- **C-14, C-25–C-28, U-6.** Add the field to the explicit ticket projection and handle missing versus invalid in `readTicket`. Use the reader's record-specific error for explicit invalid values. Normalize missing assignees in the store's supplied-state constructor as well, so direct state and the CLI construction path use the same invariant. Keep existing audit, IDs, and outbox events intact without synthetic assignment changes during load. For a real assignment with persistence, save the original ticket, audit and outbox references, prepare all three copies before installing them, then call the shared synchronous `apply`. Keep the copies on success. Restore the original references on any throw before commit, preserving both sequence counters and the previous ticket. The synchronous path hides the staged references from other HTTP requests and worker ticks. Without persistence, reuse the ordinary in-memory `apply` path. Keep rename as the commit point and send success only after it returns. A process interrupted before rename can leave an ignored temp file, and one interrupted after rename loads the whole new ticket, audit and notice. The rollback direction guaranteed by this feature is that the new service can load old files. An older executable's ticket projection drops the new field on save and its worker lacks the new template, so a deployment rollback needs a compatible executable or a pre-upgrade backup with its corresponding data cutoff.
- **C-29–C-33, C-36, C-39.** Preserve the difference among a missing parameter, a present empty parameter and a non-empty value. In `matchesFilters`, require every supplied predicate and retain the existing convention of ignoring undefined filter values; null is a real predicate. The current matcher uses `some` even though the API documents intersection. Fix it for status and priority alone as well as when assignee is present. The CLI shares this matcher, so combined flags also intersect. Keep numeric ID sort and apply filters before paging. The cursor is a lower bound by ID, even when its anchor ticket is no longer in the matching set. Keep existing query handling for limits, cursor and unrelated parameters.
- **C-34–C-39.** Apply the display choice in the table column definitions. The CLI loads the same data file reader without write access and already walks every page internally. Keep positional raw rendering and weekly report parsing as they are. Verify the new column does not mix up the stored assignee with the requester, split rows, or affect `show`, the empty-list message or CLI exit codes.

## Build order

1. Establish name validation and the ticket invariant at creation and load, including explicit ticket-record serialization. Verify the existing creation audit and an old-file read while the only possible new assignee value is null.
2. Add the store assignment operation, its scoped persistence failure handling and the effect callback's audit entry argument. Add the notification template and verify ticket, audit and outbox together with a manual clock. Exercise a save failure and retry while the worker is off.
3. Add the route with the existing request and actor pipeline. Verify all result paths through HTTP, including rejected requests with no side effects and overlapping identical PUTs.
4. Add intersection filtering and assignee query parsing. Test cursor continuation across an interleaved queue before adding the CLI table column. Exercise normal and raw CLI listings and the weekly report over saved data.
5. Complete delivery, retry and restart checks and run `npm test` against unchanged original tests and new `test/*.test.js` files. Smoke-test `npm start` and `/health` on a free port. Record the open-point choices in the build report.
