## Approach

- Add a dedicated `PUT /tickets/:id/assignee` handler in `src/app.js`. It uses the existing router, bounded JSON body reader, assignment-specific validation in `src/tickets/validate.js`, and `actorOf`. It calls one synchronous `TicketStore` operation in `src/store.js`. Reuse the shared error envelope. Keep the create and patch input allowlists.
- Put `assignee` on the ticket record so the store's usual copies expose it in every API response. Initialize new tickets to `null` and default missing values in constructor-supplied legacy state and the version 1 persistence reader. Update the ticket projection in `src/persistence.js` in both directions. Use the existing whole-state save after the assignment, audit entry, and any outbox event have all been applied.
- Use `isActive` for assignment eligibility and `TicketStore.apply` for actual changes. Record `changes.assignee` through the shared audit log and queue any named recipient through `TicketStore.notify`. Add the corresponding template in `src/templates.js`. The worker and notifier already handle delivery, retries, relay output and the admin view.
- Extend `parseListQuery` in `src/tickets/query.js` to represent an omitted assignee with an absent filter, an empty parameter with a `null` filter, and a named value with a string. Select all-match semantics explicitly at the HTTP route and reuse the store's existing filter/sort/page pipeline. Keep the direct store and CLI default of matching any supplied filter. Add an assignee column in `src/format.js` for the CLI table. The CLI already reads through the shared data-file loader.

## Decisions

The choices below resolve implementation questions for this build. Where an `Open:` line applies, the choice is provisional. The builder records the choices taken in its report, and acceptance checks use the clause as written so other reasonable answers also pass.

| Clause | Build choice and reason | Alternative considered |
| --- | --- | --- |
| C-3 | Return HTTP 200 with the current ticket for each accepted request, including a no-op. This follows PATCH and transition and gives callers the usual representation. | Use 204 and require a separate read. |
| C-4 | Check active state before no-op detection. A blocked ticket returns 409 even for its current value, following state-first checking on PATCH. | Accept blocked-state no-ops because they would have no effects. |
| C-9, C-14, C-32 | Store the exact case-sensitive string, including surrounding spaces. Reject whitespace-only names, control or line-separator characters, and lone UTF-16 surrogates. An accepted name needs to round-trip through URL encoding as well as JSON. Use a cap of 200 UTF-16 code units, matching the existing title scale for human-readable text and keeping encoded names practical in URLs. Match exact decoded strings in the query and use the first value for repeated parameters, as for existing query fields. | Trim or fold case, or treat the repeats as a union. Both would introduce distinct identity or query rules. An unbounded name could fit the body but exceed the HTTP request-target budget when encoded for filtering. |
| C-17, C-23, C-24, C-26 | Use `ticket.assigned` as the assignment-change audit action for assign, replace and clear. Use `ticket.assigned` for named-recipient outbox events only. Queue one event per genuine named change, including a return to the same agent after a different value. Give it a key derived from its type, ticket ID and newly appended audit sequence. Put the name in the existing `to` field and use a template that identifies the ticket and says it was assigned to the recipient. This identifies individual changes across restart and keeps the existing relay contract. | Key by ticket alone, which conflates pending notices for distinct recipients. A recipient-specific key would distinguish Dana and Lee and could coalesce a later return to Dana. No agent directory exists to map names to external addresses. |
| C-21 | Preserve the assignee through every legal lifecycle move. Transition continues to change status only, with its existing requester notice on resolution. The last assignee stays visible when a ticket is resolved, closed or reopened. | Automatically clear or restore an assignee at a lifecycle boundary, which would require additional audit and notification rules. |
| C-29–C-31 | Use an additive record field in version 1, with `null` for an absent legacy field. Validate a present saved value against the chosen name rules. Reuse the synchronous data-file replacement. For this new mutation, restore the prior in-memory ticket, audit and outbox if applying effects or saving throws before commit. This keeps an identical retry from treating a failed save as a successful no-op. | Version bump with migration, or a separate assignment file. The record can load old files directly and one document keeps all effects in the same commit. |
| C-35, C-40 | Pass an explicit all-match option from HTTP through `TicketStore.list` to the existing matcher. Preserve its any-match default and its treatment of undefined criteria for current callers. This shares validation and pagination. | Flip the shared matcher globally, which changes the CLI's two-option selection, or duplicate the listing pipeline. |
| C-38–C-40 | Add an `ASSIGNEE` column before `TITLE`, display `(unassigned)` for null and JSON-quote named values to distinguish a literal agent named `(unassigned)` and show surrounding spaces. Keep raw output at its four established columns. Keep the existing `show` fields, with assignment changes appearing in its history through the existing formatter. | Add raw or detail fields now. Both are open, and the table satisfies the requested listing. |

## Nuances

- **C-4–C-11, C-13, C-18–C-19.** Missing `assignee` and explicit `null` have different meanings. After `readJson` requires an object, use the assignment-only field allowlist and check that `assignee` is an own field. Validate it and the actor before calling the store, including requests that would be no-ops. Let the store look up the ID and reject a blocked state before writing. Keep the existing body limit inclusive in UTF-8 bytes, with the shared reader draining oversized requests before sending a JSON error.
- **C-12, C-14–C-20, U-6.** Setting the value before computing its audit diff loses the old value. Build the diff from the stored ticket and call `apply` once. On exact equality return a copy before reading the clock, appending audit, enqueuing or saving. On change use the single timestamp from `apply` for the ticket, audit and event creation. Keep `CREATED_FIELDS` intact so existing creation audit entries and tests keep their payload. Creation initializes to unassigned and has no assignment diff.
- **C-4, C-21–C-22.** A state check before awaiting the body, or an async gap between state check and save, permits an assignment to use stale state. Finish the request reads first, then do find, eligibility, equality, mutation, audit, notification and save synchronously inside the store. The worker also ticks synchronously in the same process. A race with resolution is accounted for by audit sequence, which orders changes even when timestamps tie. Use the existing transition table throughout.
- **C-23–C-28, U-3.** The default outbox key deduplicates by pending key irrespective of recipient. Pass the assignment-specific key explicitly. Capture the recipient and title when the change occurs so a later reassignment, clearing or title patch cannot rewrite an already recorded notice. A clear adds audit only. An exact repeat adds neither audit nor an event even after delivery. Leave the existing create and resolve keys and requester payloads alone. An absent template causes repeated delivery failures, so exercise the rendered relay line as well as the pending admin record. Keep the worker's existing at-least-once handoff; stable event IDs and keys let the relay identify redelivery.
- **C-29–C-31, U-7.** The persistence writer projects a fixed field list. Adding the field to the store alone loses it at restart. In the loader distinguish a missing field from a malformed present one, and accept explicit null. Reuse the chosen name predicate for saved names without reformatting them or applying the HTTP body limit to the file. Preserve audit/outbox records and counters on load. Capture the pre-change assignment and updated time, plus the audit and outbox snapshots for the persisted assignment path that uses `apply`. If that path throws before the replacement commits, restore the ticket fields and rebuild the audit and outbox from their snapshots, including the next event ID, then propagate the error. Keep the successful path to one save. A kill during a write can leave an orphan temporary file, which startup should continue to ignore. This covers process interruption with one writer. An old binary's fixed field projection would discard the new field on save, and it lacks the new notice template. Going back to it against a live upgraded file is unsafe. Preserve a pre-upgrade backup and use the new binary to recover a current file.
- **C-32–C-37, C-40, U-4.** Checking truthiness discards the null criterion. Use parameter presence, map only a literal decoded empty value to null, and rely on `URLSearchParams` for decoding (including `%2B` for a literal plus). Apply every HTTP criterion to the current ticket before paging, then use the existing numeric ID comparator and cursor codec. A later ticket that fails the filters cannot produce `next`, even after a full page. A ticket that changed between page requests is evaluated against its current fields. The cursor still means IDs after the previous page's last returned ID. Preserve the CLI's disjunction through every page it reads, and preserve existing validation of status, priority, limit and cursor.
- **C-38–C-40, U-5.** Display the full single-line name in the table so names containing spaces stay associated with a ticket. A plain placeholder can also be a valid name, so render named cells in quotes and the null marker without quotes. Use the common loader for old and new files and keep list read-only. Raw output also feeds the weekly report, so preserve the first four columns and one row per ticket.
- **C-41–C-44, U-8.** Existing helpers start on port 0 and expose a manual clock and a PUT client. Use new `node:test` files with isolated temp data and relay paths, and clean up servers and spawned processes even when assertions fail. Use a bounded wait for the real worker smoke case and manual ticks and clock advances for retry boundaries.

## Build order

1. Add the name rule and the canonical field on new and loaded tickets, including the persistence projection. Check the original creation audit shape, old-file loading, and round-trip record representation.
2. Add the assignment store mutation with eligibility, no-op, audit, notification enqueue and whole-state commit. Check store outcomes with the manual clock and worker off, including a failing save and a retry. Add the worker template and check a relay delivery and its attempt state.
3. Wire the PUT route using the existing body and actor plumbing. Check success, invalid body, missing ID, blocked states and representation consistency over HTTP.
4. Extend query parsing and select conjunctive matching for the HTTP route. Check mixed criteria and cursor boundaries. Add the CLI table column and verify the existing CLI selection, raw fields and weekly-report counts against the same file.
5. Complete the new integrated `node:test` coverage, run it with the existing suite via `npm test`, then smoke-test the documented `npm start` entry point with a free port. Record the choices made for every open point in the build report.
