## Approach

Build this in one pass through the existing HTTP, store, worker and file paths. Represent assignment as a single nullable `assignee` field on the ticket. Initialize it on creation and normalize legacy records on read so the API, queries and CLI all use the same representation. Keep the ticket, audit trail and outbox in the same version 1 snapshot.

Register `PUT /tickets/:id/assignee` in `src/app.js` with `Router.put`, the configured JSON body reader, a dedicated validator in `src/tickets/validate.js` and `actorOf`. Call one synchronous store operation to check eligibility, identify a no-op, and apply the change using the existing audit, outbox and persistence path. Add an assignment notification template in `src/templates.js` and use the existing worker and notifier.

Extend `parseListQuery` and `matchesFilters` in `src/tickets/query.js`, then reuse `TicketStore.list` and the existing cursor logic. Add a column to the human table in `src/format.js`. The CLI loads tickets through the shared persistence reader and store, and the weekly report continues to consume the same tab-separated columns. Keep the existing Node.js entry points, configuration and test discovery (C-1, C-2, C-35–C-37).

## Decisions

The choices below for `Open:` points are proposed build defaults. The builder records the answers actually used in its report. Shared acceptance checks target the clauses and allow other reasonable answers to those points.

| Clause | Build choice and reason | Alternative considered |
| --- | --- | --- |
| C-3, C-26, C-27 | Use a shared assignee-name check across write input, nonempty query input and saved records. Trim surrounding whitespace, reject a name that becomes empty, reject control characters and line separators in the canonical name, and limit it to 64 UTF-16 code units, following the existing requester field's size. Reject unpaired UTF-16 surrogates so every accepted identity can round-trip through URL encoding. Preserve case, Unicode spelling and internal spaces. Require saved strings to already be canonical and report bad records by field. | Verbatim whitespace makes names difficult to distinguish in the CLI. Case folding or Unicode normalization can merge distinct names without an agent directory. Using the body limit alone can admit names too long to look up comfortably in an HTTP URL or show in a table. |
| C-5, C-12 | Return HTTP 200 with the current ticket on a change or a no-op, following PATCH and transition. | A JSON acknowledgment would work but would require a second read to obtain the same result. |
| C-6, C-14, C-16, C-17 | Use `isActive`, then compare the canonical requested value with the current value. An effective change uses one audit action such as `ticket.assignee_changed`, with only `assignee` in the delta. Use the existing apply path for the timestamp, audit and notification ordering. | `isFinal` would let resolved tickets through. A generic PATCH would inherit the wrong state rules and alter the established input contract. |
| C-19–C-23 | Use the canonical agent name directly as the destination in `to`, since the service has no agent directory. Call the notice type `ticket.assigned`. Supply a namespaced key containing the ticket ID and agent, encoded as an unambiguous tuple. If Dana's equivalent notice is still pending when a ticket returns to Dana, let the existing outbox coalesce that notice. A new assignment to Dana after the earlier notice is sent gets a new event ID. | A ticket-only key suppresses Sam's notice while Dana's is pending. A fresh key for every change would also meet the open point, while the recipient-specific key follows the existing pending-deduplication convention. Inferring an email address could misdirect delivery. |
| C-24–C-26, C-38 | Extend the version 1 ticket record in both directions. Use the existing synchronous temp-write and rename for the durable commit. | C-27–C-31 | Use the first repeated `assignee` value as existing query keys do. ## Nuances

- **C-6–C-11, C-18.** Follow the existing handler order: decode the route, read the size-limited JSON object, validate its sole field and actor, then look up the ticket and check state. A strict own-field/value check keeps missing, empty, wrong-type and extra-field bodies distinct from explicit `null`. Do not copy a parsed body wholesale onto a ticket. The shared reader counts bytes across chunks and drains oversized input so a client receives the JSON error. A malformed request can fail before lookup; the 404 and 409 cases are specified for well-formed requests. Check actor length after trimming even when the store would return early. Route all failures through the existing envelope and log internal details only on the server.
- **C-6, C-13–C-18, U-1, U-6.** Check status before comparing values, including same-agent PUTs and null-on-null when resolved or closed. Keep lookup, equality, timestamp, mutation, audit, enqueue and save in one synchronous store call after the body has been read. Two overlapping requests for the same agent then observe the committed result in succession in the single owning process. Effective changes use one clock reading for `updated`, audit and enqueue timing. A repeat returns a copy before reading the clock or saving. Audit sequence is global and prior entries remain immutable. Only effective assignment changes add an assignee delta; keep the existing creation audit fields and status/patch deltas intact. Create and PATCH still reject assignee in their inputs. Resolution, closure and reopening preserve the agent, and a reopened ticket can be assigned again.
- **C-11, C-25, C-38, U-7.** `TicketStore.apply` mutates live state before calling `save`. For an effective assignment backed by persistence, take the checkpoint before applying and restore the prior map/log/outbox state if the change fails before publication. Reconstitute the log and outbox through their existing constructors so freezing, sequence and event IDs resume correctly. Keep the atomic file replace as the last fallible commit step and return success only after it. If a response is lost after commit, a retry sees the already committed assignment and becomes a no-op. Check the saved file before graceful shutdown in restart tests because `stop()` saves and could conceal a missing request-time write. An abandoned temporary file is never the load source.
- **C-19–C-25, U-2.** Enqueue only when the new value is a name. Snapshot the recipient, ticket ID and template data when the change happens. Never re-read the ticket's current assignee at delivery time or cancel an earlier notice on reassignment, unassignment or resolution. Keep creation and resolution to the requester with their existing keys and templates, even when requester and assignee share a name. Reuse scheduling, retries, attempt counts and the sent/dead transition. An undeliverable notice leaves the assignment intact. On restart a pending notice keeps its event ID, destination and due time; a send interrupted before the sent state is recorded can recur with that same event ID and key.
- **C-12, C-24–C-26, C-28, C-34.** `ticketRecord` is a whitelist used to serialize and deserialize. Add the field on both paths. Default only a missing legacy field on load, accept explicit null, and validate an explicit value before any default could mask it. If a store is constructed directly from legacy state, give missing assignees the same default on hydration. No new audit or notice results from loading, and CLI reads leave the original bytes intact. For an application downgrade, the old binary can read version 1 but drops the unknown ticket field on its next write and cannot deliver the new pending notice type. Keep a backup of the upgraded data before rollback and pair the old binary with a pre-upgrade snapshot if rolling back both. This does not preserve changes made after that snapshot in the rolled-back service.
- **C-27–C-31, C-35, U-3.** The current matcher uses `.some`, so status plus priority currently admits tickets matching either. Fix the shared matcher to use `.every` after removing only undefined values. This also fixes combined CLI status and priority filters. Keep unrelated query keys ignored and existing status, priority, limit and cursor parsing. Assignment filters can select any status, and null matching happens against already normalized records. Use the decoded value from `URLSearchParams` once. For example, a literal plus in an accepted name must be represented by `%2B` in the URL. Filter first, sort IDs numerically, then page over matches using the ID of the last returned match. Keep the cursor opaque and reuse it with the same filters; this is a live listing, so assignment changes can affect subsequent pages.
- **C-32–C-35, U-4, U-5.** Apply the table column only in the formatted listing and keep the existing empty output. `allTickets` walks pages, so table and raw output must still include later pages. Raw has one line per ticket in the existing order. The weekly report spawns the raw CLI and reads status and priority by position. Preserve the show command's existing retrieval, history and exit behavior, including newly added history entries.

## Build order

1. Establish a nullable assignment in new and loaded ticket records. Add the shared name check, update both persistence record directions, and check create/get defaults, legacy load, bad saved types and version 1 round trips.
2. Add the store mutation, audit entry, assignment notice key and template. Check state-before-no-op, global audit ordering, effective timestamps, save failure recovery and recipient-specific pending delivery through the existing worker.
3. Wire the PUT route through the standard parser, validator, actor and error envelope. Check the route end to end, including body limits and a concurrent repeat. Extend the shared query parser and matcher, and check the filter combinations against real cursor pages.
4. Add the human table column. Exercise real data-file reads, legacy input, raw output and the weekly report. Document the new route, field, filter and notification behavior in the existing API and operations documentation.
5. Add and run the assignment `node:test` coverage alongside the unchanged suite. Use the existing service helper and manual clock, temporary fixtures and port 0. Verify real persistence and delivery at least once via the normal service paths, and record the open-point choices in the build report.
