## Approach

Add `PUT /tickets/:id/assignee` to `src/app.js` using the existing `Router.put`, configured JSON reader, error envelope and actor parser. Give the route its own validator in `src/tickets/validate.js` and a dedicated synchronous method on `TicketStore`. Store the assignee as a string or null on the ticket itself. The store initializes it, owns its mutation and returns it through the existing ticket copies. Use the existing audit, outbox and whole-state save for the three effects of an assignment.

Keep version 1 of the data file. Extend the ticket record in `src/persistence.js` to round-trip the new field and default old records on load. Reuse this path when the read-only CLI opens the file. Extend the list query and shared predicate before the existing numeric-ID cursor pagination. Extend the CLI table and raw formatter, and let the weekly report continue consuming its existing columns. Add an assignment template in `src/templates.js` and deliver it through the existing worker and notifier. Describe the new route, field, query, notice and CLI columns in the relevant API and README sections. Keep the existing startup and test entry points and use only Node's standard library.

## Decisions

The following choices for `Open:` points are proposed build defaults. Record the choices actually taken in the build report. Acceptance tests must allow other reasonable answers to those points.

| Clause | Choice and reason | Alternative considered |
| --- | --- | --- |
| C-1 | Return 200 with the current ticket for both effective changes and successful no-ops, matching PATCH and letting clients immediately read the representation. | 204 would require a separate GET for the current ticket. |
| C-3 | Check for a closed ticket before comparing assignees, consistent with PATCH's closed-ticket guard. A valid unchanged PUT on a closed ticket receives 409 with no effects. | Comparing first would allow a closed-ticket no-op to succeed. |
| C-4 | Follow the existing single-line text convention. Trim surrounding whitespace, count JavaScript UTF-16 code units after trimming, reject whitespace-only values and remaining control characters, and preserve case and internal spaces. Reject Unicode line and paragraph separators and unpaired surrogates so accepted names work as single-line fields and can round-trip through URL search params. Apply the same name rules to requests, search and saved records. | Grapheme counting or case and Unicode folding would introduce identity rules absent elsewhere in the service. Allowing row delimiters would need an escaping contract in raw output. |
| C-15 | Use `ticket.assigned` as the new event type and use a key scoped to type, ticket ID and normalized recipient. A fresh assignment back to the same recipient can share their pending notice. After it is sent or dead, the same key can enqueue a new event with a fresh ID. This uses the existing deduplication rule without suppressing notices to a different agent. | A key per audit entry would queue a separate notice on every effective return to the same agent. The default type-plus-ticket key would incorrectly suppress Sam while Dana is pending. |
| C-24 | Reject an invalid nonempty query value as 400 `invalid`, matching status and priority validation. Resolve the literal empty decoded value to null before applying name validation. | An empty page would conflate an invalid name and a valid name without matches. |
| C-26 | Take the first occurrence of `assignee`, using the existing `URLSearchParams.get` convention. This also handles an empty first value. | Rejecting duplicates would treat the new filter differently from the existing ones. |
| C-28 | Use an `ASSIGNEE` table column with `(unassigned)` for null and a quoted name for an assigned row. Quoting distinguishes a real agent named `(unassigned)` from the null marker. | Bare names with the same marker would make those two rows look identical. |
| C-29 | Append a fifth tab-separated field with the name or an empty field for null. The chosen name rules exclude embedded row and column delimiters, so this field needs no delimiter escaping. | A nonempty sentinel could collide with a name. Moving the first four fields would break positional consumers. |

Use `ticket.assigned` for an effective assignment or reassignment audit action and `ticket.unassigned` for an effective clear. The distinct actions make the log readable while the `changes.assignee` pair remains the source of before/after values. Leave the existing creation audit field set intact. Use the shared list predicate for intersection, including for the CLI's existing status and priority flags, so both consumers implement the documented matching rule. Keep CLI argument parsing as it is since the request adds a display field.

## Nuances

- **C-4–C-9, C-14.** A missing property and an explicit null have opposite meanings. Require the own `assignee` property, allow only that field and validate its value before touching the store. Read the body through the existing stream reader, which counts bytes including JSON whitespace, allows equality at the limit and drains an oversized body. Validate the existing `X-Actor` independently of the assignee. Finish these checks before lookup and state checks, as PATCH does. Let the existing router decode IDs and the store handle missing IDs. Exercise malformed requests separately from valid requests to missing and closed tickets so one check does not mask another.
- **C-1–C-3, C-8–C-14, C-23.** The existing `isActive` excludes resolved tickets. Use the final-state guard instead. Perform lookup, guard, comparison, change construction, timestamp, audit, enqueue and save in one synchronous store call after the body has been read. Comparing a stale ticket before an `await` could duplicate an equal assignment or record a false `from` value. For changeable tickets, equality of normalized values, including null, exits before acquiring a timestamp or saving. For an effective change pass only `changes.assignee` to the existing `apply` path. Its injected clock supplies both `updated` and audit `at`, and the audit log supplies the global sequence. Preserve `CREATED_FIELDS`. The unchanged store test compares the full creation entry, and null initialization creates no ownership change. Create/get/list/PATCH/transition all return the store's copies, so initialize the field at creation and load rather than patching one HTTP response. Keep POST and PATCH allowlists.
- **C-15–C-18, C-20, C-23.** Queue the assignment notice within the mutation, capturing the recipient and ticket ID at that time. Rendering from the current assignee at delivery could tell the wrong person after reassignment or clearing. Send assignment notices only for an effective move to a name. Leave existing events in place so a queued Dana notice can still be delivered after Sam takes over, or after a clear. Use the shared outbox, worker and JSONL notifier, including their retry, attempt count, dead-letter and restart behavior. Preserve existing requester event types, templates and keys. A notice may already be sent by the time an enabled worker is observed, so pause it for enqueue and state assertions. Test attempts with a manual clock and real JSONL delivery with the worker enabled.
- **C-19, C-20, C-23.** Save the ticket, audit entry and enqueued notice in one complete document using the existing synchronous temporary-file/rename path. Separate saves introduce a crash window that can leave an assignee without the corresponding audit or notice. A successful response must follow the rename. For a synchronous assignment save failure, the current `apply` mutates memory first. Guard the effective persisted assignment with an in-memory checkpoint of the old ticket, audit and outbox (including the next event ID). If the apply/save throws before commit, restore those pieces and rethrow through the existing internal-error path. This keeps a retry from taking the no-op branch on state that was never saved. Scope this protection to assignment. No checkpoint or write is needed for invalid/refused requests or no-ops. After an interruption following delivery but before the delivery state is saved, the same event ID and key may be delivered again under the service's existing at-least-once contract.
- **C-4, C-12, C-19–C-22, U-5, U-6.** Adding a property to the store alone loses it because persistence enumerates the known fields. Check field presence on the original record before projecting it. Default an absent field to null, accept explicit null, validate any other value through the shared name rule, and surface failures as `DataFileError` with the path and `tickets[i].assignee`. Expose a null default for legacy state given directly to the store as well. Loading old state must leave old audit, notifications, counters and timestamps alone. Old binaries can read the v1 structure but drop the unknown ticket field on save and lack the new notice template. A rollback that needs to restore pre-upgrade data should use a pre-upgrade backup. Forward reading of legacy files is the compatibility requirement here.
- **C-24–C-27.** Distinguish absence, literal decoded empty string and a name. Omission leaves the filter key absent, empty produces a `null` comparison, and names pass through the shared validation. Drop only undefined filter values and use `every` for the rest. The current `some` admits tickets that match only one filter, including existing status+priority requests. Filter the full collection before the existing numeric ID sort and cursor paging. Keep the existing cursor format and interpret `after` as an ID boundary even if that particular ticket now falls out of the filter. `next` requires a further match, including after an exactly full final page.
- **C-28–C-30.** The CLI reads through persistence and walks all store pages. A display change in the HTTP route would never reach it. Extend the table and raw formatters, preserve empty-table output and keep raw rows separated by exactly their existing newline structure. A null raw field needs a trailing tab, so tests should split records without globally trimming whitespace. A tab or newline in a name would shift fields or inflate the weekly total. The chosen rules remove outer whitespace and reject remaining delimiters. The report counts rows and reads positional fields, so exercise the actual report against both assigned and unassigned data.

## Build order

1. Add the shared assignee name and body validation. Wire saved-record normalization and diagnostics, and initialize new tickets to null. Check legacy and invalid records, the new-ticket representation and the unchanged creation audit.
2. Add the route and the synchronous store change. Wire audit, outbox key and template together with the single save. Check PUT validation, closed and missing ticket behavior, no-ops, concurrent writes, and pending and delivered notices through the existing interfaces.
3. Extend list parsing and switch the shared matcher to conjunction. Check strict filter combinations, empty and omitted selectors, and existing cursor behavior across interspersed matches.
4. Extend table and raw output, then check both CLI data-file selection paths and the weekly report. Update the API and README contracts to match the implemented choices.
5. Add or finish new `node:test` files under `test/` against the service's normal entry points. Use the existing helpers and free ports, temporary fixtures and cleanup. Run the targeted tests and then `npm test` with the original tests as written. Verify documented startup via `npm start` on a free port and stop only the processes started for that check.
