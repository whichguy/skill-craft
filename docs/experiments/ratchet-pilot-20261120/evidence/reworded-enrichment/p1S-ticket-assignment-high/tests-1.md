## Discoveries
- A name is checked for control characters before it is trimmed, so `"dana\n"` is refused whether or not surrounding spaces are trimmed | Observable: `PUT` with `{"assignee": "dana\n"}` or `"\tdana"` answers 400 `invalid` | Why: C-3's open point (trimming) and C-5 interact; the build trims first and so accepts `"dana\n"` as `dana`. The tests read C-5 literally (a name containing a control character is refused), which holds under either answer to the trimming question.
- A repeat of the current agent enqueues no notification, even when the first notification was already sent | Observable: assign `dana`, wait until her event is `sent`, send the same `PUT` again: no new outbox event | Why: with the worker off, the pending-key dedup (decision 6) would hide a build that wrongly re-notifies on a repeat; only the worker-on case shows it, so C-21 has a test with the worker running.
- `list --raw` already prints the assignee as a fifth tab-separated column in the build | Observable: `node bin/tickets.js --data FILE list --raw` | Why: C-29's open point allows it; the tests check only the first four columns and the weekly report's counts.
- The weekly report counts must not change when tickets get assigned | Observable: `node scripts/weekly-report.js --data FILE --json` before and after assigning the same tickets gives identical JSON | Why: the report reads `list --raw` by column position, so a column inserted before the title would break it silently; C-29 tests this on a real data file.
- The data file written by the service carries the assignee under the key `assignee`; a file without the key must load as unassigned | Observable: remove `assignee` from each ticket of a saved `DATA_FILE`, start the service: `GET /tickets/:id` shows `assignee: null` and the ticket is in `?assignee=` | Why: C-12 is tested by editing a file the service wrote, since the specification does not give the file's layout.
- Filters used to combine with OR in the code before this change (`matchesFilters` used `some`) | Observable: `?status=open&priority=urgent` lists only open urgent tickets | Why: the build fixed it; C-25 would fail on the old behaviour, and no earlier test covered two filters.
