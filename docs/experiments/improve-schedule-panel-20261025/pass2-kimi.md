## 2. Augment / revise

**REVISE (own):** — P2, the largest change, forced by Codex's disk evidence.
- **From:** "The miss is a replay gap: item 1 asks for replayable examples, never a replay; require replaying each derived result and recording it, with per-transition rules, a script route, and a `NOT-REPLAYED` exit."
- **To:** The demonstrated failure is **invalid validation, not a missing replay**. Adopt this replacement item text:
  > an expected result derived from a sequence of inputs (user actions, calls, data writes), **including cases this review introduces or changes**: validate the stated start state and every transition under the spec's own rules, recomputing each intermediate state and naming the rule that permits it; record the replay in the review file (case ID, method, decisive intermediate states, computed result). Where the derivation is mechanical, recompute it with a short script in the review's experiment scratch and paste its output. A helper that merely applies the requested state changes does not establish that the sequence is permitted, and the product under construction must not be the sole authority for its own expected result. Reuse a prior review's recorded replay only when its inputs, rules and method still apply; otherwise re-derive. If you did not validate a result, mark it `NOT-REPLAYED: <reason>` — never record a replay you did not perform.
- **Why:** Codex showed run 5b's test-strategy review **added TC_28** and *did* record a replay — via `apply_simple`, a helper whose own docstring says "No legality" (run `run/scratch/oracle_replay.py`). The illegal line b2b4 b7b5 b4b5 was replayed **and ratified**. P2 as proposed (and my pass-1 version) would have reproduced the ratification, since "record the replay" accepts a no-semantics applier. This also corrects the causal story: the defect was a **review-introduced invalid oracle**, so the clause "including cases this review introduces" is load-bearing. The quantified saving stays plausible-but-unproven (n=1 send-back), and it is now clear the saving only materialises if the wording beats bogus validators. Cost guard folded in: reuse of recorded replays across the five planning reviews, or "every expected value" means re-deriving the same FENs five times — a cost the proposal missed (its "+200 characters" counts only text). This exceeds +200 characters; per the raise-the-bound policy, that is the right trade.
