The block (`U9-evidence/block-after.txt` against `block-before.txt`, both the 83/96 test-spec head; `block-fresh-synthetic.txt` and
`block-resumed-synthetic.txt` are the two forms from a real runtime start):

```
Until Loop (no iteration limit; the loop script counts the iterations):
RUN the Until Loop now, once, before any work, and do this stage's work only inside it. Start it with this command, in the foreground, exactly as printed (if the Receipt below already exists and is active, run its next_argv instead: a second start resets the loop):
python3 <runtime>/until_loop_ephemeral.py start --receipt <receipt> < <contract>
Then follow each packet it prints (run its done_argv as printed) until the receipt says complete or stopped. Its argument is already in the Contract file; do not edit that file or the receipt:
----- BEGIN until-loop ARGUMENT -----   (Work, Exit when ALL of these hold, Repeat while, Contract, Receipt: unchanged)
----- END until-loop ARGUMENT -----
Result: when the Receipt says status complete (stopped: report it), keep it in evidence_refs and run the Callback command above. If that refuses for the loop, run the start command above again (an active receipt: its next_argv instead), then run the Callback again. Done-report fields: classification trivial|non-trivial|unresolved, exit_assessment satisfied|unsatisfied|unknown, continuation_assessment allowed|blocked|cancelled, plus evidence and handoff (nonblank text).
Call an exit condition satisfied only when a command or file shows it after your last edit.
```

A packet read after the start prints `RESUME_LINE` then `ARGUMENT_LEAD` in place of the RUN line, the command and the follow line, and
`RESUME_RESULT_LINE` (it names the receipt's `next_argv`, there is no start command above it).

## Deviations and risks

- **Heading.** Plan 6.3's heading (`...; the loop script counts the iterations`) is restored (+39 per looped stage); 0d462ca4 had dropped it for bytes
  at a time the step-plan head had 26 characters of room. The value is low (it says the model need not count iterations); the cost is small and
  U7's table decides if it stays.
- **`RESUME_LINE` wording.** "do not invoke it again" became "do not start it again (a second start resets it)": the block no longer says
  "invoke" anywhere, and the reason for the rule is now said where a resumed reader sees it. The plan quoted the old sentence.
- **Cancelled-loop refusal (not in the unit text).** A resumed packet holds no start command, so the one refusal that says "start the loop again"
  now carries it (`check_loop_packet`, a one-line change, fail-first recorded). Without it a model that cancelled a loop had no printed way to restart.
- **`WORK`/`REPEAT` left as they are.** They already match 6.3's argument lines (the Work line names the packet file for the duty items) and the
  contract JSON and its hash must not change; verified byte-identical for all eight stages.
- **Offline implement block.** The offline walk's synthetic step plan has no steps, so the implement loop prints "Unavailable" in both routes: the
  rendered pin test excludes implement and a Synthetic test covers both routes' implement block. U5/U7's "real multi-step plans" fix will make the
  render exercise it; then `head_table.json` implement values need another +207 (246 less the 39 already in).
- **U5a tooling not on this base.** `render_diff.py`, `packet_changes.json` and `--text-dir` live on `feat/shiploop-eff-U5a-1d5098`, which conflicts with INT in
  `packets.py`, `packet_anatomy.py` and `shiploop-e2e-packet-anatomy.test.py` (INT's loop/packets branches changed the same hunks). I did not merge it; renders
  ran on a scratch overlay (U5a's tooling with INT's contract-writing walk). The integrator who merges U5a must add `proposed-packet-changes-U9.json` as the
  `U9` list of `packet_changes.json` and take both sides of the `until-loop` rule in `packet_anatomy.py` (the end alternatives: `ShipLoop wrote the loop contract`,
  `Unavailable: `, `Call an exit condition satisfied only when`; this unit's version has the same three).
- **A packet read again no longer shows the command.** Intended (LP-3). A stale fresh-form packet in the model's context still carries the active-receipt clause.
- **Not measured:** any live behaviour (does a Claude run now start the loop first: U31 row 1 of 7.3), the Grok view of the new heads beyond the arithmetic above.

report fields and the active-receipt clause are obligations the old block left to the runtime's output, which U21 is about to shrink.
