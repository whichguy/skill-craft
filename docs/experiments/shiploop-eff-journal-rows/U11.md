## Deviations from the unit text

1. **The dead `('*', ...)` swap row is applied, not deleted.** The row is the correct generator of the `none` schedule
   (built from `reviewed_stages("none")`, guarded at import by `_check_swaps`); it was dead only because nothing applied it
   to COMMON. `prompts.common_text(mode)` applies it and the reference calls that. Deleting it would have emptied the
   table, its guard and two tests, and left `duty()`'s `planning_review` argument unused. `state["planning_review"]` is read
   strictly (one supported version), so five tests that rendered the reference from a hand-built state now carry the key.
2. **`_checked_line` tail is shorter than the plan's wording and still grows.** Plan: "`complete --check-only` runs the same
   gates without accepting and prints the first refusal, so repeat it until it accepts" (204 characters). Built: "`complete
   --check-only` prints the first refusal without accepting, so repeat it until it accepts" (180): the same facts, 24 characters
   fewer on every producer packet (owner rule 5). Both grow the line against the base (+71 and +47): the estimate "about -40"
   cannot hold, because the first clause ("A refusal does not advance the run: fix the cause and run the same command again")
   was restored on purpose on 2026-10-11 (`837923a3`, a pin worker reported the rule had left the packet), so only the
   check-only clause could change. An earlier draft of this row said the longer wording would flip inline test-spec at 163
   characters from a whole print to a head; measured with the merged render tool it would not (15,935 against 15,911, limit
   16,000), so brevity is the only reason for the difference.
3. **validate-existing summary** is "ShipLoop ran every expectation check on the unchanged checkout and each matched its
   state." (89 characters), not "All expectation checks matched ... (script-run, no model turn)". The run-review exporter
   (`RECORDED_REASONS`) and the audit harness (`_SCRIPT_RECORDED`) recognise the script-recorded stage by the opening words;
   keeping them avoids a change to the exporter's mapping. The audit marker is now the opening words only, so it accepts the
   engine's new sentence and the longer one of an earlier ShipLoop (a `shiploop-e2e-audit` change and note).
4. **Verify's Work is route-aware.** `shiploop-packet-recut` `WorkLineTests` requires every cited item to exist, and inline has
   no item 8 (VR-6), so inline cites "1-7 and 9", ask-agent "1-9". The unit text said "equal the parsed duty counts": seven
   stages cite their whole duty (equal), verify stops at 9 (its items 10 to 12 follow the review loop), pinned in
   `WorkTextTests.LOOP_LAST`. The duty's opening says "items 8-9 once" (ask-agent) and "item 9 once" (inline).
5. **Existing pins changed by the plan's own decisions:** `shiploop-delegation` `test_verify_assembles_direct_or_chain_work`
   (inline no longer prints item 8; its "candidate is assembled in the execution checkout" sentence is ask-agent only);
   four raw-WORK asserts in `shiploop-navigator-contract` (the range is `{items}`); the Checked-by pin in
   `shiploop-packet-completeness`.
6. **Not built:** the rev 4 Step 8.1 "script-written start-contract file for the optional Backchain child" (not in the unit
   text; a feature, not a false sentence) and the measured `_checked_line` vocabulary line (conditional on U31).
7. **The Improve child's start contract is untouched.** `loop_contract.stage_exit` (called in `improve_start_contract`) still
   quotes the per-step done-when on the ask-agent route; the hand-off the child reads carries the aggregate wording. The call
   sits beside U2's edit of `required_trivial_reviews`, so it waits for U2's merge.
