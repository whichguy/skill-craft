#### Key learning

- The stop rule's scope is a gate value, not a prompt: a second value of the existing field carries the whole difference between
  document and code reviews, the runtime reads the pair from the latest report, `trivial_streak` and `last_pass_changed_tree`, and
  the state schema does not change (a test pins that). Replayed on the study's passes, gate 3 gives back all six saved passes, so
  the claim "about 4 of 40 Improve minutes" now rests on the five measured planning stages alone (not on the seven stages of the
  rule `always`: system-test-author and release-plan were not measured).
- F2 was a catalog gap: the runtime path reached `installed-skill-invocation` by no name, and the fixtures also encoded the old
  two-pass rule, so adding `git init` (the plan's fix) would not have turned them green. They now edit a file between passes and
  stay outside Git, which makes the installed read-only copy exercise F3 too.
- A measurement that writes scratch must exclude its own scratch: with TMPDIR inside the workspace the stop branch's temporary
  index (and the new throwaway repository) made every pass read as changed, with no cap to end it. Found by the first review round.
- A frozen exit condition names only what the model can assess. A count the runtime gates (two passes in a row) in the exit made a
  literal reader grade the gate, report a clean pass unsatisfied and delay the end by a pass; the count belongs to the repeat
  condition, the handoff and the runtime's own packets (R1).
- An exit item measured on an old base does not hold on a new one: nine units landed between the unit's measurement and the review,
  and the merge held one conflict, one red expectation and one row the new journal suite could not parse, none visible to an earlier
  run (R2). Re-measure on the merge with the current tip, and state the tip.
- A proposal the owner approves must say what its evidence covered: five measured stages are not seven (R3).
