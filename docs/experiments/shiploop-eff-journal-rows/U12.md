#### Key learning

- The artifact's three test-spec refusals came from one cause: a refusal that printed an example row with a real-looking ID. A
  placeholder in every printed shape closes it, but only if a copied placeholder is refused as one, so the three case placeholders
  now live with the shape (`expectations.CASE_PLACEHOLDERS`), the navigator's `HANDOFF_PLACEHOLDERS` takes them from there, and the
  refusal shape and the template can no longer disagree (the old refusal printed oracle/red/green strings that the placeholder gate
  did not know, so a copy of it passed).
- Deriving a row field is only safe when the plan states it: the criterion is filled when the plan's focused commands list exactly
  one for the ID; the requirement only when that criterion's text names exactly one R-<n> the spec holds. Everything else stays a
  placeholder, so a wrong guess can never be accepted silently.
- SPEC-6 as proposed would stay silent in the artifact (its C2 sits on a regression row). The notice fires for a criterion that only
  a focused row lists and no case names, which the step-plan gate cannot see.
- Printed text that grows with the plan needs a bound: the skeleton is capped at 12 rows and the requirement line at 2,400
  characters, because a head over 20,000 characters is not shown whole on every host.
