# User Administration

## Scope and source

On 2026-11-21 the user requested “Let admins upload a CSV to bulk-create users.” The source is the standalone ShipLoop task, § The incoming request. The task’s § Where you are establishes that there is no earlier spec, selected baseline, product repository, discovery, or research result for this run. Existing behavior and deployment capabilities are unknown. The request authorizes a CSV path into ordinary account creation. Defaults below are specification decisions taken for the unattended run, subject to the listed gaps.

“Admin” means a signed-in person with current authority to create ordinary users in the selected administration scope. A scope is the product’s existing user-management boundary, which may be product-wide. The import, file, and receipt cannot select or cross another scope. Ordinary creation means the existing validation, uniqueness, least-privileged account defaults, onboarding behavior and lifecycle, if present. Preservation statements below are obligations to verify.

### R-2 Upload and validate one CSV

**Basis and delta.** 2026-11-21 request, § The incoming request, “upload a CSV”. Add a file selection, explicit submit and import-specific validation, preserving ordinary create validation at R-3. File syntax takes its quoting and comma rules from RFC 4180 §2, with the differences specified here. There is no inspected product file contract or runtime. Implementation and upload checks are pending. [RFC 4180 §2](https://www.rfc-editor.org/rfc/rfc4180.html#section-2)

**Default format.** One UTF-8 comma-delimited file per submission, with an optional leading UTF-8 BOM, LF or CRLF record breaks and an optional final record break. Double-quoted fields may contain commas, doubled quotes or line breaks. The first record must be the header. Header names are exact, unique and in any order. The default header set is required `email` and optional `name`. Omitted or empty optional `name` uses the ordinary creation default. A delimiter after the last populated value represents an empty field. No other headers are accepted under this default. Fields go through the normal create rules for whitespace, normalization, required values and allowed lengths. A physically empty record after the header is skipped. A record containing delimiters, quotes or whitespace is a data record. Number logical records from 1 including the header and physically empty records. A quoted line break does not increment this number. File name or content type alone establishes no format validity.

### R-3 Create ordinary users and preserve existing accounts

**Basis and delta.** 2026-11-21 request, § The incoming request, “bulk-create users”. Add creation of multiple ordinary users from one accepted file. Preserve all existing single-create rules, records and authorized writers. No existing user schema, roles, identity policy or downstream effects were observed. The import rule and account-authority checks are pending implementation and verification.

**Default behavior.** Process data records in file order within an import. Wrong field count or invalid domain values skip that record with a reason. The first record that passes row validation for a canonical identity claims that identity within this file. Later valid records for that same identity are skipped as duplicates in the file, even when the first valid record collides with an existing account or later fails. A row that fails validation claims nothing. Canonical identity and uniqueness scope are the ordinary user-create rules. Examples use email as the key under the stated fixture policy. The same create authority adjudicates all writers, including single-create and overlapping imports. The first successful authoritative creation wins a race. The other attempt reports an identity conflict within the information its admin may see.

**State and recovery.** The form keeps transient selection and view state. It binds the reference to the submitter, scope and original submission intent.
