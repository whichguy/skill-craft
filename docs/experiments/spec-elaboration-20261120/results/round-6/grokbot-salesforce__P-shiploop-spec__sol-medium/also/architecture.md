# Grok Bot for Salesforce Architecture

## Decisions

### AD-1 — Lightning custom tab in the existing Salesforce shell

Propose a Lightning web component exposed as a custom tab and available from App Launcher → All Items. Create both the component target and the actual tab metadata. An eligibility target alone supplies no consumer entry. Prefer an existing shell for the development evaluation so access and navigation changes stay scoped. Generate the tab route through Salesforce navigation. Assign tab, runtime class and provider principal access only to designated users, with a specific runtime bot entitlement if required to make admission independent of navigation. Confirm metadata names, release/API version, org edition, permissions and compatibility in the selected org before committing target details. See [R-1](spec.md#r-1--open-grok-bot-in-the-intended-salesforce-development-org). [Configure Components for Custom Tabs](https://developer.salesforce.com/docs/platform/lwc/guide/use-config-custom-tab) · [Add Components as Custom Tabs](https://developer.salesforce.com/docs/platform/lwc/guide/use-config-custom-tab-lex.html) · [Secure Apex Classes](https://developer.salesforce.com/docs/platform/lwc/guide/apex-security.html)

### AD-2 — Server-side Apex to xAI Responses

Propose one imperative, noncached call from the Lightning component to Apex, with a bounded Salesforce callout to the xAI Responses API. The fixed provider base is `https://api.x.ai`; the operation is `POST /v1/responses` over HTTPS with JSON and a Bearer authorization header. Use the extensible Named Credential and Custom Authentication External Credential with a dedicated named principal. Reference the stored authentication parameter in the custom authorization header and disable auto-generation of that header. Use principal permissions and necessary User External Credentials access. Credential provisioning is an authorized setup operation separate from metadata deployment. For Custom auth, Setup reports authentication status as Unknown, so live success and failure are the readiness evidence. [Call Apex Methods Imperatively](https://developer.salesforce.com/docs/platform/lwc/guide/apex-call-imperative.html) · [Salesforce Custom Authentication](https://help.salesforce.com/s/articleView?id=sf.nc_create_edit_custom_auth_ext_cred.htm&language=en_US&type=5) · [API Keys in Custom Headers](https://help.salesforce.com/s/articleView?id=sf.nc_custom_headers_and_api_keys.htm&language=en_US&type=5) · [Salesforce Authentication Status](https://help.salesforce.com/s/articleView?id=sf.nc_understand_configuration_status.htm&language=en_US&type=5) · [Principal Access](https://help.salesforce.com/s/articleView?id=sf.nc_enable_ext_cred_principal.htm&language=en_US&type=5) · [Credential Permissions](https://help.salesforce.com/s/articleView?id=sf.nc_user_external_credentials_permissions.htm&language=en_US&type=5)

Send only the validated current text as `input` with a configured `model`, bounded settings and `store: false`. Use a nonstreaming request for the bounded interactive candidate, with no previous response ID or tools. Accept a completed response only with usable assistant message text in its output. Retain the documented distinction between storage for API retrieval and provider audit retention. Parse the terminal result on the server and return only display text or a sanitized outcome to the owner view. See R-2 through R-4. [Responses API, Create new response](https://docs.x.ai/developers/rest-api-reference/inference/responses#create-new-response) · [xAI API Security](https://docs.x.ai/developers/faq/security)

**Conditional fit.** Candidate for measurement is `grok-4.3` with `reasoning.effort` set to `none`, subject to actual model access and fit. Salesforce documents 120 seconds cumulative callout time per Apex transaction and 6 MB for synchronous callout request or response, also subject to heap. Salesforce documents a 20 concurrent off-domain callout cap specifically for Developer Edition, which must first be established for the target. The xAI guide generally prefers streaming and recommends at least 900 seconds for its workloads. A short nonstreaming turn may fit but that is an inference. Select timeout and size headroom only after an authorized target probe of representative prompts, upper workload and failure cases. If the bounded request cannot meet the interactive contract, revisit transport in this decision before dependent work and surface any required scope decision. No additional service is selected. [xAI Best Practices](https://docs.x.ai/developers/model-capabilities/text/best-practices) · [Salesforce Callout Limits](https://developer.salesforce.com/docs/platform/apex-dev/references/apex-dev/apex-callouts-timeouts.html) · [Salesforce Apex Governor Limits](https://developer.salesforce.com/docs/platform/apex-dev/references/apex-dev/apex-gov-limits.html)

### AD-3 — Lightning design primitives and a themed bot surface

Use Salesforce Lightning Design System primitives and icon family. Use locally scoped bot styling for light and dark and choose supported theme hooks after checking the target's SLDS generation. Keep the composition focused on the current exchange and composer. A dedicated status beside the composer communicates progress and actionable recovery. Let the shell supply established navigation and focus behavior, and check the actual keyboard and screen-reader journey where the bot adds asynchronous feedback. Specify the concrete palette, density, narrow/wide composition and theme implementation during planning. The local [UI visual-direction guide](GUIDES/platforms/ui.md#light-expressive-starting-point) supplies the expressive starting point. Reusing Salesforce affordances reduces maintenance and theme compatibility work relative to a separate UI toolkit. Component-level theming effectiveness and accessibility require a target browser check before relying on hooks for both appearances. See [Non-functional requirements](spec.md#non-functional-requirements).
