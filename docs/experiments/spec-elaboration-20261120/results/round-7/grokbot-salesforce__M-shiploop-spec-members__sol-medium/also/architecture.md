# Grok Bot for Salesforce Architecture

## Decisions

These are design defaults for the behavior in [the product specification](spec.md). Public documentation establishes route availability. Target configuration, compatibility and authority remain subject to R-1 through R-4.

### AD-1 — Lightning custom tab and scoped permissions

Use a Lightning Web Component with the `lightning__Tab` target and a CustomTab metadata entry labelled **Grok Bot**. Use the selected org's existing Lightning shell and a dedicated bot permission set for tab visibility, Apex invocation and external credential principal access, including applicable User External Credentials access. The provisional tab API name is `Grok_Bot`. Its proposed relative entry path is `/lightning/n/Grok_Bot`, generated through the `standard__navItemPage` reference in the target. Confirm against org inventory before committing the name or handing off the link. Confirm launcher access, direct navigation, metadata version and permission behavior in the target. This keeps the deployment and its grants scoped to the feature. [Salesforce custom tab configuration](https://developer.salesforce.com/docs/platform/lwc/guide/use-config-custom-tab) · [CustomTab Metadata API](https://developer.salesforce.com/docs/platform/api-metadata/references/meta-types/metadata-customtab.html) · [Secure Apex classes](https://developer.salesforce.com/docs/platform/lwc/guide/apex-security.html) · [Salesforce delivery guide](../GUIDES/platforms/salesforce.md#service-discovery)

### AD-2 — Imperative Apex call and server-side authentication

The component calls Apex imperatively on Send. Validate again in Apex and use an enhanced Named Credential for the outbound endpoint with a Custom External Credential and a shared named principal granted to the bot users. The credential configuration injects an Authorization bearer header referencing the protected API key. Disable the generated Authorization header and enable credential formula substitution for the custom header. Populate the secret separately from source deployment. The browser receives only display data and safe status. Pin a compatible Salesforce API version after confirming the org release and available metadata. [Imperative Apex calls](https://developer.salesforce.com/docs/platform/lwc/guide/apex-call-imperative.html) · [Call APIs from Apex](https://developer.salesforce.com/docs/platform/lwc/guide/data-api-calls-apex.html) · [Named Credentials glossary](https://developer.salesforce.com/docs/platform/named-credentials/references/named-credentials-reference/nc-glossary.html) · [API keys in custom headers](https://help.salesforce.com/s/articleView?id=sf.nc_custom_headers_and_api_keys.htm&language=en_US&type=5)

### AD-3 — Foreground Grok Responses API and view-local state

Use one non-streaming JSON POST to `https://api.x.ai/v1/responses` per admitted send. Supply the configured Grok model and a single user input. Set `store: false` and omit previous response IDs and tool definitions. A successful response has a completed status and usable text in assistant message content of type `output_text`. Consume those parts in wire order without inserting text. Ignore other output items. Map response and transport failures to the spec's safe outcomes. Verify the selected team's model and real response shape before finalizing integration. [Responses API, Create new response](https://docs.x.ai/developers/rest-api-reference/inference/responses) · [Generate Text, disable server-side response storage](https://docs.x.ai/developers/model-capabilities/text/generate-text#disable-storing-previous-requestresponse-on-server) · [Provider audit retention](https://docs.x.ai/developers/faq/security)

Track the active attempt and view identity in component memory. Apply a result only to its matching live attempt before the UI deadline. The server applies its own outbound callout deadline, selected with the end-to-end deadline after target timing evidence. This keeps the workflow to a single request and result with no independent worker lifecycle. The implementation is contingent on sufficient callout and browser timing headroom with the entitled model. If that headroom is unavailable, revisit this decision and affected acceptance criteria via the spec correction route. [Salesforce callout limits](https://developer.salesforce.com/docs/platform/apex-dev/references/apex-dev/apex-callouts-timeouts.html)

### AD-4 — Salesforce shell with a themed bot panel

Keep the org's Lightning navigation and use accessible Lightning primitives where they satisfy the interaction and appearance criteria. Scope visual styling to the bot panel. The panel centers an exchange and a reachable text composer, with a separate status area announcing pending and terminal changes. Use light-first, rounded tonal surfaces and a local dark control. Choose the final tokens and state compositions in the plan against the spec's observable criteria. [ShipLoop light expressive starting point](../GUIDES/platforms/ui.md#light-expressive-starting-point) · [WCAG 2.2](https://www.w3.org/TR/wcag/)
