## Behavior model

### Sequence flows

- **F-1 — Select and create** (R-1–R-4). An admin enters Users with current rights in the target scope. The import view explains the format and lets the admin select or replace a file (T-1). The admin explicitly submits it (T-2). The authority applies admission, parsing and validation (T-3), then rechecks authority and identity availability at the creation boundary (T-4). The originating view may show progress while waiting. Confirmed success shows the committed count and is visible on a fresh authorized Users read (T-5).
- **F-2 — Correct rejected input** (R-1, R-2, R-4). The same authorized entry and submission lead through T-1 and T-2 to a file rejection or record diagnostics at T-3. The result shows zero created. The admin edits the source outside the product, replaces it and deliberately submits a new attempt. Only that submission can lead to T-4.
- **F-3 — Resolve conflicts, failures and uncertainty** (R-1, R-3, R-4). After T-2, conflicts, revocation before commit and definite write failures go through T-4. Lost contact after submission invokes T-5 without assuming either result. An authorized admin may read the same attempt in the open view, or check Users and start a fresh attempt if they leave or status expires. T-6 governs old-view cleanup and suppression after authority changes.
