# Grok for Salesforce architecture

## Decisions

### AD-1 — Host the chat inside Lightning Experience

Use a Lightning Web Component exposed through an actual custom tab, with App Launcher visibility for authorized users. Include the tab in an approved Lightning app where necessary for discoverability. Use a dedicated, maintainable permission-set assignment for the intended cohort and require effective server class and outbound principal access. A tab's visibility and the server's authority are separate controls. Keep app, tab, credential and permission changes scoped to the selected development org.

This approach uses existing Salesforce identity and navigation. An external SPA would require separate hosting and identity integration. Agentforce or a customer-facing messaging channel would change the assumed consumer and licensing prerequisites. Either requires product direction if the private internal tab assumption changes. The actual org, edition, runtime API version, app availability and metadata API names remain open. Validate the navigation and effective roles against R-1 and check for matching existing metadata before selecting the final API names for the dev org.

### AD-2 — Make server-owned inference calls through Salesforce credentials

Use an imperative, non-cacheable invocation from the component to Apex. The Apex entry checks admission and validates the text request, then makes one HTTPS callout to the authorized xAI endpoint. Use a modern Salesforce Named Credential for the destination and a linked External Credential with a custom authentication named principal. Salesforce resolves the bearer header from the admin-provisioned encrypted parameter. Restrict principal and Apex access to the designated users, and do not accept a URL, provider key, model selection, role override or tool definition from the browser. Configure a fixed permitted model server-side. Use nonsecret config for environment differences. No Salesforce record data access is needed, so record sharing, object access and field-level access are inapplicable to the invocation as scoped. Reassess each if record access is ever requested.

A browser call would expose a shared provider secret or require an additional authentication scheme. A proxy or durable worker would add hosting, status, cancellation and retention obligations. Use the org-native callout as the starting choice. If the authorized model cannot reliably complete within the adopted deadlines, reopen this decision before adding a service or altering completion semantics. Validate the actual permission gate, provider authorization, endpoint, non-content operational signals and Lightning/session failure behavior. Confirm approved deployment and access activation separately from secret provisioning.

### AD-3 — Use text Responses with page-owned context

Start with xAI Responses at `POST https://api.x.ai/v1/responses` and candidate model `grok-4.20-0309-non-reasoning`. Model availability, billing, team approval and deadline fit require verification. Send the ordered user and assistant messages as text, request a foreground non-streaming response, disable stored response retrieval with `store: false` and omit response pointers and tools. Treat a successful HTTP response as a reply only after verifying completed status and collecting nonblank user-visible `output_text` from completed assistant message items in provider order. Return only safe outcome fields to the component. Ignore structured reasoning and never execute tool or markup output. Validate an authorized synthetic call and compare the full displayed text to the associated provider result. Validate contract fixtures with different output values to detect hardcoding.

Use component memory for isolated chat state, an immutable input snapshot per send, a current chat identity and a per-attempt identity. Reset and disconnection invalidate presentation ownership. The server request and provider processing can still finish. Keep operational disclosure distinct from the provider's audit retention terms. A saved transcript or provider response pointer would add retrieval and retention obligations. Streaming and durable background completion would require different host feasibility checks and state contracts. Keep the exact timeout, input and output budget and effective provider limits open pending the checks under R-2 and R-3.

[xAI Responses API](https://docs.x.ai/developers/rest-api-reference/inference/responses) · [Generate Text](https://docs.x.ai/developers/model-capabilities/text/generate-text) · [Candidate model](https://docs.x.ai/developers/models/grok-4.20-0309-non-reasoning) · [xAI API Security FAQ](https://docs.x.ai/developers/faq/security)

### AD-4 — Use Lightning primitives and component-scoped appearance

Use accessible Lightning base controls and Salesforce iconography where they support the interaction and the selected host theme. Compose a focused transcript, speaker groups, composer and pending/error treatment with component-scoped styles. The visual reference is the light Google Gemini starting point adapted through Material 3 Expressive principles, within Salesforce conventions. Keep the chat light on first open and offer a component-level dark choice. Inspect the selected host's theme and test styling hooks in that runtime before relying on them. Maintain a compact chat composition with clearly grouped turns, a primary Send action and a recognizable pending indicator that also works with reduced motion. Verify panel layout and accessible feedback in the composed host and keep the exact palette, type, spacing and motion treatment for planning.

Reusing existing primitives and composing the chat locally has lower integration cost than a separate UI toolkit or full custom control set, assuming the target provides the expected Lightning support. A page-scoped treatment avoids requiring a particular Salesforce-wide theme. If the host cannot support the specified contrast, usable narrow composition or native control theming, use a bounded deployed rendering check to identify the smallest component-level change. No separate design dependency is selected.
