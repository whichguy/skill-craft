# Grok Bot for Salesforce architecture

## Decisions

### AD-1 — Lightning custom tab and Salesforce execution boundary

Use a Lightning web component exposed to a Lightning component tab, plus the separate custom-tab metadata. The initial consumer entry is **App Launcher → All Items → Grok Bot** in the existing Lightning shell. The candidate tab API name is `Grok_Bot` and candidate route is `/lightning/n/Grok_Bot` in the designated org. Confirm names against target metadata and capture the resolved route after deployment. An existing page assignment or a separate app could also host the component. The custom tab gives a direct destination with a smaller footprint and no need to edit shared app navigation by default.

The component calls a non-cacheable Apex server action imperatively on Send. A feature permission set grants tab visibility, Apex class access and use of the outbound credential principal to designated users. Salesforce checks effective runtime access at the server boundaries, independently of the visible controls. The Apex action has no record query or mutation and requires no business-object access. The design needs only a single in-flight invocation per view. Keep the view, attempt identity, timeout handling and light/dark preference in component memory. Use documented lifecycle and navigation handling to discard completion after exit and avoid pulling data from component caches. Validate actual behavior on navigation away and back because the shell can own view lifecycle. Revalidate component target, org API version, grant and tab metadata, name availability and browser routing with the identified operator. [Salesforce custom tabs](https://developer.salesforce.com/docs/platform/lwc/guide/use-config-custom-tab-lex.html), [navigation item page](https://developer.salesforce.com/docs/platform/lwc/guide/reference-page-reference-type.html), [imperative Apex and one-time resolution](https://developer.salesforce.com/docs/platform/lwc/guide/apex-call-imperative.html), [Apex access](https://developer.salesforce.com/docs/platform/lwc/guide/apex-security.html), [component DOM lifecycle](https://developer.salesforce.com/docs/platform/lwc/guide/create-lifecycle-hooks-dom.html).

### AD-2 — Org-managed xAI credential and Responses adapter

Use an enhanced Salesforce Named Credential for the HTTPS xAI inference host, linked to a Custom External Credential with a named principal. Configure a custom Authorization header with the Bearer prefix and the protected principal parameter. Avoid competing generated authentication headers. The approved Salesforce administrator provisions the secret separately from metadata, with a team key limited to the needed endpoint and model. Use non-secret org configuration for the selected model, with scope for an admin to update it. Proposed default is `grok-4.3` with Responses `reasoning.effort` set to `none`. It is documented for text and simple, latency-sensitive work. An entitled newer Grok model or a different reasoning effort are options if this version ceases to fit. Recheck the exact model against current team settings, response schema, costs and a synthetic latency sample before use. No provider API key or Salesforce session value is needed in this document or in a delivery receipt.

Send a single non-streamed JSON POST to `https://api.x.ai/v1/responses` per admitted prompt. The adapter binds the configured model and accepted `input`, sets `store: false` and the specified `max_output_tokens`, and supplies no previous response ID, tools, user ID or org data. Return only completed assistant text from ordered `output` message content of type `output_text`, or the safe result category required by R-2. Verify the actual response structure and terminal states with the authorized team. The network wait is bounded within the Apex callout limits. The component separately enforces its consumer deadline since server timeout configuration alone does not define end-to-end UI delivery. A legacy Chat Completions endpoint or a streaming bridge would add a legacy dependency or additional transport and operational state. The selected endpoint supports the required one-response text exchange with Salesforce owning the boundary. [Salesforce Named Credentials glossary](https://developer.salesforce.com/docs/platform/named-credentials/references/named-credentials-reference/nc-glossary.html), [Salesforce API keys in custom headers](https://help.salesforce.com/s/articleView?id=sf.nc_custom_headers_and_api_keys.htm&language=en_US&type=5), [Apex HttpRequest](https://developer.salesforce.com/docs/platform/apex-ref/references/apex-ref/apex-classes-restful-http-httprequest.html), [xAI REST host and auth](https://docs.x.ai/developers/rest-api-reference/inference), [xAI Responses and sample response](https://docs.x.ai/developers/rest-api-reference/inference/responses), [xAI Grok 4.3](https://docs.x.ai/developers/models/grok-4.3), [xAI model best practices and alternatives](https://docs.x.ai/developers/model-capabilities/text/best-practices), [xAI errors](https://docs.x.ai/developers/debugging).

### AD-3 — Salesforce shell and a scoped conversation surface

Reuse Lightning primitives where they meet the interaction and theme requirements, and use public Salesforce Lightning Design System styling hooks or scoped styles for the bot's own surfaces. Plan a conversation area, visible synthetic-data notice, labeled multiline composer and Send action, inline status and feedback, and a bot-surface appearance switch. The conversation area leads with readable message groups, subtle tonal separation and a clear status near Send. Retain Salesforce interaction patterns and style the bot locally. Introduce no separate framework, theme override for the org, or remote font dependency by default.

Native primitives are the smaller maintenance choice. Documented hooks and selective local composition are a modest extension for intentional light and dark design. A standalone design framework adds integration and accessibility work without a demonstrated benefit for this screen. Revalidate actual org theme, supported hooks and narrow layout in a browser before selecting concrete treatments. Use the [light expressive starting point](../GUIDES/platforms/ui.md#light-expressive-starting-point) and the UI premises in the spec. No separate frontend-design skill was listed for this spec run. [Salesforce component styles](https://developer.salesforce.com/docs/platform/lwc/guide/create-components-css-intro.html), [Salesforce SLDS styling hooks and limitations](https://developer.salesforce.com/docs/platform/lwc/guide/create-components-css-custom-properties.html).
