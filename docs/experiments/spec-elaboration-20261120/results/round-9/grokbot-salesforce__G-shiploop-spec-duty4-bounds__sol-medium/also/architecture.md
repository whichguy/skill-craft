# Salesforce Grok Bot Architecture

## Decisions

### AD-1 — Host the bot on a Lightning App Page

Use a Lightning Web Component on an activated Lightning App Page with an App Launcher entry for designated users. It owns the labelled composer, current exchange, status, error space and theme option. Use native Lightning primitives and the SLDS icon set. Define concrete light/dark treatments after checking the target shell and styling capabilities. The UI's default page memory ends with the page instance. The App Page and its activation/visibility each need actual target verification. Check for metadata identity collisions before choosing any API names. A record page would tie the feature to record context, and a standalone client would need an additional access surface. [Salesforce App Page target](https://developer.salesforce.com/docs/platform/lwc/guide/targets-lightning-app-page.html), [Lightning App Builder activation](https://developer.salesforce.com/files/accessibility/lightning_app_builder/lightning_app_builder_apphome/index.html), [Lightning icons](https://developer.salesforce.com/docs/platform/lightning-component-reference/guide/lightning-icon).

### AD-2 — Mediate calls in Salesforce with a protected named principal

Use one imperative, noncacheable Apex request for an admitted send. Keep admission on the server and map app entry, Apex class access and external-credential principal access to bot-specific permissions for existing users. Use a modern Named Credential and Custom External Credential with a named principal for the xAI inference host. Populate the API key outside source, use the protected auth parameter in a custom bearer header and prevent Salesforce from generating a competing Authorization header. Use the authorized scope and least privilege of the actual key. Apex does not read or mutate business records, so record sharing, CRUD and FLS for runtime business-data access are inapplicable. Verify the selected target/API version and runtime permission mapping, especially after revocation. A browser call would expose the provider secret to the client. A standalone proxy would add infrastructure and a second authorization boundary. [Secure Apex Classes](https://developer.salesforce.com/docs/platform/lwc/guide/apex-security.html), [Imperative Apex calls](https://developer.salesforce.com/docs/platform/lwc/guide/apex-call-imperative.html), [Named Credentials](https://developer.salesforce.com/docs/platform/named-credentials/guide/get-started.html), [Custom authentication](https://help.salesforce.com/s/articleView?id=platform.flow_http_callout_guidelines_authenticating.htm&language=en_US&type=5), [xAI inference authentication](https://docs.x.ai/developers/rest-api-reference/inference).

### AD-3 — Use the xAI Responses API for a single foreground completion

Use `POST https://api.x.ai/v1/responses` from Salesforce with an entitled, configured Grok text model, `input` holding the current user's text, `store: false`, `stream: false`, no prior response ID, and no tools. Use the selected generation bound once established. Map a completed response's assistant message `output_text` items in provider order to the UI. Keep raw envelopes server-side and forward only safe application outcomes. The browser can wait asynchronously while a Salesforce transaction makes the foreground HTTP call. No queued inference, event service, shared cache or background status polling is needed for this flow. The Responses API supports typed text and explicit storage control. Provider-managed audit retention is separately governed by the approved team. The candidate model version and payload bounds depend on approved entitlement, target runtime and controlled measurement. [Responses, Create new response](https://docs.x.ai/developers/rest-api-reference/inference/responses), [Response structure and Chat Completions comparison](https://docs.x.ai/developers/model-capabilities/text/comparison#response-structure), [Callout Limits and Limitations](https://developer.salesforce.com/docs/platform/apex-dev/references/apex-dev/apex-callouts-timeouts.html), [API Security FAQ](https://docs.x.ai/developers/faq/security).
