# Passes

The working directory held no product code, so there was no existing behaviour to read; the spec treats the product as a web application with users, roles (`admin`, `member`), a sign-in, a user list and an outside email service, and says where it assumes so.

## Pass 1 — the ground
Added U-1 to U-11: the ordinary import, the template, bad rows and the fix-and-retry loop, unreadable files, following and reviewing an import, the invited user's side, resending, non-admins, double submission and concurrent admins, failure and restart, and the operator. Added the clauses each plainly needs: access (C-1 to C-3), file format and file-level refusals (C-6 to C-23), row rules and error reporting (C-24 to C-37), the created user (C-38 to C-41), import lifecycle (C-42 to C-50), history (C-57 to C-59), invitations (C-60 to C-67).

## Pass 2 — what each sentence takes for granted
"Admins": who counts as one, and what happens to everyone else and to a signed-out visitor (C-2, C-3), and a demotion between upload and creation (C-5). "CSV": encoding, delimiter, quoting, line endings, header, column identification, optional and extra columns, blank lines, wrong field counts (C-7 to C-17). "Bulk-create users": what a user needs (email, name, role; C-25 to C-29), what makes it unique (C-30, C-31 with every user state that counts), how they can sign in at all (invitation, C-60 to C-63, C-79, C-83, C-84), and what the admin sees back. Every dimension is listed in full: roles (2), user states (3), import statuses (5), file-level reasons (9), row-level reasons (8), failed reasons (3), delivery states (3), request kinds refused to non-admins (6), control-character ranges. Every limit has a number: 5 MiB, 5,000 rows, 100-character names, 64 / 254-character emails, 10 minutes, 60 seconds, 5 seconds, 90 days, 7 days, 3 attempts, 1 hour, 25 per page, 255-character file name.

## Pass 3 — where the parts meet
Import against import (same admin: C-51; different admins: C-52, C-53), import against a hand-made user (C-54), the same file twice (C-55), double click (C-81), restart mid-import (C-49), timeout against commit (C-47), status against reality (C-50), import against the rest of the product (C-72), an invitation against deactivation, expiry, a second use and a resend (C-62, C-67), the uploader being demoted during processing (C-5) or later (C-57), retention against users' attribution (C-59), email delay against import status (C-82).

## Pass 4 — the runtime's own rules
Web request time limits force an asynchronous import (C-42, C-45, C-47). Proxy request-body caps force the 5 MiB path to be checked end to end (C-69; the proxy figure is a deployment fact, not confirmed here). The browser cookie model forces the anti-forgery check (C-4). HTTPS in production (C-70). The email service's rate limits and failures force asynchronous retried sending (C-65, C-66, C-85; the provider's limit is unconfirmed and said so). Single-transaction writes must not lock the rest of the product (C-72). Logs must not hold personal data (C-71). Limits are fixed constants, not settings (C-68). A seat or licence limit on users was considered and not specified, since nothing says the product has one.

## Pass 5 — what must not change, what must never happen
Existing users never changed by an import (C-73). One rule set for every route that creates users (C-74, C-84). Others cannot see imports or their users (C-75). No duplicate users under any interleaving (C-53, C-54). No half-imports visible (C-40, C-50). No email for users that were rolled back (C-60). No passwords in files, emails or logs (C-39, C-61, C-71). Cell contents stay inert (C-41, C-80). Invited users' addresses not revealed at sign-in (C-79). No bulk undo, stated as a choice (C-76). Accessibility (C-77).

## Pass 6 — grind
Read the whole specification as the builder who will be blamed. Found and fixed: clauses that were really two (BOM beside encoding, password column beside invited sign-in, escaping beside export, submit control beside the one-active-import rule, email timing beside the email count, link entropy beside link validity, password rules beside activation, the 1-hour target beside retries) — split, the new halves appended as C-78 to C-85; an Observable that could not be observed ("retained nowhere", C-56) — rewritten to what a person can see; numeric cross-references inside Observables (C-58, C-67, C-74, C-69) — replaced by the values; a state with no end (import records, C-59; invitation delivery, C-85; imports stuck in `queued`, C-47) — given an end; several file-level problems at once with no rule (C-86); the uploader's identity after demotion (C-57); users' attribution after record expiry (C-59). Also repaired six clause bodies whose last line had been joined to the Source line by my own edits.

## Pass 7 — the pass that found nothing more
Read the specification again from the top for: Observables that cannot be observed; words two readers would read differently (checked "row", "whitespace", "existing user", "admin", "blank line", all defined in the terms paragraph or in their clause); numbers implied but not written (none found; every limit has a value); a use case without an unhappy path (every use case has one or is itself one); state with no end; silent decisions (every gap-filling rule is marked `choice`); clauses that are two (none left that join two independent behaviours; clauses that list members of one dimension were kept whole on purpose); numbering (C-1 to C-86 and U-1 to U-11, no gaps, one Source per entry). It added nothing a builder would otherwise have got wrong, so grinding stopped here.

Decisions made for the requester, all marked `choice` in the spec: all-or-nothing import (C-36), asynchronous processing with a status (C-42 to C-47), invitation email instead of passwords (C-60 to C-63), the optional `role` column with `member` and `admin` (C-12, C-29), the limits (C-20, C-21, C-27, C-68), no preview step, no bulk undo (C-76), history visible to all admins (C-57).
