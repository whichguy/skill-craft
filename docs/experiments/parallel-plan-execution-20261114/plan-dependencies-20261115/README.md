# How other tools put dependencies in code plans and bring the work back (2026-11-15)

Journal: [R8](../../../shiploop-parallel-execution-journal.md), with the work-item count of [E16](../../../shiploop-parallel-execution-journal.md). The owner asked how other skills and harnesses handle
dependencies in plans for writing software, how Claude Code and Codex run workers, what the current research says, and how that compares with ShipLoop; the owner's reading was that
parallel work pays mainly for completely independent features merged into one repository, and that the fan-in (a coordinator that checks every worker is done and brings everything back to one branch)
matters as much as the fan-out.

## What I checked myself, and what I did not

Checked against the primary page or file (downloaded 2026-11-15, then searched for the passage):

- Claude Code: five documentation pages (agent teams, commands, workflows, worktrees, sub-agents). The `/batch` description (5 to 30 independent units, a worktree and a pull request per unit); the shared task list ("shows as blocked", teammates do not self-claim a blocked task, file-locked claiming, automatic unblocking); "Two teammates editing the same file leads to overwrites"; the workflow limits (16 concurrent agents, 4,096 items a call, 1,000 agents a run); the worktree base rule and the cleanup sweep. The words "merge queue", "integration branch", "merge back" and "rebase" occur in none of the five pages.
- Anthropic: the C-compiler post (task locks as files in `current_tasks/`, "Merge conflicts are frequent", agents all stuck on one kernel bug until a GCC oracle split the work, "the task verifier is nearly perfect"), the January 2026 multi-agent post ("The primary benefit of parallelization is thoroughness, not speed", 3 to 10 times the tokens, split only "when context can be truly isolated") and the June 2025 research-system post ("most coding tasks involve fewer truly parallelizable tasks than research").
- Codex source (openai/codex main, files downloaded): `update_plan` takes `step` and `status` only (`deny_unknown_fields`, at most one `in_progress`); the sub-agent tool text ("each delegated task has a disjoint write set"); a child takes its cwd from the parent turn.
- ShipLoop's repository: In Parallel's `contract.md` (independent tasks, disjoint exact write sets, dependent graphs excluded, one delivery that preserves HEAD and the index, an unknown launch is never retryable) and Plan Dispatcher's `protocol.md` (the dispatcher owns acceptance, integration, settlement and dependency release; the example graph's join task).
- Other tools' own pages: Kiro's blog ("Tasks that touch the same files are never run in parallel"), Spec Kit's tasks template (`[P]`: different files, no dependencies), CCPM's README (`depends_on`, `parallel`, `conflicts_with`), Cursor's "scaling agents" post (locks: twenty agents slowed to the throughput of two or three; optimistic concurrency made agents risk-averse), GitHub's `/fleet` post ("the last one to finish wins—silently"), Symphony's SPEC (`blocked_by` is best-effort) and land skill (merges one pull request at a time), Gas Town's `internal/refinery/engineer.go` (a merge queue with `assign_back` or `auto_rebase`, gates before the merge and after the squash on "the actual combined code", batch-then-bisect).
- Papers: 21 arXiv identifiers exist with titles that match the roles the reports give them (listed in the journal). Read in full or in the abstract: CAID (2603.21489; its limitations section says wall-clock runtime "is not substantially reduced despite parallel execution" because "integration remains sequential and test-gated"), Li et al. (2610.10263; "Mean runtime increases for all three agents overall and in 14 of the 15 agent-benchmark combinations", 27.8 against 17.5 minutes a task for Claude Code on SWE-bench Verified, concurrent faster in 102 of 366 co-solved cases), CooperBench, Co-Coder, STORM, Passes Alone, ParallACT, Claim Plane (abstracts); Colyer's summary of Uber's SubmitQueue (mainline green 52% of one week, 40% chance of a problem at 16 concurrent changes).

Not checked: the numbers inside papers other than the passages above (Co-Coder's density correlation, DeLM's 2.49 times, AgentRoom's times, Mieczkowski's speedups and the self-claim comparison, CAID's per-row slowdowns and its MiniMax and Claude gains, STORM's baseline scores, merge-conflict base rates); Gas Town's throughput limit and Yegge's change of gating (secondary articles); the Task Master, BMAD, Superpowers and CCPM issue threads; Factory, Devin and Augment's mechanisms (vendor accounts); the Codex app and cloud pages (the sub-agent read them; the docs moved and one host returned 403 to it); Cline's `/team` source and Kiro Crew's task runner; any version-by-version limit.
