APPENDIX: WHAT THE OWNER MEASURED (2026-11-14; read-only copies of the evidence are under /Users/dadleet/src/skill-craft/docs/experiments/parallel-plan-execution-20261114/ and the journal /Users/dadleet/src/skill-craft/docs/shiploop-parallel-execution-journal.md; the per-host recipes the owner's skill uses are /Users/dadleet/src/skill-craft/skills/ask-agent/references/host-capabilities.md)
- Hosts and models, headless, one model per host: Claude Code 2.1.325 with Sonnet 5.5 at high; Codex CLI 0.169.0 with gpt-6.1-sol at medium; Grok Build 1.0.77 with grok-4.6 at xhigh. Each worker is a native sub-agent with a fresh context (Claude Agent/Task tool, Codex spawn_agent and wait_agent, Grok spawn_subagent in the background). A script (the "kit") owns the ready set; a worker may start a task only after the script says it is ready.
- Fixture: five scripted tasks, T1 to T4 independent and T5 joining them. Arm A0: the parent does all tasks itself in one context. Arm A3: one fresh native sub-agent per ready task, up to the host's capacity. A "settle" dial S adds S seconds of work inside every task (S = 0 gives 5 to 15 s tasks). Whole run = launch to exit.
- Whole-run ratio A3 / A0 (one trial per cell, n = 1, so treat small differences as noise): at S = 0 (5 to 15 s tasks) 1.22 Claude, 1.18 Grok, 1.10 Codex (fan-out LOST); at S = 30: 0.55, 0.63, 0.75; at S = 90: 0.44, 0.52, 0.69. Fixed cost outside the work phase (A3 minus A0): about 21 s Claude, 43 s Grok, 27 s Codex, roughly constant as tasks grow. Where the fixed cost goes: on Claude and Grok the parent issues all the spawns in one model call, and on Grok the host then starts the children in turn (spawn phase about 22 s); Codex issues one spawn per model call and has four concurrent agents including the parent, so three workers; its parent polled wait_agent in 10 s slices until told to wait up to two minutes (12 polls fell to 3).
- Break-even per-task time = overhead / (independent tasks minus rounds): about 7 s (Claude), 14 s (Grok), 13 s (Codex, three slots). Below that fan-out loses; the pilot's tasks sat at or just under it.
- Writing code, not just thinking: a second fixture of five writers at S = 30, each in its own git worktree with a script merging in completion order. Whole run A3 / A0: 0.50 Claude, 0.72 Grok, 0.86 Codex. The isolation and merge cost was about 1 s of script time and 0 to 11 s of whole run. A deliberate same-file conflict cost about one task round (+54 s Claude, +61 s Grok): it was detected, aborted, retried from the updated main and always ended valid. On Codex three slots hid the conflict (capacity can hide a plan defect).
- Cost: Claude fan-out used 1.4x to 3.5x the dollars of the single context; Grok about 1x; Codex 1.6x to 2.6x the tokens (its parent keeps polling). Claude's parent context grew to 0.73x of the single-context run, not the 0.24x first computed (a scorer bug: it read only the last of three result events).
- What the harness text could not change: wording per host did not change how spawns are issued; a sub-agent cannot tell from its environment that it is one; environment variable names must be matched exactly (a plugin's variables leak into other hosts' sessions).
- The owner's real unit of work: a census of 928 recorded plans from this harness found 922 record dependencies; 600 (65%) are single-step; only 92 (10%) have an independent pair; 51% of independent pairs that declare their files overlap on files; the median step takes 154 s (p25 116, p75 212); the time-weighted ideal saving from perfect step-level parallelism is 11.6% overall and 20.8% across plans with two or more steps. Earlier the owner's harness did run independent steps in parallel and retired that for reasons of isolation and rule conflicts, never having measured the gain.
- NOT measured: a real repository with semantic (not textual) conflicts, a commit stage or a clean checkout per worker, eight workers, unattended recovery of a lost worker, n >= 3 per cell, token scaling with task length, provider rate limits, prompt-cache effects.
