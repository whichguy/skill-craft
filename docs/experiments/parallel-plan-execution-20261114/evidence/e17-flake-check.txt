Reading: every tree hangs sometimes on this loaded machine: the pristine base rarely (one event in 340 runs), the two delivered trees at about 1 to 2 in 100, and the Codex tree cannot be told from the valid Claude tree (p = 0.40). At 1.2% to 1.7% a tree, a single once-only check over the twelve delivered trees of the oracle pass
would see at least one hang with a chance of about 13% to 19%, and it saw one. So the registered verdict is a weak statement about the Codex delivery (a statement that its suite can hang, as a valid Claude tree's can), and the oracle's once-only whole-tree check has a few per cent chance of failing any valid delivery on this machine.
Known cause family (read before this file was written, in the history): 26728eddd587930f5da3f6600e5d7ab4017d8acc measured that 32 of 928 concurrent `node --test` runs of this base failed (3.4%), 19 in a reset and 13 in a wrong answer, and traced it to the base's tests starting a server with listen(0) (the IPv6 wildcard) while the client dials 127.0.0.1,

What differs here: the events above are hangs (7 of 8), where the collision measurement records resets and wrong answers (8c5b4d4e's item 3 notes separately that at a load average of 35 to 98 the base's node tests also time out, not attributed to the collision); one wrong answer did appear in the earlier 30-run loop (the base test "creates an open ticket and answers 201 with it",
the signature of another server answering). Whether the hangs are the same collision (a client connected to a server that never answers) is likely and not proven: no raw TAP was kept.
