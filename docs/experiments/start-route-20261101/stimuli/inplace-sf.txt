The game: the computer places a fleet on a 10x10 grid (rows and columns 0 to 9) and the player fires at it. The fleet is the standard one: `carrier` (5 cells), `battleship` (4), `cruiser` (3), `submarine` (3) and `destroyer` (2); every ship lies straight along one row or one column, entirely inside the grid, and no two ships share a cell. A ship is sunk when all of its cells have been hit, and the game is over when the last ship is sunk. `SLNvHo250fEngine` is a public class with static methods only; a game is a JSON string. `newGame(Integer seed)` returns a new game whose fleet is placed at random from the seed: the same seed always gives the same fleet, in any transaction and however many games came before, and two different seeds give different fleets (Apex has no seeded random number generator, so write a small one). `fire(String game, Integer row, Integer col)` returns the game after one shot at that cell. The game JSON is an object with at least these keys: `shots` (the number of shots fired so far), `shipsLeft` (the number of ships not yet sunk), `gameOver` (`false` until the shot that sinks the last ship, `true` from that shot on) and `lastShot`, which is `null` in a new game and after a shot is an object `{"row": r, "col": c, "result": "miss" | "hit" | "sunk", "ship": name, "size": cells}`: `result` is `sunk` (not `hit`) for the shot that sinks a ship, and `ship` and `size` give that ship's name and number of cells on that shot only (they are `null` on a miss or a hit). Where the ships are and which cells were fired at is up to you; the board must not show a ship cell before it is hit. A shot at a cell that was already fired at, or with a row or a column outside 0 to 9, throws `SLNvHo250fEngine.InvalidShotException` (a public exception class you define inside `SLNvHo250fEngine`). After the game is over, a shot at a cell not yet fired at is still accepted: it is a `miss` and `gameOver` stays `true`. `SLNvHo250fController` has `@AuraEnabled public static` methods `newGame(Integer seed)` and `fire(String game, Integer row, Integer col)`, each returning the game JSON as a `String`, so that the board and the grader can call them. The grader calls `SLNvHo250fController` only with valid shots and calls `SLNvHo250fEngine.fire` directly for an invalid one, so the controller may report an invalid shot however suits the board (for example by throwing an `AuraHandledException`). The component `slNvHo250fBoard` renders the 10x10 grid, fires at a cell when a person clicks it, shows hits, misses and sunk ships, the number of shots fired and of ships left, says when the game is over and has a New game button. It calls `SLNvHo250fController` and renders what comes back.
