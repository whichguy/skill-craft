- The parent's `sleep` (54.1 min) and `wait_agent` (28.5 min) polling happened while the worker was busy. It is off the critical path, but its 430 polling responses cost 117k output tokens.
- Latency model, 2,918 responses, R² 0.93:
  - latency = 1.9 s + 18.1 s per 1k output tokens (about 55 tokens per second) + 0.006 s per 1k cached input tokens.
  - Output decode is 89.1% of model time, fixed per call 7.6%, input context 3.3%.
  - Responses with latency above fitted decode time total only 23 min over 5 responses (one 12 min stall, likely web search).
- Volumes:
  - 3.54M output tokens, of which 2.04M reasoning (57.6%).
  - 392.7M input tokens, 97.1% cached.
  - 40 context compactions took 44.0 min (3.8%), inside the model time above.
- What the output is:
  - 157 responses with a large authoring call (more than 6k characters) are 21.0% of output tokens.
  - 486 medium-call responses are 26.7%.
  - 2,276 small or message-only responses are 52.3% of output tokens (1.245M reasoning tokens, about 547 per response, about 10 s each). That is about 376 min, or 32.5% of the wall clock, spent reasoning before short commands. This is the effort-max signature.
- Wall-clock shares by loop role (minutes): Improve pass 1 152.5, Improve later passes 135.8, Backchain step-plan passes 107.7, Backchain plan passes 105.7, everything else 656.8.
- Evidence that effort and model, not the loops, drive the baseline:
  - Stages with no loop were slow on Luna max too: discovery 12.7 min and research 24.7.
  - The earlier batch-1121 entry has discovery and research 4 to 10 times Grok's time.
  - Sonnet did the same graph in about 9 to 19 min.
  - The in-progress 1.20.0 run's research took 8.4 min against 24.7 here. That shows large run-to-run variance for an identical model and effort (n=1 each).
- What single-pass will not fix: about 75% of the run (first-pass loop work, stage producers, build, tests) plus effort-max reasoning. The effect of lower effort on this graph is unmeasured; no same-case run at lower effort exists on 1.16.x.
- Context and prompt reading costs about 7% (compaction 3.8% + cached-input latency 3.3%). Cutting bytes of guidance helps by that much at most. Cutting obligations that induce output helps more.

6. OWNER RULES AND SPEC: WHERE THEY CONFLICT
---------------------------------------------------------------------
- SPEC S-10 says "Quality, test and review loops (Until Loop) run until a stated, checkable condition holds ... no iteration cap." The Backchain plan loop is such a review loop. A one-pass default is a different stated exit condition, not a numeric cap, but it needs a SPEC carve-out recorded as an owner decision dated 2026-10-04.
  - The memory notes "no cap, no revise/blocked for running long" apply to quality and test loops. They are textually broader than the owner's request and should be narrowed in the same record.
  - S-10 also says "a frozen contract the script writes." The Backchain contract is written by the model (glue). The loop-start contract is model-built; ShipLoop writes only the Improve contract.
- "Steps iterate until a stated check confirms each exit criterion" and the 80% postulate.
  - A single model pass leaves a residual. Evidence here: pass 1 found the 3 structural findings; later passes found only minor ones.
  - The owner's "test pass is the evidence" note favours replacing the model's confirmation passes with a script check. `backchain-check` already exists (6a997a02, record-only) and caught D1, which four model passes missed.
- "Enterprise rigour is standard." Per-outcome confirmations and source identity stay in pass 1. Passes 2..N were redundancy more than rigour, for the plan loop.
- "Verbose prompts over size bounds" against "prompts concise, aimed at meaningful change." Measured: bytes of input are about 3% of latency, so trimming text will not speed Luna. Reducing what must be produced will.
- The owner's explicit override covers Backchain passes. Single-pass Improve is not covered by the request and would also need a carve-out.

7. FACTS THAT AFFECT HOW SINGLE-PASS WOULD BE BUILT
---------------------------------------------------------------------
- [M] Runtime gate semantics, tested in scratch with the vendored `skills/improve/runtime/until-loop/scripts/until_loop_ephemeral.py`:
  - `required_trivial_reviews: 0` completes after one non-trivial pass whose `exit_assessment` is satisfied.
  - `1` needs two passes after a non-trivial first pass. `2` needs three.
  - The runtime default is 0.
- [M] In the Luna Backchain loops the model reported `exit_assessment: unsatisfied` on every pass until the second clean one. Plan passes 1 to 5 were non-trivial/unsatisfied, pass 6 trivial/unsatisfied, pass 7 trivial/satisfied. Step-plan passes 1 and 2 were non-trivial/unsatisfied.
  - The cause is the exit condition text, copied from `skills/backchain/references/convergence.md` ("Frozen plan-only child contract"). It demands two distinct clean reviews and sets `required_trivial_reviews: 2`.
  - So a one-pass default has to change both the gate and the exit-condition wording.
- Files that state the two-review rule:
  - `skills/shiploop/scripts/shiploop_prompts.py::_backchain_guidance`
  - `skills/shiploop/references/backchain-planning.md` (Source-aware native caller)
  - `skills/shiploop/SKILL.md` (Source-aware Backchain selection)
  - `skills/backchain/references/convergence.md`
  - `skills/backchain/SKILL.md` (description and a section on the two consecutive reviews)
  - Pins: `test/shiploop-navigator-dry-run.test.py` (expects `required_trivial_reviews: 2` in the plan packet) and `test/shiploop-navigator-contract.test.py`.
- Nothing refuses a different Backchain contract. `backchain-check` is record-only. Improve is script-owned: `shiploop_navigator.py` passes `required_trivial_reviews=2` through `loop_contract.contract`, so that default is easy to enforce.
- Backchain is already optional ("may request" in `backchain-planning.md`).
  - There is no flag today.
  - In 1.20.0, `BACKCHAIN_NATIVE_CALLS` holds only `plan`; spec, step-plan, carry-forward and product-acceptance get the read-only one-pass audit route. Commit 3592b195 states its live effect on Luna is unverified.
