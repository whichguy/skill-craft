Build a command-line tool report.py (Python 3, standard library only) that summarises sales records. Usage: `python3 report.py FILE [FILE ...]`. Each FILE is CSV with the header row `date,region,product,units,unit_price`; units is a non-negative integer and unit_price a non-negative decimal. Print one JSON object to stdout: {"rows": the number of valid rows, "revenue": the sum of units * unit_price rounded to 2 decimals, "by_region": revenue per region rounded to 2 decimals, "by_product": total units per product}. A row with the wrong number of columns, or a non-numeric or negative units or unit_price, is skipped and reported on stderr as `FILE:LINE: <reason>` (the header is line 1), and the exit code is then 2; otherwise it is 0. A file that cannot be read prints an error on stderr without a traceback, prints nothing on stdout and exits 1. A file with only a header contributes nothing. Cover the behaviour with unittest tests that run with `python3 -m unittest`.

Requirement approved for a later delivery, outside this delivery: an optional --region REGION selector will match exact, case-sensitive region text, including the empty string. Selection affects all aggregations: rows, revenue, by_region and by_product count only selected valid rows, and unselected regions/products have no entries. With no selected valid rows, return rows 0, revenue 0 and empty by_region and by_product objects. All input rows must still be validated; an invalid row outside the selection still produces the prescribed diagnostic and exit 2, and an unreadable file still produces no stdout and exits 1. The supported future invocation is python3 report.py [--region REGION] FILE [FILE ...], with the optional flag once before the files; a missing flag value is a usage error with stderr, no stdout and exit 2. Other flag placements and repeated flags are outside this scenario.

This delivery's outcome for that future requirement is that it is recorded in the project's living knowledge and clearly marked not implemented. Do not implement --region in this delivery. Deliver and verify the base report above; preserve the approved rule for the later request.
