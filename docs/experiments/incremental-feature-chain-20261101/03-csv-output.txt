Add an optional CSV output capability to the existing report tool: --format json|csv, default json. JSON mode, including invocation without --format, keeps the current output contract. CSV mode writes a header region,revenue followed by one row for each region represented in the selected valid rows, ordered by Python string order (Unicode code points, case-sensitive); revenue has exactly two digits after the decimal point. Use CSV quoting so commas, quotes and newlines in region names round-trip. With no selected valid rows, write only the header.

The existing region selector applies to either output format. The accepted validation, error-reporting and exit-code contracts continue to apply: invalid rows outside the selection still produce diagnostics, the chosen output format still reports valid selected rows with exit 2, and an unreadable file produces no stdout and exits 1. Supported usage is python3 report.py [--region REGION] [--format json|csv] FILE [FILE ...]. Each option may appear once, in either order before the files. Missing option values and unsupported format values produce a usage error on stderr, no stdout and exit 2. Other flag placements and repeated flags are outside this scenario.

Keep the existing report.py entrypoint, standard-library-only constraint and earlier behavior. Add and execute tests for the new capability and its interaction with the filter, and reconcile the living specification and architecture with the delivered implementation.
