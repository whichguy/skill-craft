# Log4brains baseline architecture

As of 17e32021a8c5. This file records the architecture as it is and proposes no change. Decision records kept by the repository are referenced by title and status only, never copied; each of the nineteen records maps to one decision below (AD-1 to AD-19). The other decisions (AD-20 to AD-33) are structural choices that are not recorded as decision records. AD-4 and AD-10 are superseded and listed under Superseded.

## Stack

- Language and runtime: TypeScript 4 in strict mode compiled for ES2018; Node.js 18 or newer is required, the version file pins 22, and CI tests 18.x, 20.x and 22.x. (`package.json` `engines`; `tsconfig.json` `strict`; `.github/supported_nodejs_versions.json` `versions`)
- Repository layout: Yarn workspaces with Lerna 5 in fixed-version mode, six packages all at version 1.1.0. (`package.json` `workspaces`; `lerna.json` `useWorkspaces`)
- Build: microbundle per package, emitting CommonJS and ES module bundles; the web package also runs a Next.js build and export. (`packages/cli/package.json` `microbundle`; `packages/web/package.json` `build:nextjs`)
- Command line: commander 6 for parsing; chalk, cli-table3, ora and inquirer for output and prompts; execa to start child processes. (`packages/cli-common/package.json` `cli-table3`; `packages/cli/package.json` `commander`)
- Core: awilix for dependency injection, Joi and yaml for the configuration file, simple-git for history, markdown-it with cheerio for markdown, moment-timezone for dates, chokidar for file watching. (`packages/core/package.json` `awilix`)
- Web UI: Next.js 10.2 with React 17, Material-UI 4, lunr for search and socket.io for live reload. (`packages/web/package.json` `next`)
- Quality tooling: ESLint 7 (Airbnb TypeScript, sonarjs, promise, jest and react rules) with Prettier through prettier-eslint, Jest 26 with ts-jest, husky 4 with lint-staged, commitlint. (`package.json` `lint-staged`; `.eslintrc.js` `airbnb-typescript`)
- Delivery: GitHub Actions, npm publishing through Lerna, a Docker Hub image and a GitHub Pages site for the project's own ADRs. (`.github/workflows/on-merge-to-develop.yml` `lerna publish`; `docker/Makedockfile.conf` `MDF_REPOSITORY`)

## Structure

- (root): workspace manifest, shared TypeScript, ESLint, Jest and commit-message configuration, README, CONTRIBUTING, and the project's own ADR configuration. (`package.json` `workspaces`)
- packages/cli: the adr new and adr list commands. (`packages/cli/src/cli.ts` `createCli`)
- packages/cli-common: terminal helper shared by all command lines (output, prompts, spinner, tables), the console capturer and the exit marker. (`packages/cli-common/src/index.ts` `FailureExit`)
- packages/global-cli: the log4brains executable, made of a launcher script, the composition of the commands of cli, init and web, and the top-level error handler. (`packages/global-cli/src/cli.ts` `createGlobalCli`)
- packages/core: the ADR domain model, queries and commands with their handlers, repositories, configuration, dependency wiring and the public facade class; laid out as adr/domain, adr/application, adr/infrastructure and infrastructure/api, config, di, buses and file-watcher. (`packages/core/src/infrastructure/api/Log4brains.ts` `Log4brains`)
- packages/init: the init command, which writes the configuration file, copies template, index and README, and creates the starter ADRs by running the executable. (`packages/init/src/commands/InitCommand.ts` `InitCommand`)
- packages/web: the preview and build commands and the Next.js app that renders ADRs, with pages, scenes, layouts and components. (`packages/web/cli/cli.ts` `createWebCli`)
- e2e-tests: a Node script that drives the installed executable in a temporary folder through version, init, adr new, adr list --raw and build. (`e2e-tests/e2e-launcher.js` `usingTempDir`)
- docker: the image definition (entrypoint log4brains) and a Makefile that builds and pushes it. (`docker/Dockerfile` `ENTRYPOINT`)
- scripts: the manual stable-release script and a script that waits until an npm version is published. (`scripts/release.sh` `lerna`)
- .github: workflows for pull request checks, alpha releases on merge, post-release end-to-end tests, Docker and ADR publication and two weekly checks, plus issue templates. (`.github/workflows/pull-request-checks.yml` `quality-checks`)
- .vscode: editor settings that format on save with prettier-eslint. (`.vscode/settings.json` `formatOnSave`)
- docs: the project's own ADRs, with an index, a template and a README; more records sit in packages/core/docs/adr and packages/web/docs/adr. (`.log4brains.yml` `adrFolder`)

## Conventions

- Style is enforced by ESLint (Airbnb TypeScript plus sonarjs, promise, jest and react rules) and Prettier through prettier-eslint, with zero warnings allowed per package; the editor settings are LF line ends, UTF-8, two-space indent and a final newline. (`.eslintrc.js` `airbnb-typescript`; `packages/cli/package.json` `lint`; `.editorconfig` `indent_size`)
- Existing sources use double quotes, semicolons, no trailing commas and named exports only; a default export is allowed only in Next.js pages and API routes. (`packages/cli/src/commands/ListCommand.ts` `ListCommand`; `.eslintrc.js` `import/no-default-export`; `packages/web/nextjs/.eslintrc.js` `import/no-default-export`)
- A rule that exists because of a decision record carries an @adr comment naming the record. (`.eslintrc.js` `@adr`)
- Commit messages follow Conventional Commits, checked by commitlint in a commit-msg hook; the pre-commit hook runs lint-staged (ESLint on ts and tsx, prettier-eslint on js, ts, json and md files) and the TypeScript check. (`commitlint.config.js` `config-conventional`; `package.json` `husky`)
- Work flow: branch from develop, rebase before the pull request, open it against develop, squash and merge; a pull request without tests is rejected when tests apply. (`CONTRIBUTING.md:94`; `CONTRIBUTING.md:98`; `CONTRIBUTING.md:90`)
- CI gates on every pull request: frozen install, build, the format check (Prettier over every md file too) and lint; tests of the changed packages on Ubuntu, Windows and macOS at the LTS Node and on the current Node (best effort); then the end-to-end script against a globally linked install. (`.github/workflows/reusable-quality-checks.yml` `yarn format`; `.github/workflows/pull-request-checks.yml` `tests-LTS-per-os`; `.github/workflows/reusable-tests.yml` `yarn e2e`)
- Tests: Jest with ts-jest; unit tests sit beside the code as .test.ts files; the core also has integration tests with snapshots over fixture projects; packages cli and cli-common have no test script, the init integration tests are switched off, and the only automated check of adr list is the end-to-end script, which asserts on --raw output. (`jest.config.base.js` `ts-jest`; `packages/core/integration-tests/ro.test.ts` "all"; `packages/cli/package.json` `scripts`; `packages/init/integration-tests/init.test.ts` `Tests deactivated`)
- How a command like adr list is built (the closest existing features are the --raw option of adr list and the --quiet option of adr new): one class per command with a Deps type, an exported options type and an execute method; registration in the command-line factory with commander options given as flags, description and default, and an action that builds the class and calls execute inside the known-error wrapper; output only through the console helper; data only from the core facade. (`packages/cli/src/commands/ListCommand.ts` `ListCommandOpts`; `packages/cli/src/cli.ts` `createCli`; `packages/cli/src/commands/NewCommand.ts` `quiet`)
- Script-oriented outputs that exist today: adr list --raw (comma-joined lines), adr new --quiet (the slug alone on standard output, read by init), and the JSON files written by build. (`packages/cli-common/src/AppConsole.ts` `printTable`; `packages/cli/src/commands/NewCommand.ts` `quiet`; `packages/init/src/commands/InitCommand.ts` `createAdr`)
- Domain errors are thrown as a short sentence plus optional details, and callers identify them by the sentence. (`packages/core/src/domain/Log4brainsError.ts` `Log4brainsError`; `packages/cli/src/cli.ts` `execWithErrorHandler`)
- Documentation: architecture decisions are ADRs in docs/adr and packages/core/docs/adr and packages/web/docs/adr; the changelogs are generated by Lerna and edited by hand at release; the README documents install, init, preview, adr new and CI recipes. (`.log4brains.yml` `adrFolder`; `scripts/release.sh` `CHANGELOG.md`)
- Files that look like ADRs but are not decisions of this project: the fixture projects under packages/core/integration-tests and the two starter ADRs in packages/init/assets, which init writes into users' projects. (`packages/core/integration-tests/ro-project/.log4brains.yml` `adrFolder`; `packages/init/src/commands/InitCommand.ts` `createAdr`)

## Interfaces and boundaries

- Process boundary: a user or script runs the log4brains launcher, which starts the bundled command line as a child process with a Node option for the legacy OpenSSL provider; standard streams are inherited and the launcher contains no code that forwards the child's exit status (R-9 records the inferred consequence). (`packages/global-cli/src/log4brains` `spawn`; `packages/global-cli/package.json` `bin`)
- Package graph: global-cli depends on cli, cli-common, core, init and web at exact versions; cli depends on cli-common and core; web depends on cli-common and core; init depends on cli-common and runs the executable as a child process instead of importing cli. (`packages/global-cli/package.json` `dependencies`; `packages/cli/package.json` `dependencies`; `packages/web/package.json` `dependencies`; `packages/init/package.json` `dependencies`)
- Command composition: each of cli, init and web exports a factory returning a commander command; the global factory attaches their sub-commands to one program. (`packages/global-cli/src/cli.ts` `createGlobalCli`; `packages/init/src/cli.ts` `createInitCli`)
- Command line to core: only the facade class and its record types are used; the core also exports the domain error, the configuration type, the configuration-not-found error and the file watcher. (`packages/core/src/index.ts` `Log4brainsConfigNotFoundError`; `packages/core/src/infrastructure/api/Log4brains.ts` `Log4brains`)
- Inside the core: the facade dispatches queries and commands on buses to handlers; repositories implement application interfaces; the container registers by name every export of the query-handler, command-handler and repository barrel files, so a new handler must be exported from its barrel to be found. (`packages/core/src/infrastructure/di/buildContainer.ts` `buildContainer`; `packages/core/src/adr/application/query-handlers/index.ts` `SearchAdrsQueryHandler`; `packages/core/src/infrastructure/buses/QueryBus.ts` `dispatch`)
- External programs and services: the git program through simple-git for history and user name (absent Git falls back to file times and Anonymous); the editor named by the VISUAL or EDITOR variable and the operating-system opener for adr new; npm, GitHub, Docker Hub and GitHub Pages in CI and release. (`packages/core/src/adr/infrastructure/repositories/AdrRepository.ts` `isGitAvailable`; `packages/core/src/infrastructure/api/Log4brains.ts` `openAdrInEditor`)
- Files read and written: the configuration file .log4brains.yml; ADR markdown files made of a title heading and a metadata bullet list (Status, Deciders, Date, Tags); a template file in each ADR folder; the build output folder .log4brains/out. (`docs/adr/template.md:3`; `packages/core/src/infrastructure/config/builders.ts` `configFilename`)
- Environment variables: LOG4BRAINS_CWD (starting folder), DEBUG (debug lines and stack traces), NODE_ENV (development enables traces and Next.js fast refresh); LOG4BRAINS_PHASE and NEXT_TELEMETRY_DISABLED are set or read internally by the web package. (`packages/cli/src/cli.ts` `LOG4BRAINS_CWD`; `packages/global-cli/src/index.ts` `DEBUG`; `packages/web/cli/commands/preview.ts` `NODE_ENV`)
- Data contracts shared between packages: the ADR record returned by the core (R-7) is consumed by the command line and the web package; the light projection (R-12) is produced inside the web package; the standard-output formats of adr list --raw and adr new --quiet are read by init and the end-to-end script. (`packages/web/nextjs/src/lib-shared/types.ts` `toAdr`; `packages/init/src/commands/InitCommand.ts` `adrListRes`)
