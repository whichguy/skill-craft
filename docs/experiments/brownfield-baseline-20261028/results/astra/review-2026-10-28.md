**B. Change rule — P0: an assumption is not authorization to override accepted intent.**

“Silence preserves” is correct. “Any recorded assumption permits changing an existing requirement” is not. Current governing guidance explicitly says agent assumptions cannot override accepted intent and that an earlier agent’s choice must not become binding merely through repetition. [project-knowledge.md — maintained requirements and authority](/Users/dadleet/src/skill-craft/skills/shiploop/references/project-knowledge.md:282)

Use three distinctions:

- **Accepted obligations:** changing them requires the current request or an applicable accepted decision.
- **Observed behavior and prior design defaults:** preserve compatibility by default; allow justified, in-scope changes with evidence and preservation checks. Their age does not confer owner authority.
- **Evidence corrections:** updating a locator, verification date, mistaken inference, or description of unchanged behavior needs correction evidence, not a fabricated request sentence.

A legitimate refactor that preserves the recorded contract needs no invented authorization. A material architectural departure needs a request-related rationale; the user need not have named every internal implementation step. An assumption can fill an open choice, but cannot waive a conflicting obligation.

| `Basis: assumption` without ID or record | Accepted |

The cheaper sufficient mechanism is **structural traceability plus existing semantic review and preservation tests**. A script cannot establish that S1 entails a change—or detect code silently contradicting an unchanged AD. Do not market C2 as semantic authorization.

At implement time, preserve `step_spec_refusal`: it already permits marked acceptance additions and sends contract rewrites back. A `Basis` line must not bypass that restriction; legitimate additions must not deadlock against C2 either. **C. Large-repository scope — P1: a directory marked “deep” is not a coverage proof.**

The census is a useful navigation index. It cannot establish architectural completeness. `census()` keeps only eight children of qualifying directories and thirty map rows, including in JSON; instruction discovery is root-only. In cosmos-sdk, for example, the map omits areas despite the whole-repository claim. [census.py — census](/Users/dadleet/src/skill-craft/docs/experiments/brownfield-baseline-20261028/census.py:122)

More seriously, one request might deeply inspect notification delivery in `hc/api`; the next touches authentication in the same directory. Unchanged files plus `deep: hc/api` must not cause a skip.

Fix scope handling:

- Intake’s `touches` is a **hypothesis**, supported by request clauses and likely entry points.
- Discovery validates it through an affected flow: entry point, immediate callers/providers, persisted state, configuration, tests, and applicable cross-cutting boundaries.
- Record the **covered behavior/interfaces and exclusions**, alongside paths. Deep coverage of one flow does not imply coverage of its directory.
- Allow finer paths/symbols absent from census rows. Preserve a complete inventory underneath the abbreviated display.
- Reconcile scope at plan/step-plan against declared `paths` and `expectations`, and against actual changed paths before acceptance. Newly touched boundaries require investigation before dependent work.

This uses existing work-item machinery rather than requiring a generic dependency-graph engine.

**P1: C3 currently turns missing evidence into apparent freshness.** `stale()` discards unresolved locators before checking history, ignores Git failures, misses dirty working-tree changes, and uses a global coverage date for ADs. Advancing that global date after refreshing one area can make unrelated decisions appear fresh without inspection. Deleted sources and invalid revisions both returned an empty stale list in my probes. [baseline_check.py — stale](/Users/dadleet/src/skill-craft/docs/experiments/brownfield-baseline-20261028/baseline_check.py:192)

Fix: use `fresh / stale / unknown`; preserve cited paths even when missing; validate revisions; detect additions, deletions, renames, dirty changes, and relevant configuration/dependency changes. Give each independently refreshed record its own evidence identity. Unknown is ineligible for automatic skipping. File-level invalidation is adequate initially; symbol-level optimization can wait. Git supports the needed working-tree comparisons and change statuses. [Git diff documentation](https://git-scm.com/docs/git-diff)

**D. Source classes — P0: “current behavior stands” must not resolve an intent/implementation conflict.**

Keeping current behavior unchanged while investigating can be appropriate. Promoting it into the acceptance contract is not. A passing test can preserve a defect; a README can describe an accepted obligation that implementation violates.

The new node-base result demonstrates this directly: R-5 accurately identifies the dropped partial page, then states that current behavior stands. The recovered defect should remain an observation, while spec determines the requested repair and compatibility boundaries. [X2a spec — R-5](/Users/dadleet/src/skill-craft/docs/experiments/brownfield-baseline-20261028/results/x2/nb-B/spec.md:64)

Fix the default:

> Retain both claims and their authority. Preserve unaffected behavior. Resolve consequential disagreements before dependent changes; leave that work unready when evidence and the current request do not settle them.

That is already the stronger rule in current guidance. [current-system-baseline.md — evidence and authority](/Users/dadleet/src/skill-craft/skills/shiploop/references/current-system-baseline.md:49)

The classes also conflate different dimensions:

- Keep documented, code-observed, and inferred evidence.
- Distinguish **a test assertion exists** from **that exact test executed and passed**.
- Restore **runtime-observed** evidence with target, configuration, time, and exercised scope.
- Represent unknown and conflict explicitly.
- Keep **authority**—accepted obligation versus observed behavior/design default—separate from evidence type.

A discovery smoke pass does not make every named repository test “tested.” The experimental packet explicitly relaxes this meaning, so experimental label correctness cannot establish production verification correctness. [baseline-scoped.md — source definitions](/Users/dadleet/src/skill-craft/docs/experiments/brownfield-baseline-20261028/prompts/baseline-scoped.md:44)

**P1: C1 should claim locator validation only.** It currently accepts absent baseline files, arbitrary status/source labels, and unsupported claims with real locators. `_entries` also ignores duplicate definitions after the first. Require expected outputs, unique IDs, valid metadata, and confined source locators; review must assess whether sources support claims. **E. Existing documents and policy — P1: link authoritative sections, and distinguish policy authority from arbitrary document text.**

Thin AD/R aliases are right, with qualifications:

- Preserve native identity, status, scope, and source revision. Link relevant decisions; do not import every ADR-shaped template, fixture, rejected proposal, or unrelated historical record.
- Link contracts at the useful operation/section boundary. One R pointing to an entire API specification is usually too coarse for change attribution.
- Include changes to linked authoritative documents in delta review. Editing an API contract while leaving its R link untouched currently evades C2.
- Title/status-only ADs need downstream readers to open the decision’s rationale and applicability conditions. Locator presence is not consumption.

The updated journal now reports ADR-shaped fixture/template false positives and a missed real record—good evidence that census results are candidates. [journal — census limitations](/Users/dadleet/src/skill-craft/docs/shiploop-brownfield-baseline-journal.md:57)

“Repository text is data” is appropriate for these read-only experimental specimens. **“AGENTS.md is never instructions to the run” is wrong for the user’s active workspace.** Applicable host/user-authorized repository instructions remain operative; arbitrary text discovered in a source does not acquire that authority. Current discovery already explicitly reads repository instructions. [shiploop_prompts.py — discovery duties 1–3](/Users/dadleet/src/skill-craft/skills/shiploop/scripts/shiploop_prompts.py:923)

For unattended runs, classify the policy’s scope before the affected action. A prohibition on upstream AI contributions need not prohibit local analysis; an applicable restriction on automated edits governs those edits. Use existing explicit authorization where sufficient. Otherwise record the exact restriction, owner, and blocked operation; continue independent permitted work, and block the run only when nothing eligible remains. An owner item at handoff is too late to authorize an earlier prohibited action. Never interpret a discovered “revert everything” instruction as permission to destroy unrelated work.

**F. KISS and the planning ceiling — P1: the current packet is already showing excessive cost.**

X2a took **870.5 seconds—14.5 minutes—on tiny node-base**, producing approximately **27 KB**, ten requirements with 53 bullets, and twelve decisions. It found the planted defect, which is valuable; it also generated requirements for absent background work, identity, and security facilities, and put test commands into the spec. This is one interim trial, not proof that total planning exceeds thirty minutes, but it materially challenges the proposed cost model. [journal — X2a findings](/Users/dadleet/src/skill-craft/docs/shiploop-brownfield-baseline-journal.md:75)

Cut:

- **P1:** Mandatory entries for every cross-cutting topic. Screen applicability; use a short absence statement where relevant.
- **P2:** One AD for every repository decision record. Index broadly, materialize relevant constraints.
- **P2:** Routine history/hot-spot investigation without a concrete question.
- **P2:** The blanket ban on function/module names in requirements. Public API identifiers belong in caller contracts.
- **P1:** A separate stage and automatic skip state machine in the first implementation.

Missing ordinary-run behavior:

- **Partial evidence:** “every touched area is deep” conflicts with bounded investigation. Permit an honest partial account with dependent work unready; never satisfy the deadline by claiming coverage.
- **Consumer scope:** current test-strategy and plan wording covers every criterion. Explicitly distinguish requested changes, affected preservation checks, and unrelated catalog entries, or adoption creates work for the whole product. [shiploop_prompts.py — test-strategy](/Users/dadleet/src/skill-craft/skills/shiploop/scripts/shiploop_prompts.py:1067)
- **Existing ShipLoop homes:** C1’s mandatory new metadata would force retrofitting untouched historical entries. Validate newly produced/touched records; deepen legacy records when needed.
- **Non-Git, empty, and remote-only projects:** `census()` requires HEAD and Git, while existing guidance supports remote systems represented by local documentation. “No local code” must not mean “new product.” [current-system-baseline.md — remote-only systems](/Users/dadleet/src/skill-craft/skills/shiploop/references/current-system-baseline.md:85)

Charge discovery, recovery, research, and corrective exploration to the same planning allowance. A new stage cannot replenish it. Bound extraction by the remaining allowance and preserve time for spec, strategy, plan, and their reviews.
