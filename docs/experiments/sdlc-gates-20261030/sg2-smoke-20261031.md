Status: **planned**. This section was committed before the first slice started; the results are added below it afterwards.

## Why a smoke, and what it is

Owner, 2026-10-31: "Yes, start smoke", after "Keep 4, pool SG2" and a recommendation to measure before spending on the 32
pooled slices (README.md, "Pooled reading"). Nothing of SG2 has run. Three things are unknown and matter before 27 more
Terra slices are paid for:
1. whether a slice runs end to end and scores on each of the four cases (a seeded tree, a final tree, `sg2_recall.py`);
2. minutes per slice for each route, for the bar's 1.5x cost bound and to plan the rest;
3. whether the inline review (arm A) already catches the planted defect almost every time. The pooled test sees a gain
   only below that: with B at 100%, its power is 0.86 at A = 60%, 0.42 at 75%, 0.25 at 80% and 0.03 at 90%
   (`sg2_pool_power.py`'s `pooled_power`).

## What runs

Five slices, each its own background task, sample 1:
- arm A (`delegation: inline`) on SG2-K1, SG2-K2, SG2-K3 and SG2-K4: four slices, one per case;
- arm B (`delegation: ask-agent`) on SG2-K1: one slice, so both routes' minutes are seen on one case.

Subject: Codex host, `gpt-6.1-terra` at `xhigh`, hooks on (`--dangerously-bypass-hook-trust`), the current default
(`hosts.HOST_DEFAULTS`, `RUN_DEFAULT_HOST`). Build: both arms are `4e9cf843fc191ed23d35e46487998646f5d8b3df` (release 1.23.2)
read-only, differing in delegation alone. Output: `~/e2e-runs/sg2-20261031`. Command per slice:
`python3 test/shiploop_e2e/experiment.py run SG2-K<n> --arm <A|B> --sample 1 --out ~/e2e-runs/sg2-20261031`, then
`experiment.py score SG2-K<n> --out ...`. Another session's Terra run was live on the same account while these start.

These are samples 1 of the pooled run, so `queue` skips them and nothing is repeated. Reading them early adds no bias to
the A-against-B test: the choices below depend on completion, cost and arm A's results alone, and a stop that depends only
on arm A can remove a rejection, never add one.

## What the smoke decides (fixed before any slice)

- **A slice fails to complete or to score** (a host refusal, a harness error, a missing final tree): find the cause and fix
  it before anything else runs; that sample does not count.
- **Arm A catches 0 to 3 of the 4 cases:** the cases leave room. Continue with the rest of the pool
  (`queue SG2-K1 SG2-K2 SG2-K3 SG2-K4 --arms A,B --jobs 4 --no-early-stop` skips what finished).
- **Arm A catches all 4:** a ceiling warning, not a verdict (4 of 4 has probability 0.32 at a true 75% and 0.66 at 90%).
  Run arm A sample 2 on all four cases before any more B. If A then holds 8 of 8, stop and report: the pool would have
  about 3% power at a true 90%, so the cases need harder planted defects (a change of the cases, which is the owner's). Any
  other result: continue as above.
- **Minutes:** reported per slice and per arm. One B slice does not decide the 1.5x bound; the pooled run does. If a slice
  takes more than 100 minutes, say so and decide then (background tasks are killed near 120).
- **Nothing is concluded about B against A from one B sample on one case.**
