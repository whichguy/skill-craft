(Why it might matter: A caller passing a FEN typed by a person, read from a file or left over from an earlier bug needs a predictable failure it can catch or display, rather than a crash deep inside, a silently wrong move list or a hang; the maintainer needs to know which error type to expect.)
- **U-2**: Whether a FEN without the halfmove clock and fullmove number (the four-field form common in EPD test suites, boards and many tools) is accepted, and if so which clocks appear in the FEN applyMove returns. (Why it might matter: Standard test positions and many tools emit four fields; a user pasting one expects it to work or to get a clear message, and needs to know what the counters become.)
- **U-3**: How applyMove treats move values that are not exactly one of the lowercase UCI strings legalMoves returns: uppercase ('E2E4', 'e7e8Q'), surrounding spaces, SAN ('e4'), a hyphen or capture mark ('e2-e4', 'e2xe4'), a promotion with no piece letter ('e7e8'), a promotion letter on a non-promoting move ('e2e4q'), off-board squares ('e2e9'), a non-string value, and king-takes-rook castling ('e1h1'). (Why it might matter: A caller relaying user input or output from PGN or another library needs to know which spellings throw IllegalMoveError, which throw something else and which move a piece; auto-queening a bare 'e7e8' or accepting 'e2e4q' would change the game without the caller knowing.)
- **U-4**: What the exported IllegalMoveError looks like to a caller: whether it extends Error, its name, its message (whether it names the rejected move) and any properties it carries. (Why it might matter: Callers write catch blocks with instanceof IllegalMoveError or instanceof Error and log or show the message; a class that does not extend Error loses the stack trace and breaks generic error handling, and a maintainer writing tests needs to know which checks the class supports.)
