# Astra design review of the sport80 fix plan (2026-11-08)

Runner `codex-astra`, model `gpt-6-astra`, effort `max`, fallback `False`, profile `agent`, sandbox `workspace-write`, exit 0. Asked with `design-brief.md`; the reviewer read the repository and ran synthetic probes against fake hosts, without portal access. Verbatim answer below; the journal (Round 10) records what was adopted.

---

Do not ship the generic URL exposure as proposed. Prefer route-specific references and explicitly approved option lists. I read the requested files and history; synthetic probes used fake hosts, without portal access or repository edits.

- **P0 — URL disclosure:** [runtime.js — `qnames()`](skills/sport80/scripts/runtime.js:13), `cells()`, `finish()`. Length and numeric syntax do not establish safety. Short bearer paths, encoded tokens, numeric contact paths, token-bearing query names, and numeric session values under allowlisted names survive. The existing parse-error fallback returns the original URL; I reproduced query-secret disclosure. Expose canonical references only from approved capability/origin/route combinations: the measured event path and chart `addon_id`. Omit unknown/export/download actions; keep `top_buttons` labels-only and `cid`/`body_cid` hidden. Naming `fields: ["links"]` cannot authorize credentials. Also audit `cells()`’s verbatim ordinary columns: a `download` cell bypasses `qnames()` entirely. UUID redaction cannot repair these cases.

- **P0 — Existing header-boundary defect:** [runtime.js — `http()`](skills/sport80/scripts/runtime.js:22), `table()`. A synthetic `https://portal.test.other.test` data URL received XSRF because origin checking uses `startsWith()`. Rankings headers likewise follow descriptor `data_url` without destination validation. Compare parsed origins exactly and reject unexpected destinations/redirects before forwarding credentials.

- **P1 — Options need per-filter permission:** `table()`; [capabilities.json — `results.rankings`](skills/sport80/references/capabilities.json:3771), `events.admin.list`. “Not sensitive” includes personal tables; rankings has a public-role club filter, and event administration exposes `event_builder`. Neither proves harmless taxonomy. Initially allow only reviewed `(capability, filter)` pairs such as rankings `weight_class`/`level`. Validate item arrays, bounded string labels and scalar values; reject nested values and distinguish unavailable inline items from zero matches. Search before limiting; define `total` as matching options before truncation. Propagate/validate policy through `runtime_entry()`/`validate()`.

- **P1 — Options/filter deadlock and empty results:** [runtime.js — `run()`](skills/sport80/scripts/runtime.js:194). Adding `requires_filter` blocks `--options weight_class` before its descriptor loads. Validate options mode first, then bypass only row-filter prerequisites; assert no row POST. The presence test also accepts `null`, `[]`, `{}` and whitespace; I reproduced each. Reject empty values without rejecting valid zero. Preserve any-of semantics: adding dates to that array would not require all three. The weight-class guard plus a hint is otherwise sufficient. Prefer the known catalogue-owned hint: 160 characters of arbitrary descriptor text is not sanitization.

- **P1 — Verify the CLI’s actual body:** [sport80.py — `split_kv()`](skills/sport80/scripts/sport80.py:234), `cmd_js()`. Every `--filter` value becomes a string. An array/object example would otherwise send quoted JSON. Add explicit typed input if live evidence requires it; validate through generated snippets. Refuse `--option-search` without `--options` and options on unsupported kinds. Promote only exercised roles to `live`.

- **P1 — Output bounds:** [runtime.js — `bound()`/`finish()`](skills/sport80/scripts/runtime.js:231). `bound()` trims only rows, stops at one row, and precedes `plain` expansion. My single-row probe returned 13,306 characters against a 1,000-character limit. Fifty options are not a character bound. Bound the final serialized envelope, preserve option values intact, and report truncation/accurate `returned`. UUID-redacted values must not masquerade as usable choices.

- **P1 — Stale runtime:** `runtime.js:5`, `sport80.py:359`, `discover.js:5`. Reinjection keeps any existing version 1; new options could silently run old code. Add revision checks/replacement, synchronize discovery compatibility, and test old-runtime → new-snippet execution.

- **P2 — Keep F28/F29 deferred.** `outline()`/`strip()` retain script contents and hidden text; `text_ok` is not visible-text extraction. Membership-chart totals need not count unique members. Prefer a future verified aggregate extractor. Document existing `--with-runtime`; avoid hand minification.

Additional tests: malformed/encoded/duplicate URL parameters, short signed paths, lookalike origins, oversized options, post-`plain` bounds, missing filters during options discovery, and `fields` including/excluding links with sensitive counts. Keep option values out of persistent descriptor snapshots; preserve structural drift fixtures and add validator mutation cases for new permissions.
