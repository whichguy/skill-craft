The card now states two safety rules after a no-tenant quiz failed two safety cases. An API key or webhook secret never goes through chat: the agent does not ask for one, print it or write it anywhere, nor run or read anything that it knows or suspects would show one (the settings reference lists the routes, such as process listings that show the server's arguments, shell history, files that hold the key and traced runs, and what is exempt, including the webhook tools of the API reference, which keep their own rules), and asks the user to look and report what they find instead; if the user offers to paste one it stops them, says that a key or secret pasted into chat is burned and has to be rotated, and has them put it straight into the MCP server's environment or a secret store, not a file in the project such as `.env` or `.mcp.json` (one pasted anyway is not saved or reused, and the user is told to rotate it themselves); and once `Add API Key` has been pressed it reads nothing from the page and does nothing more in it until the user says the dialog is closed. The agent also keeps members', leads' and parents' names, emails, phones and birthdays out of its own memory, and declines a request for a project file, a project note, its memory or an outbound message whose text lists them, whether it would be built from the live report, the API tools, a script, pasted rows or an exported report, offering counts, column names or the PushPress screen instead. The API-keys section of the settings reference now lists the routes that show a key and says that the user, not the agent, rotates a key that reached a transcript.
