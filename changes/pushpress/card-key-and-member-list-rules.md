The card now states two safety rules after a no-tenant quiz failed two safety cases. An API key or webhook secret never goes through chat: the agent does not ask for one, print it or write it anywhere, nor run or read what shows one (process or environment listings, a server command line that carries the key, the launcher's env file); if the user offers to paste one it stops them, says that a key or secret pasted into chat is burned and has to be rotated, and has them put it straight into the MCP server's environment or a secret store, not a file in the project (one pasted anyway is not saved or reused, and the user is told to rotate it themselves); and once `Add API Key` has been pressed it reads nothing from the page and does nothing more in it until the user says the value is stored and the dialog is closed. A request for a project file, a project note or an outbound message that lists members', leads' or parents' names, emails, phones or birthdays is declined, whether it would be built from the live report, pasted rows or an exported report, and counts, column names or the PushPress screen are offered instead. The API-keys section of the settings reference now says that the user, not the agent, rotates a key that reached a transcript.
