ShipLoop starts each Improve review at the gate its stage kind names. The reviews after the five planning stages the stop-rule study measured (spec, test-strategy, plan, step-plan, test-spec) and after two it did not measure (release-plan, and system-test-author, which writes test code) keep the one-pass rule: a trivial, satisfied pass that leaves the content unchanged ends the review. The review after each accepted implement step and the one after the last carry-forward, which review code, run at `required_trivial_reviews: 3`: a first pass that leaves the content as it started still ends the review, and once a pass has changed the content it takes two such passes in a row. The runtime measures this; the label is never enough and there is no cap or timer. The review's repeat condition and its handoff say which rule applies (its exit condition names no pass count, so a clean pass is never reported unsatisfied for want of a second), and the import accepts a completed review from either gate. The scope is a proposal awaiting the owner's SPEC S-10 text, which also asks whether the review after system-test-author should run at 3. An in-place run outside Git can now start its Improve review (the runtime measures a directory that is not a Git worktree).
