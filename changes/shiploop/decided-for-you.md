The spec stage lists the choices it made that the request does not settle in a new result key, `defaults`: for each, the
requirement whose clause states it, the question the request leaves open, the answer chosen, one workable alternative
with what it would change for a person who uses or runs the product, and why. `[]` says none qualifies. ShipLoop refuses
only mechanical faults: a missing list, an incomplete entry, a template text left in, a requirement the living spec
does not hold. It shows the list to the requester three times and asks nothing: the packet of the next stage prints the
rows and tells the host to name them in its progress line; the done packet lists them; and the report has a new
section, "Decided for you", directly after the request. No stage waits and nothing is blocked for what an entry says.
Changing a default is a new run on the delivered project: no route changes an accepted specification inside a run. A
run saved without the list still loads, and its report says "not recorded".
