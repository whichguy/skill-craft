The spec stage lists the choices it made that the request does not settle in a new result key, `defaults`: for each
acceptance line that states what the request does not and that a person who uses or runs the product would notice, the
requirement that holds it, the question the request leaves open, what that person sees or must do, one workable
alternative, and why. `[]` says no line qualifies. ShipLoop refuses only mechanical faults: a missing list, an
incomplete entry, a template text left in, a requirement the living spec does not hold. It shows the list to the
requester three times and asks nothing: the packet of the next stage prints the rows and tells the host to name them in
its progress line; the done packet lists them and tells the host to say them in its last message; and the report has a
new section, "Decided for you", directly after the request. A row whose requirement a later stage rewrote is marked
"changed after the spec stage". No stage waits and nothing is blocked for what an entry says. Changing a default is a
new run on the delivered project. A run saved without the list still loads, and its report says "not recorded".
