The knowledge home's fact files have named sections, the inner stages that find commands, facts and decisions keep them up to date, and ShipLoop counts the sections a close finds missing.

- **Sections as constants** (`knowledge_home.SECTIONS`): `spec.md` has Requirements, Non-functional requirements and Retired; `environment.md` has Targets and runtimes, Commands, Access and accounts and Platform facts; `architecture.md` has Stack, Structure, Conventions, Interfaces and boundaries, Decisions and Superseded; `test-strategy.md` has Harnesses and suites, Commands, ID convention and Real-boundary checks. A packet quotes them; none is hard-coded in a packet.
- **Writer entries on the 8-stage graph** (`knowledge_home.STAGE_FILES`): research, validate-existing, implement and test keep `environment.md` up to date; implement also keeps `architecture.md` (a deviation recorded as the next `AD-<n>`); carry-forward keeps `architecture.md` and `environment.md`. verify reads the architecture and writes nothing. A test pins every key to a stage of the graph.
- **A counted notice, not a refusal** (`knowledge_home.section_notices`): at the closes (prepare, test-spec, release-plan, release-verify), for each of the four files that exists and has text, one line per section that is missing or empty. Each line starts `ShipLoop knowledge notice: `, names the file by absolute path first, the section, and what to add; it never blocks a close and never raises. A section counts when a markdown heading (`#` to `####`, any case, trailing words allowed) starts with its name and has at least one non-blank line before the next heading of the same or higher level. Whether to turn the notice into a refusal waits for a live run that shows packets which quote the headings get them written.
