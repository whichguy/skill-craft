An Improve review now ends on one pass instead of two clean ones. The bundled Until Loop runtime's `required_trivial_reviews: 2` gate completes the loop when the report calls a pass trivial and satisfied, its checks passed, and the runtime measures the content tree (the worktree's Git tree, plus the bytes of any `candidate_paths` file outside it) equal to the tree the previous pass left; for the first pass, the tree at start. A pass that changed the tree never ends the loop, however it is labelled, so a material pass is always followed by another. There is no pass count and no timer. Before, a polish edit classed non-trivial reset the two-pass streak and forced two more passes, and 10 of 21 passes in the last live run changed nothing.
- Active gate-2 packets report `progress.last_pass_changed_tree` (true, false, or null when the tree could not be measured) in place of `trivial_streak`; the old `unchanged_first_pass` key is gone. Gates 0 and 1 and their packet shape are unchanged, so contracts written for the published until-loop plugin stay valid.
- `start` refuses a gate-2 contract whose tree cannot be measured (Git cannot snapshot the workspace, an unreadable candidate file). Values of `required_trivial_reviews` above 3 are refused (3 is the code-review gate, see the note on the two-pass gate). A saved run from the older runtime is refused with a message naming the way forward.
- The tree is measured through a copy of the Git index marked racily clean, so a same-size edit made within the cached mtime's second is seen. Before, such an edit could read as unchanged on one measurement and changed on the next.
- The runtime script and its two documents are now recorded adaptations in `PROVENANCE.json` (upstream and bundled hashes, and the reason); upstream until-loop does not have the rule yet.
